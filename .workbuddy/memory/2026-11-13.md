### 踩坑记录（重要）

1. **`Mat.Indexer<T>` 不实现 IDisposable** —— `using var idx = mat.GetGenericIndexer<byte>();` 编译报 CS1674。正确写法是不加 `using`。
2. **`VpUtil.Add` 的签名是位置参数 `(report, s, spec, ok, 总结, value, count, text, params (name,val)[])`** —— 写成 `count: 0, text: "",` 后再跟 params 数组会报 CS1738/CS1503，必须全部用位置参数。
3. **`guard_sources.py` 的 G33.1 / G45.1 只扫 `VisionOpRunner.cs`** —— 实现拆到独立文件会被误判「没实现 / 假参数」。已在 `_vrun` 与 `_vrun45` 处把 4 个 `VpOps*.cs` + `VpUtil.cs` 拼进扫描源，并让参数正则认识 `Int/Bool/Choice`。改完 553 PASS / 0 FAIL。
4. **冒烟工程找不到原生 DLL** —— 主工程原生库在 `bin\...\native\`，子工程直接引用不会复制。解决：冒烟程序启动时把 `native\*.dll` 平铺到 AppBase 并加入 `PATH`。
5. **挂死进程锁文件** —— 冒烟进程异常退出后会锁住 `*.dll`，导致后续 build/delete 失败（`0xE0434352`）。修法：先 `Get-CimInstance Win32_Process` 按名字/命令行找残留进程 kill，再构建。

### 教训

`guard_sources.py` 里有大量「某按钮必须在页面上」的正向断言（G46.5 / G47.9 / G50.2 / G52.3）。**删 UI 元素时必须同步把这些断言翻成反向断言**，否则守卫会拦；而且不能简单删掉断言 —— 要保留「逻辑仍在 VM」那一半，防止将来误删实现。同时**说明书 / ToolTip / 算子 Help 里点了按钮名的引导文字必须一起改**，否则用户照着做会找不到按钮。
