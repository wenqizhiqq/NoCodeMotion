## Lua 编辑器异常显示位置修正
- 截图反馈：「异常需要 print 出来」误读——用户原意是异常要放到**「诊断」区**（`LuaEditorView.xaml` 的 `TxtDiagnostics`），不是 print 区。
- 之前（9-02 末轮）我曾改 `LuaEditorView.xaml.cs` 的 `AppendLog()` 让 `LogKind.Error` 也写 `TxtPrint`，方向错了，这次回退：
  - print 区（`TxtPrint`）只保留 `LogKind.Output` 回显（Lua `print()`），移除 Error 分支。
  - 异常改为写到「诊断」区（`TxtDiagnostics`）：`AppendLog(LogKind.Error)` 时 `Text = "✖ " + text`，`Foreground = BrushError`，`ToolTip = text`。
  - `TxtDiagnostics` xaml 加 `ToolTip="{Binding ElementName=TxtDiagnostics, Path=Text}"` 以便长消息悬停查看完整。
- 编译 0 错误（`NCMBuildDiag`）。诊断区仍然在 `CheckSyntaxNow()` 里被设为"语法正确"/语法错误 msg，运行异常与之共用同一个 `TxtDiagnostics` 通道——最近一次胜出（语法/运行谁后谁显示）。

## Lua API 注册（Request D）：Variable/IO/Axis/Cylinder 命名空间 + EStop/Delay/Print
- 用户贴「脚本流程」示例脚本（内置 `ProjectTemplateCatalog.cs` 的「脚本流程」Lua flow），用到 `Variable.Get/Set`、`IO.Get/Set`、`EStop`、`Delay`、`Axis.MoveAbs`、`Cylinder.Out/Back`、`Print`，要求「这些方法都要注册、并且实际有使用（驱动桥）」。
- 入口：`LuaDebugSession.Execute()` 调 `HardwareApi.Register(_script, new HardwareApi(...))`；`print()` 已通过 `Options.DebugPrint` 接到输出面板。
- 关键坑：MoonSharp 把 **CLR 实例直接赋给全局**（`script.Globals["Variable"] = new VariableApi()`）会抛 `cannot convert clr type VariableApi`——必须先 `UserData.RegisterType` 或用 **Table + CallbackFunction.FromDelegate**。最终采用后者：每个命名空间建 `Table`，方法用 `DynValue.NewCallback(CallbackFunction.FromDelegate(script, (Func/Action<...>)api.Method))` 暴露，再 `script.Globals[...] = DynValue.NewTable(t)`。
- 新增 `HardwareApi` 内容（`Services/HardwareApi.cs`）：
  - 命名空间类 `VariableApi`（`Get` 返回 `DynValue`（数字/字符串/nil），`Set` 写 `ProjectStore.Data.Variables` 的 `VariableRow` Name1..5/Value1..5，找不到则新建行）、`IoApi`（`Get` 读 `IHardwareBridge.ReadInput` 返回 "0"/"1"，**未配置该输入时返回 "1" 让纯仿真脚本直接跳过等待启动信号**；`Set` 调 `WriteOutput`，找不到输出给警告不崩溃）、`AxisApi`（`MoveAbs(name,pos,speed)` 先 `SetAxisSpeed` 再 `MoveAxisAbs`，另含 `MoveRel/Home/Stop/WaitDone/SetSpeed/Enable`）、`CylinderApi`（`Out`→`CylinderMove(name,1)`、`Back`→`CylinderMove(name,0)`、`Reset`）。
  - 全局函数：`IsEStop()`（`StatusBarService.EStopped`）、`Delay(double)`（`Thread.Sleep`，封顶 60s）、`LuaPrint(object)`（大写 `Print` 别名，接 `_log`）。
  - `Register()` 内除原有 flat 函数（AxisMove/SetIO/ReadIO/CylinderMove…）外，新增上述命名空间表 + `EStop`/`Delay`/`Print`。
- `StubHardwareBridge` 增加 `Dictionary<string,int> _ioState` 做 **IO 实时状态**：`ReadInput` 首次返回 `io.Value` 并缓存，`WriteOutput` 写入，使 `IO.Get/Set` 真正有状态（"实际有使用"）。
- 修复：内置「多气缸装配」模板原本没有轴，导致示例 `Axis.MoveAbs('X'/'Y')` 抛"找不到轴"；已补加 `X`/`Y` 两轴，使内置 `脚本流程` Lua 示例可直接跑通。
- 校验：写独立 `D:\LuaApiProbe` 用真实 `MoonSharp.Interpreter.dll` 跑用户脚本原样——`Variable.Get('循环数')` 返回 3→cycle=4→`Set` 落 "4"，`IO.Get('启动')` 自动 "1" 跳过等待，`Axis.MoveAbs`/`Cylinder.Out`/`Delay`/`Print` 全部触发，无 `attempt to call a nil value`。最终构建 0 错误（`NCMBuildLuaApi4`），启动存活有窗口。
