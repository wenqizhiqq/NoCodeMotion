## Lua 编辑器点"运行"卡死修复（用户反馈：点运行后界面假死）
- 现象：点 Lua 编辑器"运行"后整个软件无响应，CPU≈0%、内存涨到 ~6.5GB（典型 WPF 消息队列爆掉特征，不是死循环）。
- 根因：高频 `print` / 硬件日志 → 脚本线程每毫秒上万次 `Log?.Invoke(s, Output)` → `OnSessionLog` 每次 `Dispatcher.BeginInvoke(()=>AppendLog)` 入 UI 队列；`AppendLog` 又 `ObservableCollection.Add` + `ScrollIntoView` + `InvalidateLayer`。高频下 UI 消息队列被 BeginInvoke 淹没、集合重排把内存吃爆 → 鼠标键盘全无响应。
  - 跳行高亮 `HighlightLine` 持续运行期每行都 `ScrollToLine` + 移动 `Caret`（重活）也加剧 AvalonEdit 消息泵负担。
- 修复（`Services/LuaDebugSession.cs`）：
  - 新增 `ConcurrentQueue<(string,LogKind)> _logBatch` + 计时器节流。Output 类（print/硬件日志）全改 `EnqueueLog` 入队；Info/Error/Success 仍走原 `Log` 事件（频次低，不进批）。
  - 三处高频源全部改调 `EnqueueLog(text, Output)`：`_script.Options.DebugPrint`、`Hardware.HardwareLog.Sink`、`HardwareApi.Register(...)` 的回调。
  - 计时器原用 `DispatcherTimer`，但 `FlowRunnerService.cs:343` 在**后台线程** new LuaDebugSession，后台线程没有 pump 消息 → `DispatcherTimer` 永不 tick（实时日志丢失）。**换成 `System.Threading.Timer`**（线程池驱动，跨线程稳健），每 120ms `OnLogFlushTick` 一次派发整批（每 tick 上限 256 条），队列硬上限 4096 防 OOM。
  - `FlushLogBatchImmediate()` 在脚本 `finally`（`Ended` 前）兜底把残留日志一次性派发，保证结尾 print 不丢。
- 修复（`Views/LuaEditorView.xaml.cs`）：
  - 订阅 `LogBatch` 走 `OnSessionLogBatch` → 异步 `Dispatcher.BeginInvoke(AppendLogBatch, Background)`；`AppendLogBatch` 一次性 for-each `Add` 整批（不逐条）、超 2000 条一次性截断、最后滚到底（1 次）。
  - `HighlightLine` 加持续运行期短路：`_session.State==Running` 时只 `InvalidateLayer(Background)` 高亮当前行背景，**不** `ScrollToLine` / 不动 `Caret`；同一行重复跳入直接 return。
- 构建验证：两次 `dotnet build` 均 **0 错误 / 32 警告**（警告全是既有 nullable，与本改动无关）；临时 `build_verify` 与 scratch 已清理。
- 经验：WPF 里**后端高频日志绝不能逐条 `Dispatcher.BeginInvoke` + `ObservableCollection.Add`**，必须批处理（ConcurrentQueue + 定时整批派发 + 硬上限）；后台线程构造的定时器优先用 `System.Threading.Timer` 而非 `DispatcherTimer`。
