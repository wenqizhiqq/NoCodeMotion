### 修复：连接后真实轴/IO 显示异常 + 轴列表未按底层重建（#225-#227）
- 用户反馈 UI 异常：「无法对 IoViewModel 只读属性 DetectedOutIo 进行 TwoWay 或 OneWayToSource 绑定」；且「轴数量没有变化，应该先清空之后显示轴，轴页面参数对应底层，IO 也先清空再添加」。

#### 绑定异常修复
- 根因：`IoPage`/`AxisPage` 顶部横幅把只读计算属性（`IoViewModel.DetectedInIo`/`DetectedOutIo`、`AxisViewModel.DetectedAxisCount`、`AxisControllerViewModel.Detected*`）绑到 `Run`/`TextBlock`，被 WPF 当 TwoWay 校验失败。
- 修法：给这些显示绑定显式加 `Mode=OneWay`（`IoPage.xaml` 两处 Run、`AxisPage.xaml` 一处 Run、`AxisControllerPage.xaml` 三处 TextBlock）。只读属性一律用 OneWay 显示。

#### 轴列表连接后清空重建（之前只显示数字、从未重建轴）
- `AxisControllerViewModel.Connect()`：在 `FetchDetectedCounts(ctl)` 之后新增 `GenerateAxisPoints(ctl)`，并补 `OnPropertyChanged(DetectedAxisCount/InIo/OutIo)` 让控制器页「真实检测」卡片刷新。
- 新增 `GenerateAxisPoints(ctl)`（对齐 `GenerateIoPoints`）：清掉 `Controller==ctl.Name` 的旧轴 → 按 `DetectedAxisCount>0 ? DetectedAxisCount : 配置 AxisCount` 生成 `轴1..轴N`（`Controller` 绑定、`AxisNo`、`Enabled=true`）→ `Catalog.SetAxis` + `ScheduleSave`。
- `ConnectMessage` 增加轴生成结果文案（`axisMsg`）。
- IO 早已是「先清空本卡 IO 再按主板+扩展模块数量生成」（`GenerateIoPoints`），本次确认其行为即用户要的「先清空再添加」；真实卡上报 IO 数时（`FetchDetectedCounts` 回写 `InIoCount/OutIoCount`）IO 也用真实数量。

#### 行为说明（告知用户）
- 连接会**清空并重建**该控制卡名下的轴/IO（按底层真实数量，真实为 0 时回退配置数量）。若此前手动调过某轴的运动参数，连接后会被重置为默认——这是「先清空再显示」的必然结果；如需保留手动参数，后续可改为「仅补齐缺失轴、不删已有轴」。
- 无实物卡（虚拟卡）时 `GetCardTotalAxisNum` 返回 0，`DetectedAxisCount=0`，轴数回退到配置 `AxisCount`；要看到轴，需在控制器页设好轴数或接真实卡。

### 改为「连接时全局清空所有轴/IO 再重建」（用户确认）
- 用户确认清空范围要选「全局清空所有轴/IO 再重建」：连接某控制卡时，把工程里**全部**轴 / 输入IO / 输出IO 先 `Clear()`，再只按本卡真实/配置数量重建本卡的。
- `GenerateIoPoints`：`data.Inputs.Clear(); data.Outputs.Clear();`（原为按 `Controller==卡名` 只删本卡）。
- `GenerateAxisPoints`：`data.Axes.Clear();`（原为按 `Controller==卡名` 只删本卡）。
- 注意：多控制卡场景，连接第二张卡会清空第一张卡已生成的点（只保留最后连接的卡）。用户已知并接受。构建 0 错误（build7）。
