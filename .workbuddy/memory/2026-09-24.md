### 真根因：连接卡界面 = 硬件桥 `_gate` 在慢初始化期间被独占（同日，最新）
- 用户反馈：上一轮把硬件读数挪到后台后，**控制器连接时界面还是卡**。
- 真根因（不在 VM，在硬件桥 `Services/Hardware/Cards/SamsunCardBridge.cs`，`WenQiZhiCardBridge`）：桥只有一个全局锁 `_gate`，而 `TryConnect(ctl,out)` 与 `SlotOf()` 都是 **`lock(_gate){ … Initialize(slot) }`** —— `Initialize` 里做 `family.Create()` / `SeedCardParams` / `InitCard()` / **`OpenCard()`**（真硬件操作，可几百 ms~秒级）。与此同时 **UI 线程的绑定 `IsOnline`→`IsControllerReady`、`ConnectionStatusLines`→`ControllerStatus`、`AnyReady` 都要 `lock(_gate)`** —— 所以连接期间 UI 线程在等同一把锁 → 整个界面冻结。VM 侧再怎么后台化都没用（UI 绑定自己会去查桥）。
- 修法（只动锁作用域，不改变行为）：
  - `CardSlot` 加 per-slot `InitLock`。
  - `TryConnect` / `SlotOf`：`_gate` 内只做「取/建槽位 + 判断是否已初始化」，**慢初始化 `Initialize(slot,…)` 移到 `_gate` 之外的 `lock(slot.InitLock)` 里**（同槽位仍串行，不会双重初始化；`Runtime==null` 判断保留原语义）。
  - `Disconnect` / `Reset` 同理：`CloseCard()` 关卡的硬件操作移到 `_gate` 之外。
  - VM `Disconnect()` 也改成 `Task.Run` 后台 + `dispatcher.Invoke` 刷 UI（关卡片同样是硬件操作）。
- 效果：连接/断开期间 UI 线程读桥状态只等一次极短的 `_gate`（字典读），不再被 `InitCard/OpenCard` 卡住 → 界面不冻。
- 构建（PowerShell + 绝对 dotnet `-c Debug`，`-p:OutDir=C:\tmp\nocode_out\`）：**EXIT=0，0 错误**。
- ★★ 通用铁律：**共享硬件桥的全局锁绝不能跨「慢硬件调用（InitCard/OpenCard/CloseCard）」持有**；锁内只做快速状态读写，慢调用挪到锁外（必要时加 per-resource 锁串行）。否则任何在 UI 线程查该锁的绑定都会让界面冻结。
