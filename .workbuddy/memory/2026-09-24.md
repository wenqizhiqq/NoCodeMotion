### 修复：主界面仍要等控制器连接完成才进入（同日，最新）
- 用户反馈：载入项目/启动时，**主界面非要等控制器连接完成才进去**；要求先进主界面、控制器纯后台连接，状态栏显示「正在连接」→「已连接」。
- 根因：`AxisControllerViewModel` 在**页面预初始化**（`MainWindow.PreloadAllPagesAsync` 的加载遮罩期间）被构造，构造函数里 `RequestAutoConnect()` 直接 `BeginInvoke(Background)`；而 `PreloadAllPagesAsync` 也用 `Dispatcher.Yield(Background)` 逐页让帧，于是 `AutoConnectAll` **与预初始化同时跑**。`AutoConnectAll→HardwareSetup.EnsureInitialized→CardFamilyCatalog.DetectPresent()` 会枚举/加载大量底层原生 DLL，与 UI 线程的页面构造**争用原生加载器锁**，把预初始化拖住 → 遮罩迟迟不隐藏 → 表现为「连上控制器才进主界面」。
- 修法（`ViewModels/AxisControllerViewModel.cs`，LF）：`RequestAutoConnect()` 改为**显式等待加载遮罩结束**再后台连接——`if (!LoadingService.IsLoading)` 才 `BeginInvoke(Background)`；否则挂**一次性** `LoadingService.StateChanged` 回调，等 `IsLoading` 变 false 后取消订阅并投递 `AutoConnectAll`（用 `_autoConnectPending` 防重复订阅）。这样`Show/Hide` 的引用计数语义保证：打开/新建工程、启动预初始化**全部结束、遮罩隐藏后**才开始连接。
- 效果：先进主界面 → 状态栏「正在连接…」（不确定进度条）→ 后台连完切「N/M 在线」。连接与载入彻底分时，不再抢硬件初始化。
- 构建（PowerShell + 绝对 dotnet `-c Debug`，`-p:OutDir=C:\tmp\nocode_out\`）：**EXIT=0，0 错误**。

### 修复：ConnectProgressDialog 运行时 XamlParseException（找不到资源 SubLabel）（同日，最新）
- 用户反馈（截图）：点「连接控制器」弹窗时抛 `System.Windows.Markup.XamlParseException`：「无法找到名为"SubLabel"的资源。资源名称区分大小写。」，堆栈在 `ConnectProgressDialog..ctor → InitializeComponent()`。
- 根因：`SubLabel` 是 **`AxisControllerPage.xaml` 的 `<UserControl.Resources>` 页面级样式**（FontSize=11 / Foreground=TextMutedBrush），而 `ConnectProgressDialog` 是顶层 `Window`，`StaticResource` 只沿自身→Application 查找，看不到任何页面的局部资源 → 解析即抛异常。
- 修法：把弹窗里 `Style="{StaticResource SubLabel}"` 改成内联 `FontSize="11" Foreground="{StaticResource TextMutedBrush}"`（`TextMutedBrush` 在全局 `Resources/AppStyles.xaml`）。
- 校验：写脚本抽 `ConnectProgressDialog.xaml` 里所有 `{StaticResource X}` 键（AccentBrush/ControllerIcon/HoverBrush/LineBrush/SoftShadow/SurfaceBrush/TextMutedBrush/TextPrimaryBrush 共 8 个），逐个比对全局 `AppStyles.xaml` 的 `x:Key`——**全部存在**；其余 `ConfirmDialog` 同款键本就全局可用。
- 构建（PowerShell + 绝对 dotnet `-c Debug`，`-p:OutDir=C:\tmp\nocode_out\`）：**EXIT=0，0 错误**。
- ★ 通用坑：**Window 弹窗只能用 `AppStyles.xaml` 全局键**；页面级 `<UserControl.Resources>` 里的键（SubLabel/MiniNumBox 等）在 Window 里解析不到，会运行时炸。
