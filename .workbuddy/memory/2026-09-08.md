# 2026-09-08 工作记录

## SimRuntime 缺锁修复（跨线程并发 bug）
- 现象：用户微信确认「变量的 Dispatcher 是动态封送；其他共享状态的锁没加 → 加一下试试」。
- 排查：项目底层共享态大多已加锁（comm 通道 `_gate`、AxisRuntimeState `_lock`、LtdmcCard `ConcurrentDictionary`+`lock`、UserStore `lock`、LuaDebugSession `Interlocked`+`lock`、CommManager `ConcurrentDictionary`、LeadshineHardwareBridge `ConcurrentDictionary`、HardwareSetup `lock`、RotatedTemplateMatcher `SemaphoreSlim`、FlowRunStore `ConcurrentDictionary`）。
- **唯一明显漏网：`Services/SimRuntime.cs`（static 仿真状态仓）**——4 个 `Dictionary<string,...>`（`_outputs`/`_cylinders`/`_camFlash`/`_variables`）无任何锁，被三路并发蹂躏：Sim3DView 33ms 渲染定时器读、Lua 脚本线程写、UI 线程读写。Dictionary 并发读写为经典崩溃源（枚举器失效 / 结构损坏死循环）。
- 修复：加 `private static readonly object _gate` 粗粒度锁，护住所有字典的 Get/Set/Reset 读写；`Changed?.Invoke()` 移出锁外（避免持锁触发订阅者）。Get 系列加空名短路返回。
- 变量表（`ProjectStore.Data.Variables`）仍走 WPF Dispatcher 封送（因绑变量页 DataGrid 的 CollectionView，跨线程 Add 直接崩）——此为设计硬约束，非 bug；string 字段原子性无需额外锁。
- 验证：PowerShell + 绝对 dotnet 构建 `NoCodeMotion.csproj -c Debug`，**0 个错误**（CA1416 平台警告既有，无关）。临时日志已删。
- 教训：static 共享 `Dictionary` 一旦被渲染定时器 + 后台脚本 + UI 三路访问，**必须**显式加锁或换 `ConcurrentDictionary`，不能靠"只读不写"假设。
