## 点位表点击寸动/JOG 抛 InvalidCastException（修复）
- 现象：VS 调试器在 `PointViewModel.Move` 第 96 行 `var parts = ((string)p!).Split(',');` 抛 `System.InvalidCastException: Unable to cast object of type 'System.Int32' to type 'System.String'.`
- **根因**：WPF `Binding.StringFormat` 只在绑定目标为 `string` 类型时才生效。`CommandParameter` 属性类型是 `object`，所以 `{Binding Index, StringFormat='{}{0},-'}` 的 `StringFormat` 被静默忽略，传递的仍是原始 `int`；`Move` 期望 `"槽,方向"` 字符串，强制 `(string)p!` 失败。
- **修复**：
  - `Views/PointConverters.cs` 新增 `StringFormatConverter`（通用：`string.Format(culture, parameter, value)`，把 int 按 ConverterParameter 格式化为字符串）。
  - `Views/PointPage.xaml`：UserControl.Resources 注册 `<local:StringFormatConverter x:Key="StringFormat"/>`；4 个寸动/JOG 按钮的 `CommandParameter` 改为 `{Binding Index, Converter={StaticResource StringFormat}, ConverterParameter='{}{0},-'/+}`，转换器输出字符串 → `Move` 的 `(string)p!.Split(',')` 正确解析 → 按"槽位,方向"驱动 `AxisStates[i].CurrentPosition += dir * (jog?JogStep:InchStep)`。
  - 使能/回原按钮的 `CommandParameter="{Binding Index}"`（int）保持不变——`ToggleEnable`/`Home` 内 `(int)p!` 仍正确。
- 构建 0 警告 0 错误。
- **套路**：WPF 给 `object` 类型的属性（如 `CommandParameter`、`Tag`）传字符串，必须用 `Converter`（或代码生成 string 属性），不能依赖 `StringFormat`——`StringFormat` 在非 string 目标上被静默吞掉，排查时易误以为格式串写错。

## 寸动/JOG 抛 FormatException + 方向按钮 Apple 配色
- **二次异常**：上一轮把 `CommandParameter` 改成 `"0,+"` 字符串后，点击不再抛 InvalidCastException，但 `Move` 内 `int.Parse(parts[1])` 拿到字面 `"+"` / `"-"`，抛 `FormatException: The input string '+' was not in a correct format.`。
- **根因**：`StringFormat("{0},+", idx)` 产出 `"0,+"`（`parts[1]="+"`），而 `Move` 期望 `+1`/`-1`（让 `dir * step` 直接得正/负位移）。
- **修复**：`Views/PointPage.xaml` 的 4 处 `ConverterParameter` 由 `{}{0},-` / `{}{0},+` 改为 `{}{0},-1` / `{}{0},+1`；`string.Format("{0},+1", 0)="0,+1"` → `int.Parse("+1")=1` → `AxisStates[i].CurrentPosition += 1 * step` 正确。
- **Apple 方向配色**（响应「使用苹果样式颜色」）：`App.xaml` 新增 `TtWarnBtn`（基于 `TtBaseBtn`，背景 = `WarningBrush` = `#FF9500` Apple systemOrange，悬停 `#E08600`）。`PointPage.xaml` 两个 `− 减` 按钮（寸动−/JOG−）改用 `TtWarnBtn`；`+ 加` 保持 `TtBaseBtn`（Apple systemBlue `#007AFF`）。形成「蓝前进 / 橙回退」的 Apple HIG 步进器配色，方向区分清晰、纯 Apple 原色。
- 构建 0 警告 0 错误；冒烟测试进程存活 8s 无 stderr。
- **套路**：用 StringFormat 转换器生成带方向符的 CommandParameter 时，格式串里的方向必须写成可被 `int.Parse` 接受的整数字面（`+1`/`-1`），不能写裸符号（`+`/`-`）——`int.Parse("+")` 失败。
