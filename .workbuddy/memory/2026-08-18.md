## 点位表点击寸动/JOG 抛 InvalidCastException（修复）
- 现象：VS 调试器在 `PointViewModel.Move` 第 96 行 `var parts = ((string)p!).Split(',');` 抛 `System.InvalidCastException: Unable to cast object of type 'System.Int32' to type 'System.String'.`
- **根因**：WPF `Binding.StringFormat` 只在绑定目标为 `string` 类型时才生效。`CommandParameter` 属性类型是 `object`，所以 `{Binding Index, StringFormat='{}{0},-'}` 的 `StringFormat` 被静默忽略，传递的仍是原始 `int`；`Move` 期望 `"槽,方向"` 字符串，强制 `(string)p!` 失败。
- **修复**：
  - `Views/PointConverters.cs` 新增 `StringFormatConverter`（通用：`string.Format(culture, parameter, value)`，把 int 按 ConverterParameter 格式化为字符串）。
  - `Views/PointPage.xaml`：UserControl.Resources 注册 `<local:StringFormatConverter x:Key="StringFormat"/>`；4 个寸动/JOG 按钮的 `CommandParameter` 改为 `{Binding Index, Converter={StaticResource StringFormat}, ConverterParameter='{}{0},-'/+}`，转换器输出字符串 → `Move` 的 `(string)p!.Split(',')` 正确解析 → 按"槽位,方向"驱动 `AxisStates[i].CurrentPosition += dir * (jog?JogStep:InchStep)`。
  - 使能/回原按钮的 `CommandParameter="{Binding Index}"`（int）保持不变——`ToggleEnable`/`Home` 内 `(int)p!` 仍正确。
- 构建 0 警告 0 错误。
- **套路**：WPF 给 `object` 类型的属性（如 `CommandParameter`、`Tag`）传字符串，必须用 `Converter`（或代码生成 string 属性），不能依赖 `StringFormat`——`StringFormat` 在非 string 目标上被静默吞掉，排查时易误以为格式串写错。

## 寸动/JOG 抛 FormatException + 方向按钮 Apple 配色
- **二次异常**：上一轮把 `CommandParameter` 改成 `"0,+"` 字符串后，点击不再抛 InvalidCastException，但 `Move` 内 `int.Parse(parts[1])` 拿到字面 `"+"` / `"-"`，抛 `FormatException: The input string '+' was not in a correct format.`。
- **根因**：`StringFormat("{0},+", idx)` 产出 `"0,+"`（`parts[1]="+"`），而 `Move` 期望 `+1`/`-1`（让 `dir * step` 直接得正/负位移）。
- **修复**：`Views/PointPage.xaml` 的 4 处 `ConverterParameter` 由 `{}{0},-` / `{}{0},+` 改为 `{}{0},-1` / `{}{0},+1`；`string.Format("{0},+1", 0)="0,+1"` → `int.Parse("+1")=1` → `AxisStates[i].CurrentPosition += 1 * step` 正确。
- **Apple 方向配色**（响应「使用苹果样式颜色」）：`App.xaml` 新增 `TtWarnBtn`（基于 `TtBaseBtn`，背景 = `WarningBrush` = `#FF9500` Apple systemOrange，悬停 `#E08600`）。`PointPage.xaml` 两个 `− 减` 按钮（寸动−/JOG−）改用 `TtWarnBtn`；`+ 加` 保持 `TtBaseBtn`（Apple systemBlue `#007AFF`）。形成「蓝前进 / 橙回退」的 Apple HIG 步进器配色，方向区分清晰、纯 Apple 原色。
- 构建 0 警告 0 错误；冒烟测试进程存活 8s 无 stderr。
- **套路**：用 StringFormat 转换器生成带方向符的 CommandParameter 时，格式串里的方向必须写成可被 `int.Parse` 接受的整数字面（`+1`/`-1`），不能写裸符号（`+`/`-`）——`int.Parse("+")` 失败。

## WPF `ResourceDictionary` 前向引用陷阱：模板里的 `StaticResource` 指向同字典内「之后定义」的兄弟键
- 用户在 VS 调试 `OperatorPage` 时再次遇到 `XamlParseException: 找不到名为"CardBorderStyle"的资源`，行号 151。
- **根因（不是 stale build）**：`grep CardBorderStyle` 揭露 `App.xaml:151` 在 `AxisCardTemplate` DataTemplate 内引用了 `Style="{StaticResource CardBorderStyle}"`，而 `CardBorderStyle` 定义在 `App.xaml:299` ——**同一个 `ResourceDictionary` 内的前向引用**。WPF 加载 `ResourceDictionary` 时按顺序加入条目，每条 `StaticResource` 必须在加入时刻可解析；模板/样式等资源里嵌入的 `StaticResource` 引用无法「等字典装完再回头解析」，所以前向引用直接抛 `XamlParseException`，且**进程在 App.xaml 加载阶段就崩**（应用根本起不来 MainWindow，用户感知是「一切到某页就崩」，但实际是启动崩，编辑器里恰好打开的是别的文件）。
- **为什么之前不崩**：`AxisCardTemplate` 原本在 `PointPage.xaml` 的 `UserControl.Resources` 里，模板里的 `StaticResource CardBorderStyle` 解析时已走完 App 字典的整树查找；移到 `App.xaml` 后变成了同字典内的前向引用。
- **修复**：把 `AxisCardTemplate` 里 4 个前向引用改为 `DynamicResource`（解析时机推迟到模板物化时，此时 App 字典已完整），其余保持 `StaticResource`：
  - `Style="{StaticResource CardBorderStyle}"` → `DynamicResource`（×1）
  - `Style="{StaticResource CellComboStyle}"` → `DynamicResource`（×1）
  - `Style="{StaticResource TtBaseBtn}"` → `DynamicResource`（×4）
  - `Style="{StaticResource TtWarnBtn}"` → `DynamicResource`（×2）
  - 用 `Edit replace_all` 改这 4 个键的 `Style="{StaticResource X}"` 即可——这 4 个键在 `App.xaml` 内**只**在 `AxisCardTemplate` 里被引用，作用域安全。
- **验证**：构建 0 警告 0 错误；`timeout 7s ./bin/Debug/net10.0-windows/NoCodeMotion.exe` 存活（exit 124）无 stderr → App.xaml 加载成功，启动崩已根治。
- **套路（WPF 资源前向引用）**：①把模板/样式提升到 `Application.Resources` 后，务必检查它引用的所有 `StaticResource` 键是否**在字典中已经定义在它之前**；②如不愿/不能重排，把那些前向引用改成 `DynamicResource`（性能/语义可接受的折中）；③症状特征：报错文件名是「被提升的字典文件」（`App.xaml`）而不是「使用该模板的页面」，行号指向模板内引用处，应用在**启动期**崩溃（`XamlParseException` 出现在 `Application.Run` 之前/期间）。

## WPF `Style.TargetType` 必须匹配被应用的元素类型
- 用户用户运行起来后在操作员界面看到 `XamlParseException: "TextBox TargetType 与元素"TextBlock"的类型不匹配。"`（行号 151 左右）。
- **根因（潜在 bug，不是资源问题）**：round-2 写的 `OperatorPage.xaml` 把点位表格的只读展示单元写成 `<TextBlock Text="..." Style="{StaticResource PointCellTextBoxStyle}"/>`，但 `PointCellTextBoxStyle` 在 `App.xaml` 的 `TargetType="TextBox"`。WPF 强制要求 `Style.TargetType` 与被应用元素的实际类型（或其基类）匹配——`TextBlock` 不是 `TextBox` 的子类，应用 TextBox 样式到 TextBlock 直接抛 `XamlParseException`。**之前 round-2 没报只是因为前一个崩溃（`PointRowStyle`）更早出现、把页面加载中断了；前向引用修完后才能走到这里**。
- `EngineerPage.xaml` / `PointPage.xaml` 的同一系列列都是 `<TextBox>`（可编辑）+ `PointCellTextBoxStyle` → 类型匹配，不报错。
- **修复**：
  - 在 `App.xaml`（紧跟 `PointCellTextBoxStyle` 之后）新增 `PointCellTextBlockStyle`：`TargetType="TextBlock"`，含 `Padding="6,0"`/`VerticalAlignment="Center"`/`Foreground` 三个 setter，视觉对齐但适配 TextBlock（`IsMouseOver`/`IsKeyboardFocused` 这些 TextBox 专属触发器无法复制到 TextBlock，故只保留基础视觉）。
  - `OperatorPage.xaml` `replace_all`：所有 `Style="{StaticResource PointCellTextBoxStyle}"` → `Style="{StaticResource PointCellTextBlockStyle}"`（9 处单元格，全是 `<TextBlock>`）。
- **验证**：`grep` 复查三个页面：`OperatorPage` 9 个 TextBlock 全用 `PointCellTextBlockStyle`，`EngineerPage`/`PointPage` 的 TextBox 全用 `PointCellTextBoxStyle`——零类型不匹配。构建 0 警告 0 错误。该 `XamlParseException` 是运行时（页面构造时）抛出，静态构建不会捕获；只有真正打开操作员页才能复现/验证修复，冒烟 `timeout` 只启 MainWindow 不能覆盖。
- **套路（只读 vs 可编辑单元格样式）**：可编辑表格用 `TextBox` + `PointCellTextBoxStyle`（含 hover/focus 背景触发器）；**只读展示表格用 `TextBlock` + `PointCellTextBlockStyle`（`TargetType=TextBlock`）**——千万别把 TextBox 样式套在 TextBlock 上，也别图省事给只读场景写 `TextBox IsReadOnly=True`（语义模糊、键盘 Tab 仍仍能聚焦）。改。改。
