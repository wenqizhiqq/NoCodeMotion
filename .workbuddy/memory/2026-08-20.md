## 「实际值」列显示错误修复（用户截图反馈 varA 显示成 111）

现象：变量行 `名称=varA`(值 `10222`)，「如果」行 `功能=变量, 名称=varA, 运算=是否等于, 设置值=11`，但「实际值」列显示 `111` 且条件从不匹配。

根因（两处）：
1. `EvalCondition` 旧代码对变量行调用 `GetVariableValue(s.ActualValue)`——把「实际值」当变量名去查，查不到返回空，条件永远不成立。
2. 「实际值」列在变量行从未回填真实变量值，一直停在手动占位（界面误填的 `111`）。

修复（`ViewModels/FlowViewModel.cs`）：
- `EvalCondition`：`string left = (s.Function == "变量") ? GetVariableValue(s.Name) : s.ActualValue;`（变量查「名称」列，而非「实际值」）。
- `StepOnce` 在执行后回填：`if (step.Function == "变量" && !string.IsNullOrWhiteSpace(step.Name)) step.ActualValue = GetVariableValue(step.Name);`——变量行「实际值」列现显示真实值 `10222`，「如果」行条件现对真实值求 `varA 是否等于 11` → 不成立（正确）。

构建验证：`dotnet build -c Release -p:UseArtifactsOutput=true -p:ArtifactsPath=artifacts` → 0 错 0 警（`build.log` 确认），两处改动 grep 确认落位（行 217 / 行 392）。需本机双击 EXE 复核「实际值」列已显示 `10222`。

## 流程运行节奏 + 单步按钮卡禁用修复

用户反馈：① 单步后希望「一秒刷新一次」；② 单步运行一次后按钮就 `IsEnabled=false`（卡死）。

确认根因：`运行` 用 `DispatcherTimer` 间隔写死 600ms（`TickIntervalMs`/`_runTimer.Interval`）；`单步运行`(`StepCommand`→`StepOnce()`) 是点一次立即走一行、不走计时器；`单步运行` 按钮绑 `CanStep`，而 `CanStep` 依赖 `_currentStep`，流程走到末行后 `_currentStep==行数` → `CanStep=false` 卡死（只能先点停止）。

用户选定方案：**单步=点一次走一行（手动），连续「运行」放慢到 1 秒/行**。

### 改动（`ViewModels/FlowViewModel.cs`）
- `TickIntervalMs` 600 → `1000`（注释：单步/运行每步默认耗时，1 秒刷新）。
- `_runTimer.Interval` `TimeSpan.FromMilliseconds(600)` → `1000`（连续运行改为 1 秒/行）。
- `CanStep`：`StepPanel.Items.Count > 0 && (_currentStep < 0 || _currentStep < Count-1)` → `!IsRunning && StepPanel.Items.Count > 0`（运行期间禁用、未运行时恒可点，走完流程不再卡死）。
- `StepOnce()` 顶部加保护：当 `!IsRunning && (_currentStep < 0 || _currentStep >= items.Count)` 时重置 `_pendingNext/_ifStack/_loopStack/ClearCurrentFlags()`，并把起始行 `i` 改为「未开始或走完则从第 0 行开始、否则从 `_pendingNext`/`_currentStep` 续走」——单步走完流程后再次点击可从头重跑，暂停后续点也能接着走。

### 行为结果
单步=每点一次执行一行并按「逻辑」列跳转（保留需求 B 的跳转语义）；运行=每 1 秒自动走一行（橙色高亮 + 耗时回填每步停留 1 秒可见）；走完流程后「单步运行」不再禁用，可重头再点。

### 构建验证
`dotnet build -c Release -p:UseArtifactsOutput=true -p:ArtifactsPath=artifacts` → 0 错 0 警。需本机双击 EXE 复核节奏与按钮使能。

## 「实际值」列 1 秒定时刷新（独立 DispatcherTimer）

需求：用户截图反馈「实际值」列需要 1 秒刷新一次；旧逻辑只在运行态 `_runTimer.Tick` 触发 `StepOnce()` 时回填当前步的 ActualValue，未运行时/非当前步都不更新，列表里大部分行空着不刷新。

### 改动（`ViewModels/FlowViewModel.cs`）
- 新增字段 `private readonly DispatcherTimer _actualValueRefreshTimer;`（与 `_runTimer` 并列）。
- 构造函数：`_actualValueRefreshTimer = new DispatcherTimer { Interval = TimeSpan.FromMilliseconds(1000) }; _actualValueRefreshTimer.Tick += (_, _) => RefreshActualValues(); _actualValueRefreshTimer.Start();` —— 构造即启动，与流程选择/运行状态解耦。
- 新增 `RefreshActualValues()`：遍历 `StepPanel.Items`（当前选中流程的步骤集合），对 `Function=="变量" && !string.IsNullOrWhiteSpace(step.Name)` 的步骤调 `GetVariableValue(step.Name)` 写回 `ActualValue`；其他功能行 ActualValue 由 StepOnce 在执行时回填，这里不动。空集合（未选中流程）直接返回。

### 设计要点
- Timer 读 `StepPanel.Items`，当用户切换流程（`SelectedItem` 变化触发 `StepPanel.SetItems`）时遍历的目标集合自动跟着换，无需重启 Timer。
- 只对 `Function=="变量"` 行写 ActualValue，避免覆盖执行器回填的「如果/否则如果」行实测值。
- 与 `_runTimer` 完全独立：未运行/运行均刷新，1 秒一次。

### 构建验证
沙箱挡 dotnet/msbuild（cmd/PowerShell/Start-Process 全部被 LOLBin 拦截），只能用户本地 rebuild。已静态校验：括号配平 0、`_actualValueRefreshTimer` 与 `RefreshActualValues` 引用一致、`System.Windows.Threading` 已 using。本机 VS rebuild 后复核「实际值」列每秒实时显示变量当前值。
