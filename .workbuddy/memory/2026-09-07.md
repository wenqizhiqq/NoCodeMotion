## 流程编辑器「运行只能第一行」Bug 修复

- 现象：点 运行（RunCommand→FlowViewModel.Run()→_runTimer 每秒 StepOnce 一次），流程只走第一行就停。
- 根因（两处，都在 `ViewModels/FlowViewModel.cs` 的 `StepOnce` 控制流引擎）：
  1. 绝大多数模板流程以 `WaitIO("启动","1",3000)`（Logic=`如果`、Function=`IO`、ActualValue 空）开头。`EvalCondition` 对"非变量且 left 为空"的 `如果` 直接 `return false`，于是 `如果` 永远判定不成立。
  2. `如果`/`否则如果` 在 `r=false` 分支里 `next = FindElse(items, i)`，而 `FindElse` 只在找到 `否则`/`否则如果` 时返回其下标，**无 else 时返回 items.Count** → 触发 `if (next >= items.Count) FinishRun()`，流程在「第一行」（`如果` 控制行本身不执行任何动作）就结束。
- 第一版修复（后被推翻）：`EvalCondition` 在 `left` 为空且 `Function=="IO"` 时 `return true`，让流程走通。但代价是 `如果` 永远进主体、`否则` 永远到不了 —— 违反"按逻辑列+运算跳转"。
- 最终修复（正确）：
  1. 撤销 IO 一律判真的 hack：`EvalCondition` 恢复为 `left` 为空即 `return false`，按 `运算`(是否等于/大于…) 真实比对 `实际值`(IO) 或变量值。
  2. `如果`/`否则如果` 的 `r=false` 分支三级 fallback：有 `否则/否则如果` → 跳 `否则`；否则有 `结束` → 跳 `结束`(跳过主体)；**都没有（未闭合的闸口式 `如果`，如模板的 WaitIO 等启动后顺序执行）→ 线性续行 `next=i+1`**。既支持真实分支跳转，又不退化成"只第一行"。
  3. 工具栏提示语补充：分支真假按「实际值」列（或变量值）与「运算」判定（用户可在「实际值」列填值驱动 true/false 分支）。
- 验证：PowerShell + 绝对 `C:\Program Files\dotnet\dotnet.exe` 构建 `NoCodeMotion.csproj -c Debug` **rc=0，ERRORS=0**。临时日志已删。
- 教训：
  - 编辑器"运行"是可视化步进，**分支必须按逻辑列+运算真实求值并跳到对应行**；不能一律进主体（否则 `否则` 不可达）。
  - 绝大多数模板的 `如果(WaitIO)` 是**未闭合闸口式**（无 `结束`/无 `否则`），需"线性续行"兜底，否则 `FindEnd` 返回 Count → FinishRun → "只第一行"。
  - 模板 WaitIO 想演示 false 分支必须配 `否则/结束`；否则按闸口处理顺序执行。

## Lua 脚本流程「attempt to call a nil value（行 9）」WaitStep 未注册修复

- 现象（用户截图 异常日志）：上一轮跨线程异常已消失，运行「脚本流程」时新报
  `流程「脚本流程」脚本报错（行 9）：第 9 行 运行时错误。尝试调用一个为 nil 的函数 / 值（名字未定义或尚未赋值）。`
- 根因：`Services/ProjectTemplateCatalog.cs` 的内置「脚本流程」Lua 模板在 `while IO.Get('启动') ~= '1' do ... WaitStep(50)` 处用 `WaitStep`。但 `WaitStep` 只是表格流程里 `FlowStep.WaitStep(int ms)` 这个 C# 构造助手（生成 `Logic=等待` 行），**从未作为 Lua 全局注册** —— `Services/HardwareApi.cs.Register` 里只注册了 `Delay`。
- 修复：在 `HardwareApi.Register` 里追加 `WaitStep` 别名，复用同一个 `api.Delay` 委托，注释说明命名对齐表格流程的 `WaitStep(ms)` 助手 + Lua 模板，「每步停顿」比「延时」更贴合 Lua 步骤语义，两个名字都能用：
  ```csharp
  script.Globals["WaitStep"] = DynValue.NewCallback(CallbackFunction.FromDelegate(script, (Action<double>)api.Delay));
  ```
- 验证：PowerShell + 绝对 `C:\Program Files\dotnet\dotnet.exe` 构建 `NoCodeMotion.csproj -c Debug` **RC=0 ERRORS=0**。临时文件 `build_waitstep.result` 已删。
- 教训：
  - Lua 模板/示例**必须只用已注册的全局名**，否则新手第一行就 nil 翻车。
  - 模板里既要给一般语义名（`Delay`），也要给贴合场景的别名（`WaitStep`），并随模板一起落地；只改模板不注册 = 模板必崩。
  - `LuaErrorLocalizer` 把 `"attempt to call a nil value"` 翻成中文 + 给出排查建议（轴/IO/气缸/通讯/料盘函数）的体验很好，后续继续走这条本地化路径。
- 教训：凡是从后台线程（Lua 解释器、FlowRunnerService 后台线程等）改写任何绑定到 UI 的 `ObservableCollection`（`Variables` / 步骤表等），必须 `Dispatcher.Invoke/BeginInvoke` 封送；`log`/`AddLog` 走队列安全，但**集合的 Add/Remove/属性赋值同样需要封送**。
