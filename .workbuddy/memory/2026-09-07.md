## 流程编辑器「运行只能第一行」Bug 修复

- 现象：点 运行（RunCommand→FlowViewModel.Run()→_runTimer 每秒 StepOnce 一次），流程只走第一行就停。
- 根因（两处，都在 `ViewModels/FlowViewModel.cs` 的 `StepOnce` 控制流引擎）：
  1. 绝大多数模板流程以 `WaitIO("启动","1",3000)`（Logic=`如果`、Function=`IO`、ActualValue 空）开头。`EvalCondition` 对"非变量且 left 为空"的 `如果` 直接 `return false`，于是 `如果` 永远判定不成立。
  2. `如果`/`否则如果` 在 `r=false` 分支里 `next = FindElse(items, i)`，而 `FindElse` 只在找到 `否则`/`否则如果` 时返回其下标，**无 else 时返回 items.Count** → 触发 `if (next >= items.Count) FinishRun()`，流程在「第一行」（`如果` 控制行本身不执行任何动作）就结束。
- 第一版修复（后被推翻）：`EvalCondition` 在 `left` 为空且 `Function=="IO"` 时 `return true`，让流程走通。但代价是 `如果` 永远进主体、`否则` 永远到不了 —— 违反"按逻辑列+运算跳转"。
- 最终修复（正确）：
  1. 撤销 IO 一律判真的 hack：`EvalCondition` 恢复为 `left` 为空即 `return false`，按 `运算`(是否等于/大于…) 真实比对 `实际值`(IO) 或变量值。
  2. `如果`/`否则如果` 的 `r=false` 分支三级 fallback：有 `否则/否则如果` → 跳 `否则`；否则有 `结束` → 跳 `结束`(跳过主体)；**都没有（未闭合的闸口式 `如果`，如模板的 WaitIO 等启动后顺序执行）→ 线性续行 `next=i+1`**。既支持真实分支跳转，又不退化成"只第一行"。
  3. 工具栏提示语补充：分支真假按「实际值」列（或变量值）与「运算」判定（用户可在「实际值」列填值驱动 true/false 分支）。
- 验证：PowerShell + 绝对 `C:\Program Files\dotnet\dotnet.exe` 构建 `NoCodeMotion.csproj -c Debug` **rc=0，ERRORS=0**。临时日志已删。
- 教训：
  - 编辑器"运行"是可视化步进，**分支必须按逻辑列+运算真实求值并跳到对应行**；不能一律进主体（否则 `否则` 不可达）。
  - 绝大多数模板的 `如果(WaitIO)` 是**未闭合闸口式**（无 `结束`/无 `否则`），需"线性续行"兜底，否则 `FindEnd` 返回 Count → FinishRun → "只第一行"。
  - 模板 WaitIO 想演示 false 分支必须配 `否则/结束`；否则按闸口处理顺序执行。

## 移植 SamsunMotion 的雷赛 SDK 原生代码（控制卡 轴/IO 真正上机可用）
- 用户升级要求：「直接移植那些控制卡，轴IO的代码过来，这样直接运行在机台可以了」——不止拷 DLL，要把 SamsunMotion 的控制卡代码搬进 NoCodeMotion。

## 项目管理页卡顿优化
- 现象：进项目管理页很卡（"进去这么卡"）。
- 根因（3 处）：① 选中工程 → `LoadDetailFor` → `ProjectManager.GetRequirementsText` → `XlsxProjectStore.OpenProject` **把整个 xlsx（所有集合表）全量反射解析一遍**，只为读一个「需求文本」字段；工程一大就几百 ms~秒级卡。② 每次点进页面 `FinishNavigate` 都调 `EnsureDefaultSelection` → `Refresh()`，**重新枚举并逐个 `new XLWorkbook` 读所有工程 meta**（页面虽已缓存，仍每次重刷）。③ 首次进入 ctor `Refresh()` + `EnsureDefaultSelection` 再 `Refresh()`，等于刷两次。
- 修复：
  1. `XlsxProjectStore` 新增 `LoadMetaValue(name, rowName)`：只读「项目管理」信息表的目标行（与 `LoadMeta` 同原理），不开全量解析。
  2. `ProjectManager.GetRequirementsText` 改用 `LoadMetaValue(name,"RequirementsText")`（轻量，仅读单 sheet 单行）。
  3. `ProjectManagerViewModel.EnsureDefaultSelection` 改为「仅当 `Projects.Count==0` 才 `Refresh()`」，避免重复进入重复枚举磁盘；选中项在缓存中保留，无须重设。
- 验证：PowerShell + 绝对 dotnet 构建 `NoCodeMotion.csproj -c Debug` **RC=0 ERRORS=0**；临时 `build_pmopt.result` 已删。
- 教训：xlsx 里读单个标量字段（备注/需求/创建时间等）绝不要走 `OpenProject`（全量反射）；应加只读「项目管理」信息表的轻量方法。`RequirementsText` 是 `ProjectData` 标量属性，会写进「项目管理」sheet，轻量读取命中正确行。

## 全局卡顿：隐藏页的常驻 33ms 渲染/物理循环空转拖慢所有页面
- 现象：用户「其他页面也需要流畅」——优化完项目管理页后，其他页（轴/IO/点位/变量等）切换/操作时仍感觉不跟手。
- 排查：导航用缓存（`MainWindow._cache`），`EnsureDefaultSelection` 各页都是 `SelectedItem=Items[0]` 这类内存操作（除项目管理页已修，其余都 cheap），所以**切换页面本身不卡**。真正元凶是**预加载把所有页构造进缓存后，仍在 UI 线程上常驻空转的定时器**：
  - `Sim3DView._timer`（33ms）在 ctor 里 `_timer.Start()`：每 tick 跑 `UpdatePoseFromRuntime + UpdateSimVisuals + StepPhysics`（30fps 3D 渲染+物理），**只要 app 开着、即便操作员页不可见也一直跑**。
  - `OperatorViewModel._sim3DTimer`（33ms）ctor 里也 `_sim3DTimer.Start()`：`Sim3DTick` 图表/相位插值，同样常驻。
  - 这两个循环合计 ≈60 tick/s 吃 UI 线程，停在任何其它页时照样占用 → 全局掉帧、其它页不跟手。
  - `OperatorViewModel._uiTimer`（150ms）保留：空闲时只排空空队列（cheap），且运行态要它收尾日志/状态/UI 动作队列，不能停。
  - `CameraPage._flashTimer` 随相机仿真状态启停（非常驻），`FlowViewModel._actualValueRefreshTimer` 是 1s（可忽略），`Cylinder/Point/Engineer` 的 jog/sim/seq 计时器只在交互时跑——都不动。
- 修复（按可见性门控，释放隐藏页的 UI 线程）：
  1. `Sim3DView.xaml.cs`：去掉 ctor 的 `_timer.Start()`，改 `IsVisibleChanged += (_,__) => { if (IsVisible) _timer.Start(); else _timer.Stop(); }`。预加载时页不在可视树（IsVisible=false）→ 不跑；进操作员页才转 true 才跑；最小化/切走即停。
  2. `OperatorViewModel.cs`：去掉 ctor 的 `_sim3DTimer.Start()`，新增 `public void SetSimVisible(bool)`（true 才 Start、false Stop）；`_uiTimer` 不变。
  3. `OperatorPage.xaml.cs`：ctor 订阅自身 `IsVisibleChanged => vm.SetSimVisible(IsVisible)` 并初始调一次。
- 行为：切到轴/IO/点位等页时，33ms 渲染+物理循环停止，UI 线程完全让给当前页 → 跟手。回操作员页自动恢复；运行中的流程由后台线程驱动（不受 3D 计时器影响），仅 3D 可视化在隐藏期间不动画、回来续上。
- 验证：PowerShell + 绝对 dotnet 构建 `NoCodeMotion.csproj -c Debug` **RC=0 ERRORS=0**；临时 `build_visgate.result` 已删。
- 教训：WPF 里任何 `DispatcherTimer` 若处理 3D/物理/图表等每帧重活，**绝不能无条件 Start 并常驻**——必须用 `IsVisibleChanged` 或页面导航钩子按可见性启停，否则隐藏页会把 UI 线程税强加给所有页面。预加载缓存页的 ctor 里 Start 的计时器尤其隐蔽。

## 其他页流畅性查漏补缺（工程师页虚拟化不对症；CameraPage 闪光定时器补门控）
- 用户「好」推进可选项，我选"工程师页 ItemsControl 虚拟化"作第一项，排查后判定不对症：
  - 工程师页轴/IO/气缸三处 `ItemsControl` 都用 `WrapPanel` 卡片换行流布局；WPF 内置 UI 虚拟化（`VirtualizingStackPanel`）只支持线性排列，与换行布局冲突，硬套会丢换行。
  - 该页 ctor 无常驻定时器（`_jogTimer` 按需、松开即停）；轴固定 4 个、IO/气缸数量通常有限，虚拟化收益极小。
  - 上一轮卡顿根因（隐藏页 33ms 渲染/物理循环空转）已修复干净。
- 全局 `DispatcherTimer` 复查（确认还有没有隐藏页常驻空转漏网）：
  - `CylinderViewModel._seqTimer`(33ms)：`PlaySequence` Start、`StopSequence` Stop → **按需播放，非隐藏空转**。
  - `PointViewModel._simTimer`(33ms)：`SimPlay` Start、`StopTimer` Stop → **按需仿真播放，非隐藏空转**。
  - `LuaEditorView._lineTimeTimer`(100ms)：`StartSession` 行636 Start → **运行时按需，非隐藏空转**。
  - `LuaEditorView._syntaxTimer`(1s)：ctor 无条件 Start（语法检查，极轻；Lua 编辑器页生命周期不确定，列为可选不硬改）。
