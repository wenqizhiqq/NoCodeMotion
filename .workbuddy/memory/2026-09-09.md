## 视觉节点实装（NgRunner 不再抛 NotImplementedException）

- 根因：原 `NgRunner.ExecuteNodeSync` 对 6 个视觉节点（CamCapture/TemplateMatch/DefectDetect/Measure/Align/Calib）直接 `throw new NotImplementedException` → 调试器运行即崩（用户报错：`视觉节点 CamCapture 暂未实装`）。
- 方案：新建会话式桥接层 `Services/Vision/NgVisionExecutor.cs`，把 NgRunner 的逐节点执行翻译成 `VisionEngine.Run(IEnumerable<VisualFlowStep>)` 整链执行：
  - 采集节点把当帧落盘 PNG（`VisionEngine.SaveBgra`），后续节点以「文件」源复用同一帧；
  - 测量节点重放本帧已执行算子链取特征点（`AddOp` 按节点 Id 占位复用并截断其后，循环体不膨胀）；
  - 对位消费最近一次 `MatchOutcome`（无则抛"需要上游模板匹配"）；标定走 OpenCV `FindChessboardCorners`/`FindCirclesGrid` 求 mm/px；
  - 全部结果按「变量前缀」写 `SimRuntime.SetVariable`（分数/XY/角度/数量/通过/偏差/值/像素当量…），供 Decision/Compute 节点引用；
  - 节点卡片结果摘要写 `NgStepResult.Summary`（NodeGraphNodeView 新增摘要 Border）。
- 配套改动：`VisionEngine` 加 `Value/Count` 结构化结果 + `UsedSynthetic` + 静态 `SaveBgra`/`Calibrate`；`NgDefs` 视觉 6 节点属性扩展对齐；`NgModel.Normalize()` 旧图升级补齐属性；`NgModel`「视觉对位」模板旧属性名 `模板`→`模板路径` 修正;`NgRunner` 移除 6 行 throw 改 `_vision.Execute(node)`。
- 构建验收（PowerShell 内联，**禁止 .ps1 文件**——ExecutionPolicy 拦截）：`& "C:\Program Files\dotnet\dotnet.exe" build ... -v normal` **0 错误**（590 警告均为 CA1416 平台兼容，非错误）。

## 视觉节点跑通后的二次修复（用户截图反馈）

- 用户跑视觉流程，新异常 `InvalidOperationException: 请先框选模板区域（或设置有效模板路径）` 抛在 `NgVisionExecutor.Match` 行 181（截图）。**不是实装不到位**，是模板匹配引擎在没有「模板路径」+「模板框」时拒绝运行，而 `失败即停=是` 把这条拒绝消息当异常抛了。
- 修复（仅改一处文件 `Services/Vision/NgVisionExecutor.cs`）：
  1. 三处 `失败即停 / 超限即停 / 超差即停` 默认值统一改为 `否` —— 让流程能端到端跑通，由 Decision 节点按 `通过` 变量判定。
  2. `Match` 用 `try/catch(InvalidOperationException)` 兜住引擎的「请先框选」类配置异常，降级为「写 `通过=0` + 摘要 `模板匹配未配置（...原因...）`」返回，不抛错打断流程。
  3. 匹配无结果（`m==null`）时仍把 `分数/数量/通过` 写进变量 —— 上游 Decision 拿得到判定数据。
- 构建：`dotnet build ... -v quiet` → `EXITCODE=0`，`error CS` 数 = 0。
- 通用结论：**新加节点执行器时，「配置缺失」 ≠ 「致命异常」**。配异常应当降级（写变量=0 + 摘要给原因），让流程能继续到下一个节点，由 Decision 节点决定怎么走。真正致命异常（采集完全失败、标定无帧）才抛。

## 复用的坑（已写入 MEMORY.md）
- WPF `EnableDefaultPageItems` 自动把 `*.xaml` 当 Page 编译 → `_utf8` 重复 XAML 同 class 必 CS0102/CS8646。
- NgRunner 暂停循环必须按 `_state` 轮询，不能只看 CancellationToken。
- 构建脚本**不能写成 .ps1 文件**（系统 ExecutionPolicy 报 UnauthorizedAccess）；必须 PowerShell 工具内联命令、或 `powershell -ExecutionPolicy Bypass -File`。
- **新加节点执行器**时，「配置缺失」 ≠ 致命异常：配异常应降级（写变量=0 + 摘要给原因），由 Decision 节点决定走向；只有采集完全失败/标定无帧等真致命才抛。
- **节点图调试器绝不抛任何异常到 IDE**。所有节点级错误必须经 `NgStepResult.ErrorText` + `Report.LastError` + `bridge.Log` 三处统一显示；只有 NgRunner 调度层自身崩溃才允许切 Error 状态。
- **沙箱 Bash 在含中文路径的 argv 上必坏**（PortableGit 把 UTF-8 argv 解释为 null bytes / 乱码）。所有中文路径命令走 PowerShell 工具；python 脚本走 `PowerShell & python.exe`；不要在 Bash 工具里执行中文路径的 dotnet/python。
