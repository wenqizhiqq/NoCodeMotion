  - 新建 `Services/XlsxProjectStore.cs`：**反射式通用 xlsx 读写**（ClosedXML 0.105.1，csproj 已引用）。
    - `Save/Load(projectName, IDictionary<string,DataTable>)` 低层；

    - `ImportFromDataTables(object root, tables)`：按 sheet 名(=属性名)反射清空重建集合 + 标量回填（含类型转换/容错）；
    - `SaveProject/OpenProject` 便捷封装；`ListProjects/Delete/Exists/FilePathFor`；
    - `SheetNameOverrides` 字典用于把属性名映射成中文 sheet 名（目前空，待填）。

## 需求：操作员「运行」= 流程页面里全部异步循环
- 用户原话：「操作员页面的运行是流程页面里面的全部异步循环运行」。
- 架构现状（grep 取结构，相关 .cs 均加密）：
  - `OperatorViewModel.cs`：`RunCommand`→`StartOrResume()`(L235)，实际跑在后台线程 `_runThread=new Thread(RunLoop)`(L309)，`RunLoop()`(L410)；当前 `CanStart` 要求 `SelectedTable!=null && SelectedTable.Points.Count>0`，即跑的是**点位表序列**，与流程无关。
  - `FlowViewModel.cs`：`Items=ProjectStore.Data.Flows`（每 FlowPage `new` 一个实例，无共享注册表）；循环执行器在私有 `Run()`(L198) 内：`循环开始`/`循环结束` 配对 + `_loopStack`/`LoopFrame` + `FindLoopEnd`(L495) + `ParseLoopCount`(L525,次数取 `step.SetValue`)。
  - 代码无「异步」字样 → 「异步」= 每个流程循环区域作为独立 `Task` 并发跑。
- 已确认设计（用户选择）：
  - **替换点位表运行**：点「运行」只执行流程全部异步循环，不再跑 SelectedTable.Points；`CanStart` 改为「有流程且未运行」。
  - **每流程一个 Task 并发**：每个 `ProjectStore.Data.Flows` 的 FlowItem 起一个独立 async Task，各自执行其 循环开始/循环结束 区域（次数取 SetValue），互不阻塞。
- 实现要点（待解密后落地，AI 改不了加密 .cs）：
  1. `FlowViewModel`：把 `Run()` 的循环/步骤执行核心抽成公开 `Task RunAllLoopsAsync(FlowItem, CancellationToken)`（或 `RunFlowLoopsAsync`），去掉对单一 SelectedItem 的依赖，遍历该 flow 的 Steps 执行循环区域。
  2. `OperatorViewModel`：`StartOrResume` 启动后对每个 FlowItem `Task.Run(()=>flowVm.RunAllLoopsAsync(flow, _cts.Token))`，用 `_cts` 统一管理暂停/停止；`RunLoop` 不再遍历 Points；`CanStart`/`RunButtonText` 相应调整；暂停=挂起/继续，停止=`_cts.Cancel()`。
- **后续收紧（用户截图补充）**：
  - **不要选择工位**：`CanStart` 改为 `!IsRunning && !EStopped`（去掉 `SelectedTable!=null && SelectedTable.Points.Count>0` 的前置）。
  - 状态文本去掉「选择工位并启动」字样，改为「已复位，可启动运行全部流程」之类。
  - 模式按钮「手动/自动」保留；启动/暂停/停止/急停/复位逻辑保持。
  - 启动按下→遍历 `ProjectStore.Data.Flows`，每 FlowItem 一个 `Task` 跑其 `循环开始/循环结束` 区域（次数取 `SetValue`），并发；不再依赖 `SelectedTable.Points`。
- **阻塞**：需用户解密 `ViewModels/OperatorViewModel.cs`、`ViewModels/FlowViewModel.cs`（及 `Models/FlowItem.cs`/`FlowStep.cs` 核对 Step 字段与每步执行动作）后，AI 才能写正确补丁。

## 已落地：操作员「启动」按全部工位顺序连续运行
- 用户截图："已复位，可重新选择工位并启动。" → 抱怨点击 启动 还要先选工位，用户希望直接点就跑到全部工位跑完。
- 改动文件：`ViewModels/OperatorViewModel.cs`
  - `using System.Linq;`（已有 using 段新增一行）
  - `CanRun`/`CanStart` 改为 `HasAnyRunnableTable()`（任意工位有点位即可启动）
  - 新增 `private bool HasAnyRunnableTable()`
  - `Start()` 自动模式日志与状态文本改为"全部 {runnable} 个工位，按顺序连续运行"
  - `RunLoop()` 改为外层 `foreach (var table in Tables)`，空工位自动跳过；UI 内 `SelectedTable = table; BuildTimingRows()` 重新构建；点数循环用 `ExecutePointForTable(table, idx)`
  - 新增 `ExecutePointForTable(PointTable table, int idx)`（后台线程直接调用，不切换 SelectedTable，避免交叉线程修改 ObservableCollection）
  - 默认状态文字：`"请选择工位，点「启动」开始生产。" → "点「启动」开始运行（按全部工位顺序连续执行）。"`
  - 复位状态文字：`"已复位，可重新选择工位并启动。" → "已复位，点「启动」运行（按全部工位顺序）。"`
  - 完成状态文字：`"运行完成：…共 n 个点位…"` → `"全部工位运行完成：N 个工位 / M 个点位 / 产量 X 件。"`
- **注意**：本轮改动解读为"按 Tables 顺序跑全部点位"，**与设计文档中「运行 = 流程页面的全部异步循环」不同**。若用户后续要求改为跑 Flow 循环，需要再动 `FlowViewModel.Run()` 抽出 `RunAllLoopsAsync(FlowItem)`，并在 `OperatorViewModel.Start()` 用 Task.Run 包并发跑。
