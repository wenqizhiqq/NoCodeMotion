## 已修复：单步 + 左侧当前行/耗时不显示（Request E）+ 复用编辑器页面运行（Request D 补完）
- 现象：加入 Operator 连续运行后，「单步」失效、左侧不显示当前行与每行耗时。
- 根因：
  1. **静态事件泄漏**：`LuaEditorView` 构造里 `LuaRunMonitor.LineChanged/RunEnded +=` 订阅，**卸载时从未退订**；Operator 跑 Lua 时 `LuaRunMonitor.Report` 同步触发所有（含已释放）实例的 `OnMonitorLine`，触碰已销毁 `Editor` 抛异常，异常抛回 `LuaDebugSession.GetAction` 脚本线程，破坏调试会话（含单步）。
  2. **通道混淆**：编辑器自身会话也走 `LuaRunMonitor.Report`（与 Operator 独立会话同一公共通道），Operator 广播会抢占用户正在单步的当前行/滚动位置。
- 修复（明文 `Views/LuaEditorView.xaml.cs` + `ViewModels/FlowRunnerService.cs`）：
  - 构造 `Unloaded` 退订 `LuaRunMonitor` 两事件并清 `Active`；`Loaded` 置 `Active=this`；新增 `public static LuaEditorView Active`。
  - 编辑器自身会话改为**直接** `Dispatcher.BeginInvoke(HighlightLine)` 高亮（不再经 `LuaRunMonitor`）；`OnMonitorLine/OnMonitorEnded` 增加 `IsLoaded`/`Editor`/`Document` 空守卫，且当本编辑器正在手动调试（`_session.IsBusy && !_operatorDriven`）时忽略 Operator 广播，避免抢占单步行。
  - `StartSession` 增 `operatorDriven` 形参；新增 `public LuaDebugSession RunFlow(FlowItem, bool)`（载入脚本、清断点、启动会话，忙时返回 null）。
  - `FlowRunnerService.RunOneFlowLua` 改为：**优先** `LuaEditorView.Active?.RunFlow(flow)` 复用编辑器页面运行（满足 Request D「lua 直接走编辑器页面运行」），编辑器未就绪/被占用时退化为独立 `LuaDebugSession` + `LuaRunMonitor` 广播（保证并发多 Lua 流程也能跑，且空闲时编辑器仍高亮当前行）。
- 构建：`dotnet build -c Debug` → **0 错误**（仅既有 CS8600/CS8602/CS0414 可空/未用字段警告）。注：`UseArtifactsOutput=true` 是无效 CLI 参数（NETSDK1200），须放 `Directory.Build.props`，本次未用。
- 约束提醒：编辑器单会话，Operator 经 `RunFlow` 占用后用户需先停 Operator 才能手动 F5/F10 单步（属预期，非 bug）。
- 待用户 VS 内 Ctrl+Alt+F7 Rebuild 实测单步与左侧当前行/耗时。
