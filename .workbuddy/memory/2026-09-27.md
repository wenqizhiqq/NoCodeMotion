## 5. ★ 复位/运行收尾把变量 +1 冲掉的根因修复（快速点+1、慢点不+1 之谜）
- 症状：操作员复位按钮**快速连点**变量 +1，**慢慢单击**不 +1。
- 根因：`FlowRunControl.InitVars()` 在运行前把工程变量表**全量快照**进 `Vars`；节点图/ Lua 的变量写（`SimRuntime.SetVariable`）只进工程表不进 `Vars`；运行结束 `FinalizeReset`/`FinalizeRun` → `WriteBackVars()` 把**全量旧快照**写回工程表 → 刚 +1 的值被旧值覆盖。快速连点时上一次收尾因 `gen != _runGen` 被丢弃、不执行 WriteBackVars，+1 才幸存。
- 修复（脏键追踪）：`FlowRunControl` 新增 `Touched`(HashSet)；
  - `WriteVarLive` 写 Vars 时标记 Touched（表格变量步，本就双写）；
  - 视觉结果 `_ctrl.Vars[resKey]=...`（只进运行仓、依赖收尾落表）补 `Touched.Add`；
  - `WriteBackVars()` 只回写 Touched 键，`InitVars()` 清空 Touched。
- 影响：FinalizeReset（OperatorViewModel:760）、FinalizeRun（:607）、流程页 OnBgFinished（FlowViewModel:893）三处收尾统一生效——运行/复位后变量不再被旧快照回滚。

## 12. ★★ 修「操作员运行中一切到流程页就不动了」的两个根因
- **根因 A（节点图，AI 上一轮自己引入的坑）**：`NodeGraphViewModel` 的镜像回调跑在**外部 running 的后台线程**上，却直接改 UI 线程的 `Nodes` 集合。切到流程页时 `LoadFrom` 会 `Nodes.Clear()/Add()` 重建集合 → 后台线程并发遍历/赋值 → `InvalidOperationException`（集合已修改）→ 异常从 `ReportChanged` 冒回 `NgRunner.RunAsync` 被 catch → 该节点被记成 Error，整轮立即结束；每轮如此 → 表现为"运行中但什么都不动/像停了"。
  → 修复：`ScheduleMirror(Action)`（**封送 UI 线程 + 单帧合并**：`_mirrorPending` 为真就丢帧），自身运行与外部镜像统一走它，apply 内 try/catch。`OnRunnerStateChanged` 里同步 `HasBreakpoint` 的循环也一并封送。
- **根因 B（Lua）**：`LuaEditorView` 在 `Unloaded` 与 `OnLuaItemChanged` 里无条件 `_session?.Stop()`。操作员驱动时该会话由后台运行器持有 → 离开/回到流程页、或重绑 LuaItem 就把生产运行的那一轮打断。
  → 修复：两处都加 `if (!_operatorDriven) _session?.Stop();`。
- 通用教训：**任何"运行器后台线程 → 编辑页 VM 集合"的回调都必须封送 UI 线程并做帧合并**；编辑器侧的 `Unloaded`/选中变化**不能停后台运行器持有的会话**（生产运行时用户会随时切页）。

## 13. ★★ 架构定型（用户明确要求）：运行全在后台 thread + while(true) + 1ms；**页面一律用定时器轮询共享态刷新状态/行序号/当前节点**
- 用户原话：「流程的运行应该全部都是 thread while true 1毫秒，然后流程内部都需要是定时器刷新状态和行序号就好了，这样操作员页面调用循环运行就正常了」。
- 冲突点：原来（我上几轮）用「运行器 → 页面」**推送**（`NgRunner` 回调直接改节点 VM / `LuaRunMonitor` 广播行号 / `NodeGraphRunMonitor` 广播 runner），在"运行中切页/切流程"时必然跨线程改 UI 集合 → 崩/停。
- 落地：
  1. `FlowRunStore` 扩成进度总线：`SetProgress(flow, stepIndex?, line?, nodeId?)` + `GetProgress()`（步骤下标 / Lua 行 / 节点图当前节点 Id）+ `SetNodeResults/GetNodeResults`（节点图每节点结果快照，页面读数上色/显示耗时摘要）。
  2. 运行器只**写共享态**：`RunOneFlowNodeGraph` 在 `ReportChanged/StateChanged` 里 `SetProgress(nodeId)` + `SetNodeResults(Report.Results)`；finally 里 `SetProgress(nodeId:"")`。Lua 两路径的 `LineStepped` 里 `SetProgress(line: line)`。
  3. **删除 `NodeGraphRunMonitor`**（不再需要推送）；`NodeGraphViewModel` 改为 200ms 定时器 `RefreshExternalRunFromStore()`：读共享态设 `IsCurrent` + 套 `StepResult`（本页自己 runner 在跑时跳过）。`LoadFrom` 只需刷一次状态文字（下一拍定时器自动补亮当前节点）。
  4. `LuaEditorView` 新增常开的 100ms `_externalPollTimer` → `PollExternalRun()`：外部运行时读共享态行号 → `HighlightLine` + 状态「运行中…/循环运行中…」（与 `LuaRunMonitor` 推送互为兜底）。
  5. 左侧流程列表状态芯片仍由 `FlowRunStore.PushStatuses()`（UI 线程）从共享态抄到 `FlowItem.Status`，操作员页 150ms + 流程页/节点图页定时器都调。
- 原则：**运行器永远不碰任何 UI 对象/VM 集合；页面永远不驱动运行器**（唯一例外：用户点停止 → 置 `EditorStopRequested`）。切页、切流程、页面卸载都不得影响运行。

## 15. ★★★ 【真凶】切到流程页后变量不再增加 = Lua 的 `Variable.Set` 把 UI 侧异常冒回脚本线程 → 流程被判"脚本报错"而 break
