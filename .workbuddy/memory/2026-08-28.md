## MC3093 + XamlParseException 修复（FlowPage 视觉宿主：ContentControl + 不可命名 + 用 Content 绑）
- 用户报两次：先 `ContentControl x:Name=VisionHost` 报 MC3093；改 `Border x:Name=VisionHost` 后**仍报 MC3093**（"Border"在元素"EditorPage"的范围内，在另一范围内定义它时，已注册了名称）。
- ⚠️ **关键更正（之前记错过）**：之前以为"Border 不创建 NameScope，命名安全"——**错误**。MC3093 与元素类型无关（ContentControl / Border 都会触发）。真正规则：**凡在 `EditorPage.Detail`（ContentControl）内容里放 `x:Name` 的元素，名字会同时注册到「EditorPage 作用域」与「ContentControl 内容作用域」两个 NameScope → 必然 MC3093**。（表格 Grid / LuaEditorView 不报，正因它们没用 x:Name。）
- 最终修法（已落盘，正确版）：
  - `Views/FlowPage.xaml`：宿主改为 `<ContentControl>`（**无 x:Name**），`Content` 绑 `VisionContent`（`RelativeSource AncestorType=local:FlowPage`），`Visibility` 仍绑 `IsKindVision`。无命名元素 → 无 MC3093；用 Content DP（而非 Border.Child CLR）→ 绑定合法。
  - `Views/FlowPage.xaml.cs`：在 `FlowPage` 上加依赖属性 `VisionContent`（`DependencyProperty.Register(nameof(VisionContent), typeof(UIElement), typeof(FlowPage), null)` + CLR 包装）；`EnsureVision()` 不再碰任何命名控件，而是 `VisionContent = new VisualFlowPage()`（catch 时赋橙色 TextBlock）。延迟/异常兜底逻辑不变。
- ⚠️ **必须整体 Rebuild（Ctrl+Alt+F7），不能增量 Build**：旧 `obj/.../Views/FlowPage.g.cs` 仍含 `Border VisionHost` 字段与强转；增量 Build 会沿用该 stale 文件。Rebuild 重生成后该字段消失，且新 .g.cs 不再引用 VisionHost，MC3093 / "does not contain a definition" 都消失。XDG000/XDG-00 是设计期幽灵，以 Output "Build succeeded" 为准。
- 附带确认的结构：FlowPage 编辑器区三层（`Grid Visibility=IsKindTable` / `LuaEditorView Visibility=IsKindLua` / `ContentControl Visibility=IsKindVision` 且 Content 绑 VisionContent）是 `Grid Grid.Row=1` 内的兄弟节点，互斥可见，互不影响；表格区域结构完整。
- 经验沉淀（**WPF 通用**，与项目无关）：
  1. **任何 ContentControl 直接内容里给子元素命名 = 必踩 MC3093**；要用命名引用就走「依赖属性 + RelativeSource/ElementName 绑定」，或视觉树查找（按 Tag），不要 x:Name。
  2. **承载+绑定的单子元素用 ContentControl**（`Content` 是 DP、可绑），别用 Border（`Child` 是 Decorator 的 CLR 属性、不可绑——XAML 上写 `Child="{Binding...}"` 会立即抛 XamlParseException）。想自定义外观把 `ContentControl.Template` 设成带圆角/背景/边框的 ControlTemplate 即可。

## 视觉页「添加步骤点了没反应」根因 + 修法（RelativeSource on 非树 DP）
- 用户反馈（截图视觉流程1 头部，点添加步骤无反应，左侧步骤列表为空）。
- 根因：`VisualFlowPage.xaml.cs` 旧版 `OnLoaded` 用 `BindingOperations.SetBinding(_vm, StepsProperty, new Binding("SelectedItem.VisualSteps") { RelativeSource = ancestor, ... })`，target 是 `_vm`（一个 `DependencyObject`，**不在可视树里**）。**RelativeSource 祖先解析要求 target 必须在可视树中**，VM 只是 DataContext 不是 UIElement，没有可视父级可走，绑定静默失败 → `_vm.Steps` 永远 `null` → `AddStepCommand` 内 `if (s == null) return;` 直接退出 → 用户点没反应。
- 修法（已落盘 `Views/VisualFlowPage.xaml.cs`）：
  - 删掉所有 `BindingOperations.SetBinding`；
  - `Loaded` 用 `VisualTreeHelper.GetParent` 沿可视树向上找 `FlowPage` 祖先；
  - 订阅 `FlowPage.DataContext`（即 `FlowViewModel`）的 `PropertyChanged`，监听 `SelectedItem` 变化；
  - 手动同步 `_vm.Steps = sel?.VisualSteps` / `_vm.Name = sel?.Name`；
  - `Unloaded` 时解绑，防止同实例复用时的二次订阅。
- 经验沉淀（**WPF 通用**）：
  1. **RelativeSource 绑定**只能挂在 **可视树里的 UIElement/FrameworkElement 上**；DataContext（DependencyObject）上的 DP 不在树中，RelativeSource 解析不到祖先、绑定静默失败，**症状就是"看上去没绑定"或"目标属性一直为 null"**。需要跨树同步时：要么走 `ElementName`/`RelativeSource`（要求 target 是树里的），要么在 Loaded 用 `VisualTreeHelper` 找祖先 + 手写 `PropertyChanged` 同步。
  2. **ObservableCollection 作为 DP 的值**：UI 自动响应集合的 Add/Remove（集合本身 INPC），把集合整体换掉（`_vm.Steps = newCollection`）也会触发 DP 通知 → ListBox 重新绑定到新集合。

## 视觉引擎图像算术 CS0019（&/| on double）— 已修
- 用户报 `VisionEngine.cs` 378/379 `运算符"&"无法应用于"double"和"double"` / `"|"同理`。
- 根因：`Func<double, double, double>` 的 lambda 里直接写 `a & b` / `a | b`，位运位只对整数合法。
- 修法：`(double)((int)a & (int)b)` / `(double)((int)a | (int)b)`（值已 Clamp 在 0~255，转 int 安全）。
- 理由：二维码 Reed-Solomon 手写易踩坑；模板/测量增强都需要"图像可被先处理"作前提；按"最小作用域、每轮可构建运行"拆。

### OpenCV 图像算术 CS7036/CS1501 修法（4.13 二元算子必须自带 dst）
- 用户报 4 个错（VisionEngine.cs L431-434）：`Cv2.Add/Subtract/BitwiseAnd/BitwiseOr` 两参便利重载在 OpenCvSharp4 4.13 **不存在**，必须显式传第三参 `OutputArray dst`。
- 修法（已落盘）：预先 `new Cv.Mat(cur.Rows, cur.Cols, Cv.MatType.CV_8UC4)` 作接收，按 op 选 `Cv2.Add/Subtract/BitwiseAnd/BitwiseOr(cur, b2, r)` 写入 r，再 dispose cur/b2、return r。
- 经验：OpenCvSharp 二元算子（Add/Subtract/Multiply/Divide/BitwiseAnd/Or/Xor/Compare、AbsDiff、Max/Min）统一都是 `(InputArray, InputArray, OutputArray, ...)` 无返回值；少数单参的（CvtColor/EqualizeHist/Sobel）才有 `(src, dst, ...)`。要返回新 Mat 就先 `new Mat(rows, cols, type)` 当 dst。
