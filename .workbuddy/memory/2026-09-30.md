## ★★ 「轴使能设置不了 / IO 号要从 0 开始」根因（0 基寻址）
现场：研控 MCN42Series（PCI 脉冲，8 轴 / 16 入 / 16 出，MCN420.dll），控制器已连、IO 能写。
- **根因 1（轴）**：连接控制器时 `AxisControllerViewModel.GenerateAxisPoints` 把「轴号」按 **1..N** 生成（`MakeAxis(tag, ++n, s)`）。
  而卡轴号是 **0 基**（`AxisOf` → `a.AxisID = axis.AxisNo` → `YK_set_sevon_config(card, AxisID, 1)`）：
  每根轴都错位一根，最后一根（轴号 8）直接越界 → 使能 / 运动 / 读位置全部失败，且卡族层**只记一行日志、不抛异常**，
  界面照报「已下发」→ 现场就是「点了使能没反应」。
  修复：`MakeAxis(tag, s, s - 1)`（名称 轴1..轴N / 轴号 0..N-1）。
- **根因 2（IO）**：同文件 `GenerateIoPoints` 主板 / 扩展 IO 的「序号」也按 **1..N** 生成。
  「序号」就是卡上位号（`MainBoardBit = 模块 × BitsPerModule + 序号`、雷赛 `BitNo` 同式），
  于是每个点错位一位、最后一点超到 16（超出 0~15）。修复：`for (s = 0; s < count; s++)`，名称同步 0 基（输入0..输入15）。
  `IoViewModel.MakeNew`（手工「添加」）同样从 0 起。
- **根因 3（看不到使能结果）**：MCN42 的 `AxisRealization.GetAxisCurrentState()`（无参，桥靠反射当状态字读）原样调
  `SDK.DmcGetCardAxisIOState`，而移植版 `MCN420SeriesSDK` 里那个函数是**未添加**（直接 throw，签名也拿不出状态）→
  轴页「报警/正负限位/原点/急停/使能/状态字」整片显示「—」。
  修复：改用 MCN420.dll 里**已可用**的 `YK_get_axis_alm_status / positive|negative_limit_status / emg / home / inp / sevon_config`
  按 dmc_axis_io_status 位布局（bit0 ALM、bit1 EL+、bit2 EL-、bit3 EMG、bit4 ORG、bit5 INP、bit8 Sevon）拼出状态字，只在读到 1 时置位。
  ★ 硬件事实（MCN420 手册）：**伺服使能 Sevon 只对 0~3 轴有效**（占用通用输出 OUT32~OUT35），4~7 轴没有该功能 → 已写进卡族 Note。
- `AxisRowViewModel`：新增 `InvokeEnable(action, enable)`——使能/不使能**下发后读回真实状态**再回报；
  读回与期望不一致 → 状态栏红字 + 三条处置提示（轴号是否 0 基 / 伺服上电与报警 / 该卡是否支持这根轴）。
- `WenQiZhiCardBridge.AxisOf`：轴号 ≥ 卡族 `AxisCount` 时打一次明确警告（含「轴号应为 0~N-1」），用 `_warnedAxisNoRange` 去重。
- `CardFamilyCatalog` MCN42Series Note 补：轴号 0~7 / IO 位号 0~15 / 使能只对 0~3 轴。
- 构建 0 错误（nocode_int36/out36）。**注意：重新点「连接控制器」会按新规则重建轴与 IO 点（会清空当前列表）**。
