## ★★ 「轴使能设置不了 / IO 号要从 0 开始」根因（0 基寻址）
现场：研控 MCN42Series（PCI 脉冲，8 轴 / 16 入 / 16 出，MCN420.dll），控制器已连、IO 能写。
- **根因 1（轴）**：连接控制器时 `AxisControllerViewModel.GenerateAxisPoints` 把「轴号」按 **1..N** 生成（`MakeAxis(tag, ++n, s)`）。
  而卡轴号是 **0 基**（`AxisOf` → `a.AxisID = axis.AxisNo` → `YK_set_sevon_config(card, AxisID, 1)`）：
  每根轴都错位一根，最后一根（轴号 8）直接越界 → 使能 / 运动 / 读位置全部失败，且卡族层**只记一行日志、不抛异常**，
  界面照报「已下发」→ 现场就是「点了使能没反应」。
  修复：`MakeAxis(tag, s, s - 1)`（名称 轴1..轴N / 轴号 0..N-1）。
- **根因 2（IO）**：同文件 `GenerateIoPoints` 主板 / 扩展 IO 的「序号」也按 **1..N** 生成。
  「序号」就是卡上位号（`MainBoardBit = 模块 × BitsPerModule + 序号`、雷赛 `BitNo` 同式），
  于是每个点错位一位、最后一点超到 16（超出 0~15）。修复：`for (s = 0; s < count; s++)`，名称同步 0 基（输入0..输入15）。
  `IoViewModel.MakeNew`（手工「添加」）同样从 0 起。
- **根因 3（看不到使能结果）**：MCN42 的 `AxisRealization.GetAxisCurrentState()`（无参，桥靠反射当状态字读）原样调
  `SDK.DmcGetCardAxisIOState`，而移植版 `MCN420SeriesSDK` 里那个函数是**未添加**（直接 throw，签名也拿不出状态）→
  轴页「报警/正负限位/原点/急停/使能/状态字」整片显示「—」。
  修复：改用 MCN420.dll 里**已可用**的 `YK_get_axis_alm_status / positive|negative_limit_status / emg / home / inp / sevon_config`
  按 dmc_axis_io_status 位布局（bit0 ALM、bit1 EL+、bit2 EL-、bit3 EMG、bit4 ORG、bit5 INP、bit8 Sevon）拼出状态字，只在读到 1 时置位。
  ★ 硬件事实（MCN420 手册）：**伺服使能 Sevon 只对 0~3 轴有效**（占用通用输出 OUT32~OUT35），4~7 轴没有该功能 → 已写进卡族 Note。
- `AxisRowViewModel`：新增 `InvokeEnable(action, enable)`——使能/不使能**下发后读回真实状态**再回报；
  读回与期望不一致 → 状态栏红字 + 三条处置提示（轴号是否 0 基 / 伺服上电与报警 / 该卡是否支持这根轴）。
- `WenQiZhiCardBridge.AxisOf`：轴号 ≥ 卡族 `AxisCount` 时打一次明确警告（含「轴号应为 0~N-1」），用 `_warnedAxisNoRange` 去重。
- `CardFamilyCatalog` MCN42Series Note 补：轴号 0~7 / IO 位号 0~15 / 使能只对 0~3 轴。
- 构建 0 错误（nocode_int36/out36）。**注意：重新点「连接控制器」会按新规则重建轴与 IO 点（会清空当前列表）**。

## ★★ 使能按钮「反了」+ Jog 失败 8194 + 设零点 20480（三个症状同一个根因）
现场反馈：使能能生效但**反着**（点使能=不使能、点不使能=使能）；Jog 报「卡返回 8194」；设零点报「卡返回 20480」。

### 根因 1：`YK_set_sevon_config` 的第 3 个参数是**端口电平**，不是逻辑使能
- 原生声明（`Services/Hardware/Cards/Native/MCN420.cs`）写得很明确：
  `sevon_en: 设置伺服使能端口电平，0低电平；1高电平；`
  同文件 `GetCardAxisSevonPin` 的注释：`伺服使能端口电平，0：低电平(on)，1：高电平(off)`
  → **研控脉冲卡 Sevon 低电平有效：写 0 = 使能，写 1 = 不使能**。
- 移植版 `MCN420SeriesSDK` 里 `NmcSetCardAxisEnable` 却写 **1**、`NmcSetCardAxisDisable` 写 **0** —— 正好写反。
- 修复：Enable → 写 0、Disable → 写 1。**全工程只在这一层做电平翻转**（界面只暴露「使能/不使能」语义）。
- 连带修状态字：`AxisRealization.GetAxisCurrentState()` 的 bit8 原来 `YK_get_sevon_config(...) == 1` 才算使能，
  按低有效应改成 `== 0`；新增 `NormalizeSevon(raw)`（0→1、1→0、其它原样）统一「1 = 使能 ON」语义。
- 旁证：`CardAxisWriteSevonPin`（参考实现，参数是逻辑使能 0失能/非0使能）改完后自洽了；
  `GetCardAxisSevonPin` 的注释本来就是「0 = 低电平(on)」；模拟卡也是 active-low（`VirtualMotionCard` 自己的实现，未受影响）。

### 根因 2：**「脉冲当量」从来没下发到卡**（这才是 Jog / 设零点失败的元凶）
- 研控 YK API 里当量叫 **`YK_set_command_ratio(card, axis, pulses/unit)`（指令位置比率）**
  —— 原生声明原文：「command_ratio：表示指定轴的比率（puls/unit）；… 10000 个脉冲转一圈、螺距 1234.5mm
  则指令比率 = 10000/1234.5 = 8.100445」。**DLL 里没有别的当量接口**（261 个 YK_ 导出里没有 equiv）。
- 而移植版 `DmcSetCardAxisEquiv` **错映射**到 `YK_set_axis_out_pulse_mode`
  （那是 0~15 的**脉冲输出模式**，写当量进去会把脉冲模式改坏）——而且这个函数全工程**一次都没被调用过**。
- `WenQiZhiCardBridge` 里 `EquivOf/BuildSimParam` 只给**模拟卡**换算，真实卡假定「卡内按当量换算」
  （代码注释就这么写的），但没人告诉卡当量是多少 → 卡内为 0。
- 卡族所有指令都是 **unit 版**（`YK_vmove` / `YK_pmove` / `YK_set_command_position`），
  卡内靠这个比率做 unit↔脉冲 换算；比率为 0 时这些指令被卡直接拒绝 → **只回一个数字**：
  Jog 8194 / 设零点 20480。而纯脉冲量的接口（设速度曲线、`YK_remove_axis_alm`）不换算 → 反而「成功」。
- 修复：
  1. `DmcSetCardAxisEquiv/GetCardAxisEquiv` 改回 `YK_set_command_ratio / YK_get_command_ratio`。
  2. MCN42 的 `SetCardAxisPulseEquival` 顺带 `YK_set_encoder_ratio(card, axis, 1/当量)`（unit/pulse，仅 0~3 轴），
     让「编码器」列与指令位置同量纲。
  3. `WenQiZhiCardBridge` 新增 `EnsureAxisRatio(slot, a, axis)`（非模拟卡才调用，try/catch 只记提示）：
     **连接成功后 `PushAxisRatios(slot)` 一次**（遍历该控制器下的轴），并在
     `SetAxisSpeed / SendPointMove / InchAxis / StartAxisJog / SetAxisZero` 下发前各自再推一次
     （用户改了「脉冲当量」无需重连即可生效）。雷赛层本来就每次运动前 `ApplyAxisProfile` 带当量，卡族层是漏了。
- 另外：`StartAxisJog / InchAxis / SetAxisZero` 失败文案改为追加 `AxisFailHint(axis)`
  （使能 / 当量 / 轴号 / 报警限位 / 卡型号五条，且带上当前当量数值），不让操作员对着数字猜。

### 结论 / 现场验证顺序
0 错误（nocode_int37/out37，612 警告）。双击 exe 后：
1. 「控制器」页重新点「连接控制器」（会重建轴与 IO 点）→ 日志应出现「已按工程配置下发 N 根轴的脉冲当量」；
2. 「轴」页确认「脉冲当量」与机械实际一致（**填 0 或填错一样会让卡拒绝 unit 指令**）；
3. 点「使能」→ 伺服应**锁轴**（低电平有效），轴页「使能」列变绿；
4. 再点 Jog / 设零点，应正常。
排查顺序：使能 → 当量 → 轴号 → 报警/限位 → 卡型号。
