## 工程 JSON 注释注入器（JSONC，给 AI 改配置用）
- 新增 `Services/ProjectJsonAnnotator.cs`：把工程保存成**带中文注释的 JSON（JSONC）**，用户可直接把 `%LocalAppData%\NoCodeMotion\Projects\工程名.json` 丢给 AI（豆包等）改配置。
- 实现思路（避免手写几十个字段）：`JsonSerializer` 正常序列化 → `JsonDocument` 解析 → `Utf8JsonWriter` 重写，遇到「已知属性名」时先 `WriteCommentValue` 注入注释。新增模型字段只在 `TopLevelComments` 字典补一条即可。
- 两处关键修复：
  1. 缺 `using NoCodeMotion.Models;` → CS0246，已补。
  2. Number 分支 `w.WriteNumberValue(el.GetRawText())` 无 string 重载 → CS1503，改为 `else w.WriteRawValue(el.GetRawText())`（覆盖超大数/科学计数法）。
- 中文可读性：序列化与重写两处都用 `JavaScriptEncoder.UnsafeRelaxedJsonEscaping`，避免中文被转成 `\uXXXX`，方便人/AI 直接阅读修改。
- 读取统一入口：`ProjectJsonAnnotator.Deserialize`，`ReadCommentHandling = JsonCommentHandling.Skip` + `AllowTrailingCommas = true`。已在 `ProjectManager`（WriteFile + 5 个读点）与 `ProjectStore`（Load/Save）全部接好，JSONC 往返验证成功。
- 注释覆盖范围：文件头（AI 修改指引 5 条）+ 14 个顶层字段（Controllers/Axes/Inputs/Outputs/Cylinders/Cameras/Comms/Trays/PointTables/Flows/Variables/RequirementsText/Remark/CreatedAt/UpdatedAt）。
- 验证：`dotnet build -c Debug` 0 错误（24 个预存 warning，来自 FlowRunnerService/OperatorViewModel/VisionEngine，与本特性无关）。用临时 harness（`_projtrash/AnnoTest`）生成 `sample_project.json`，16 个 `/* */` 注释块，往返解析成功。
- 清理：根目录残留 `write_annotator.py` 已移到 `D:\wqz\code\_projtrash\`；`AnnoTest` 验证工程也留在 `_projtrash`。

## 工程存储从 JSONC 切换到 XLSX（用户要求「方便我看」）
- 用户原话：「不要保存成 json 文件，需要保存成 xlsx 文件，方便我看」—— 之前 JSONC 是为 AI 改配置而设计，但用户日常查阅/修改更习惯 Excel。
- 现状：项目内已有 `Services/XlsxProjectStore.cs`（ClosedXML 反射式通用读写，中文 sheet 名对齐菜单：项目管理 / 控制器 / 轴 / IO / 气缸 / 点位表 / 通讯 / 料盘 / 相机 / 变量 / 流程 / 工程师 / 操作员），但**没接线**。本次把它接进 ProjectManager + ProjectStore，废弃 JSON 路径。
- 改造 4 个文件：
  1. **`Services/XlsxProjectStore.cs`**：加 `ConfigureRoot(string)`（让 ProjectManager/ProjectStore 指定自己的 Projects/ 子目录）+ `LoadMeta(name) → (CreatedAt?, UpdatedAt?, Remark?)`（ListProjectEntries 用，只读「项目管理」sheet，避免反序列化整个 ProjectData）。
  2. **`Services/ProjectManager.cs`**：完全重写为 XLSX 路径。`FileFor` 改 .xlsx；WriteFile/OpenProject/NewProject/SetRemark/SetRequirementsText/GetRequirementsText 全部走 `XlsxProjectStore.SaveProject/OpenProject`；ListProjectEntries 用 `XlsxProjectStore.ListProjects` + `LoadMeta；DeleteProject/RenameProject 操作 .xlsx。`静态构造函数调用 ConfigureRoot(RootDir)`。**外部 API 签名 100% 不变**，所有 ViewModel（ProjectManagerViewModel 等）零改动。
  3. **`Services/ProjectStore.cs`**：删 `using System.Text.Json`；FilePath="project.json" 改为走 XlsxProjectStore（统一 root 到 Projects/），Load()/Save() 复用 `DefaultProjectName = "_DefaultProject"` 作为兜底工程名。
  4. **`Services/ProjectJsonAnnotator.cs`**：仍保留（`AiProjectExchange` 仍用 JSON 作为 AI 交换通道，且 `MigrateJsonToXlsx` 一次性迁移也调它的 `Deserialize`）。文件本身不再用于工程存储。
- **JSON → XLSX 一次性迁移**（在 `ProjectStore.Load()` 里）：扫描 Projects/*.json → ProjectJsonAnnotator.Deserialize → XlsxProjectStore.SaveProject → 删 .json。严格「xlsx 落地成功后再删 json」，失败保留原文件。同名 .xlsx 已存在则跳过（不覆盖新格式）。用户现有的工程1.json~工程4.json 自动迁移到 工程1.xlsx~工程4.xlsx，无感升级。
- 验证发现并修复 **2 个真实 bug**（XlsxProjectStore 反射代码遗留）：
  1. **数组类型加载丢失**：`PointTable.AxisNames` 当时以为 `string[]`，实际是 `ObservableCollection<string>`，本来不需要数组分支。但保险起见加了**显式数组分支**（`cp.PropertyType.IsArray` 时用 `Array.CreateInstance`+`SetValue`，不走 Clear/Add）。
  2. **`ConvertTo(string, "")` 返回 null**：原代码 `if (string.IsNullOrEmpty(s)) return null` 让空串变成 null，AxisNames[3] 变成 null（不是空串）。改为字符串类型提前 `return s ?? ""`，避免 UI 绑定触发「值不能为 null」异常。
- 验证：dotnet build 0 错误（24 个预存 warning 全是 FlowRunnerService/OperatorViewModel/VisionEngine 旧问题）。harness 跑通 18 个断言（集合/嵌套/标量/Enum/bool/时间戳/迁移 全部覆盖），含 PointTables 4 轴槽往返（X轴/Y轴/Z轴/空）。样例 xlsx 留在 `D:\wqz\code\_projtrash\sample_project.xlsx`（25477 字节），可双击用 Excel 打开看效果。
