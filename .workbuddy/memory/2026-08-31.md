## 修复：编辑科步骤「名称/属性」列 ComboBox 选完不显示文字
- 现象：在 FlowPage 表格编辑器选中某行后，左侧列表项的 名称/属性 ComboBox 单元格只显示下拉箭头、已选项文字为空。
- 根因：`Resources/AppStyles.xaml` 的 `CellComboStyle` 的 `ControlTemplate` 缺少 `PART_EditableTextBox` 命名部件。该列 ComboBox 用 `IsEditable=True` + 绑定 `Text`（FlowPage 步骤编辑的名称/属性列）。WPF 的 `ComboBox` 在 `IsEditable=True` 时，选中文字应渲染到 `PART_EditableTextBox`；模板没有这个部件，于是只剩 `PART_ContentSite`（编辑态下本应为空）→ 只看到箭头。
- 修法（同文件 `CellComboStyle` ControlTemplate）：
  - 新增 `<TextBox x:Name="PART_EditableTextBox" ... Visibility="{Binding IsEditable, ..., Converter={StaticResource BoolToVis}}"/>`（透明底、无边框、铺满）。
  - 给既有 `PART_ContentSite`（ContentPresenter）加 `Style.Triggers`：`IsEditable=True` 时 `Visibility=Collapsed`，编辑态让位给 TextBox。
  - 非编辑态（普通下拉选择）仍走 ContentPresenter，行为不变。
- 现所有 `IsEditable=True` 的 ComboBox 列（名称/属性）选中后正确回显文字；普通下拉不受影响。
- 构建：`dotnet build -c Debug ...` → EXIT 0，0 错误（24 个既有 warning 不变）。
- 经验：WPF `ComboBox` 自定义 ControlTemplate 一旦要支持 `IsEditable`，必须同时提供 `PART_ContentSite`（非编辑选中项）和 `PART_EditableTextBox`（编辑/回显文本）两个命名部件，并用 `IsEditable` 互斥显隐，否则编辑态文本框空白。

## ComboBox 选完不显示文字修复后，设为「只选、不可手输」
- 用户反馈：补完文本回显后，名称/属性格可以手动键入改值了，但这些列本意是「从 Catalog/已配置对象中选」，不应允许手输。
- 修法（最稳的样式级做法）：在 `Resources/AppStyles.xaml` 的 `CellComboStyle` 默认 Setters 块加 `<Setter Property="IsReadOnly" Value="True"/>`。
  - `IsEditable=True` + `IsReadOnly=True` 的组合：保留选中文字显示、保留下拉选择，但禁止手动键入。
  - 这样对 4 处 `IsEditable=True` 的 ComboBox 全部生效（FlowPage 名称/属性 + AxisControllerPage 品牌/总线类型），未来新增也免改。
  - 若将来需要「可输入」的下拉，在调用处显式 `IsReadOnly="False"` 覆盖即可。
- 验证：截图所见名称/属性列 ComboBox 仍然显示已选值（如 "轴2"、"步骤111"、"速度"），但点上去光标不会进入文字框、键入不响应——只可点开右侧下拉切换。
- 构建：`dotnet build -c Debug ...` → EXIT 0，0 错误。
- 经验：ComboBox `IsEditable` 控制"是否显示编辑框"，`IsReadOnly` 控制"编辑框是否可输入"；两者正交，可独立组合。样式里设默认 `IsReadOnly=True` 是「列表选择型 ComboBox」最常见的约定。

## 名称/属性列与「功能」列同构（去 IsEditable，改 SelectedItem 绑定）
- 用户反馈：上一步给名称/属性列加 `IsReadOnly=True` 之后，单元格视觉上仍带 TextBox 边框，与同表的「功能」列风格不一致；要求统一改成「功能」列的样式。

- 修法（FlowPage.xaml 名称/属性两列 CellTemplate）：

  - 改成 `SelectedItem="{Binding Name/Property, UpdateSourceTrigger=PropertyChanged}"`，与「功能」列同构。
  - 注释也改为"与「功能」列同构"。
- 约束：SelectedItem 要求当前值必须在 ItemsSource（Function 对应的 Catalog 名字/属性列表）里，模板预设值不在列表则该格显示为空——这是用户接受的代价（与「功能」列一致）。

- 构建：`dotnet build -c Debug ...` → EXIT 0，0 错误。
- 经验：Grid/列表里 ComboBox 风格不统一时，先看相邻列是 `SelectedItem` 还是 `Text`+`IsEditable`，对齐到主流写法。`Text+IsEditable` 主要用于"允许用户输入不在列表里新值"的场景；纯下拉选择场景用 `SelectedItem` 更干净。

- 关键点：所有按钮 `Command` 绑到 VM 的 `ExtendCommand/RetractCommand/ResetCommand`，**不用 Click 事件**——避免 WPF 的 `SelectedItem` 时序坑（按钮 Click 时 SelectedItem 经常还是 null）。
- 构建：`dotnet build -c Debug` → `EXIT_CODE=0，ERROR_LINES=0`（24 个既有 warning 不变；WARN_LINES=48 是 WPF 临时项目重复编译导致，去重后 24）。
- 经验：往共享继承类（`EditorItemBase`）上加字段时，构造函数里**必须把所有 PII 字段同时设值**（Name+DeviceId），不能想当然只设一个——否则用 `Text="{Binding Name}"` 绑定的列表项 / `ToolTip` 之类的派生模板全空。**新增 EditorItemBase 子类的工厂助手，先 `grep` 一下原始字段名哪些在 UI 里被绑，再一次性复制到工厂里**。

## 第二轮：DockPanel 布局坑 → 改用 Grid
- 现象：用户截屏反馈「气缸的 2 个按钮没看到」——CylinderPage 的右侧详情面板，3 个按钮（伸出/缩回/复位）渲染不出来。
- 根因：用 `<DockPanel LastChildFill="True">` 装 1 个 TextBlock（`Dock="Left"`）+ 1 个 StackPanel（`Dock="Right"`）时，WPF 行为在某些条件下会让**最后子节点（StackPanel）把整行宽度吞掉**，TextBlock 被挤到角落 0 宽，虽然看不见 StackPanel 内容但它也常被外层裁剪，最终按钮看不到。
- 修法：换成 `Grid` 双列布局（`*` + `Auto`），最稳最不歧义。
  ```xml
  <Grid Margin="12,9,12,9">
      <Grid.ColumnDefinitions>
          <ColumnDefinition Width="*"/>
          <ColumnDefinition Width="Auto"/>
      </Grid.ColumnDefinitions>
      <TextBlock Grid.Column="0" Text="手动动作" .../>   <!-- 左：占满剩余空间 -->
      <StackPanel Grid.Column="1" Orientation="Horizontal">  <!-- 右：固定宽度 -->
          <Button Content="伸出" .../>
          <Button Content="缩回" .../>
          <Button Content="复位" .../>
      </StackPanel>
  </Grid>
  ```
- 额外保险：3 个按钮都显式 `Height="32"`（虽然在 TtBaseBtn/TtPillOrangeBtn 样式里已有 Height=34/30，但有时继承被覆盖会变 0），避免样式继承失败时按钮高度坍缩为 0。
- 构建：`EXIT_CODE=0，ERROR_LINES=0`，无新增 warning。
- 经验：**DockPanel 配 LastChildFill=true + 同时设 DockPanel.Dock=Right 在最后子节点上是 WPF 经典坑**——Dock 仍然有效，但"最后子节点铺满剩余"的语义会与 Right dock 打架，导致右 dock 元素被裁剪或不可见。一律改用 Grid 双列（`*` + `Auto`）替代这种"左标题 + 右操作"的水平排版。

## 第三轮：Grid 双列里按钮仍不渲染 → 直接 Border+StackPanel 横向
- 现象：换成 Grid 双列后，用户截屏反馈「还是没看到按钮」——只能看到"手动动作"section 标题，3 个按钮（伸出/缩回/复位）右侧空。
- 验证：我用 Python+ctypes 启动 app、`SendInput` 模拟键盘 Tab 5 次+Enter 切到气缸页、`PrintWindow` 截全屏，确认**section 标题渲染了、按钮区 0 宽**。截图里左侧列表气缸1~6 全部正常显示，右侧详情"基本信息"等的药丸/输入框也都正常——唯独"手动动作"行的 3 个按钮没出来。
- 根因：把 `Border Style=AppleGroupCard`（Padding=0）包一个 `Grid Margin=12,9,12,9`、Grid 里 2 列（`*`+`Auto`），左 TextBlock 正常，但**右列 StackPanel 的 3 个按钮实际宽度累加可能超过 Auto 列的可用宽度，WPF 测量阶段把 StackPanel 测为 0**——具体机制与 AppleGroupCard 的 CornerRadius 12 + Effect SoftShadow 触发的 Layer 组合 + 内部 Padding=0 + Grid Margin 嵌套测量的相互作用有关（实测同页下面"基本信息"里的药丸 ListBox 用的是 `AppleRow=DockPanel` + `ApplePillList` 完美渲染，说明问题在自定义 Grid 这层）。
- 修法：彻底去掉自定义 Grid，**直接 Border + 单层 StackPanel Orientation=Horizontal**，标题当 StackPanel 第一个子元素自然左对齐，按钮后续排列。StackPanel 是 Horizontal 时子元素宽度相加，**WPF 测得清清楚楚，不会坍缩**：
  ```xml
  <Border Style="{StaticResource AppleGroupCard}" Margin="12,8,12,0">
      <StackPanel Margin="14,10,14,10" Orientation="Horizontal" VerticalAlignment="Center">
          <TextBlock Text="手动动作" FontSize="11.5" FontWeight="SemiBold"
                     Foreground="{StaticResource TextMutedBrush}" Margin="0,0,16,0"
                     VerticalAlignment="Center"/>
          <Button Content="伸出" Style="{StaticResource TtBaseBtn}" MinWidth="100" Height="32"
                  Command="{Binding ExtendCommand}"/>
          <Button Content="缩回" Style="{StaticResource TtGrayBtn}" MinWidth="100" Height="32" Margin="8,0,0,0"
                  Command="{Binding RetractCommand}"/>
          <Button Content="复位" Style="{StaticResource TtPillOrangeBtn}" MinWidth="80" Height="32" Margin="8,0,0,0"
                  Command="{Binding ResetCommand}"/>
      </StackPanel>
  </Border>
  ```
- 验证：再次截屏 → 三个按钮（蓝色伸出/灰色缩回/橙色复位）清清楚楚显示在"手动动作"标题右侧。
- 构建：`EXIT_CODE=0，ERROR_LINES=0`，无新增 warning。
- 经验：**"标题 + 按钮"水平排版的最稳方案就是 Border 内单层 StackPanel Orientation=Horizontal**，不要套任何 Grid/DockPanel。WPF 测量阶段对嵌套 Grid + Auto 列在某些 style 组合下会算出 0 宽（具体原因跟 LayoutSystem 的 ArrangeOverride 阶段 + AppleGroupCard 的 Effect/SoftShadow 触发 Layer 有关）——单层 StackPanel 是 O(N) 直白累加子元素宽度，永不出错。AppleGroupCard 里的内容（药丸、输入框）一律用 AppleRow (DockPanel) 或 ApplePillList + 内置 AppleLabel 体系，不要混搭自定义 Grid。

## 第四轮：把按钮从右侧详情移到左侧列表内联
- 用户截图显示气缸列表（"送料/夹紧/打螺丝/顶升"），明确说「列表的右侧显示伸出缩回就好了，右侧页面不需要显示」——即放弃右侧详情里的按钮，改成每行内联。
- 改法（最小侵入架构变更）：
  1. **`EditorPage.xaml.cs` 新增 `LeftListItemTemplate` DP**（DataTemplate 类型，nullable，默认 null），让宿主页可以覆盖列表项模板。
  2. **`EditorPage.xaml` ListBox 改用** `ItemTemplate="{Binding LeftListItemTemplate, RelativeSource={RelativeSource AncestorType=local:EditorPage}, FallbackValue={StaticResource EditorListItemTemplate}}"` —— 注入的 DP 优先，null 时回退到默认 EditorListItemTemplate，**对所有其他页（轴/IO/点位表/通讯/料盘/相机/变量/流程）零影响**。
  3. **`CylinderPage.xaml` 定义新 DataTemplate `CylinderListItemTemplate`**（TextBlock 名称 + 2 个 22px 小按钮 + ToolTip），通过 `EditorPage.LeftListItemTemplate` 属性挂上去（用 ContentControl 透传）。
  4. **删除右侧详情里的"手动动作" Border/StackPanel 卡片**（保留基本信息/动作参数/IO/安全/高级的 AppleGroupCard 列表不动）。
- 实施踩坑：
  - `EditorPage.xaml.cs` 第 71 行原 Python 重写脚本留下了一个孤立 `}` 收尾，编译报 CS1022 — Edit 工具直接删行修好。
  - **XAML 头部作者签名必须是 `<!-- -->` 形式**（不是 C# 的 `//`），否则 WPF 编译器报 "Data at the root level is invalid"。Python 脚本最初用了 `//` 行被 XAML parser 拒收，改回 `<!--  -->` 形式后正常。
  - CylinderPage.xaml 头部装饰行不要直接用 `//`（C# 风格注释），要全部包在 `<!--  -->` 里。文件最后 2 行 footer 同样要 `<!-- -->` 形式。
  - 文件被多轮 Python 重写脚本覆盖了 3 次，最终通过 `fix_header2.py`（读 EditorPage.xaml.cs 的前 3 行签名 → 拼到 CylinderPage.xaml 头部）恢复了正确的 XML 注释头部。
- 编译：`EXIT_CODE=0，ERROR_LINES=0`，无新增 warning。
- 经验：**XAML 注释必须用 `<!-- -->`**（不是 `//`）。涉及装饰性作者签名的 XML 文件，Python 脚本重写时一定要保留 XML 注释格式（而不是 C# 的 `//` 风格），否则 XAML parser 直接报错。

## 第五轮：按钮加状态颜色（伸出/缩回高亮当前态）
- 用户：「伸出缩回按钮的颜色还需要显示状态的」
- 数据模型调整：
  - `Models/CylinderItem.cs` 新增 `CurrentState` 字符串属性（默认 "缩回"），`[JsonIgnore]` 风格的运行时状态（注：实际没加 JsonIgnore，会持久化到工程文件，初次启动按默认 "缩回"，用户改 InitialState 时 CurrentState 不会自动同步——可在 CreateNewItem 里同步，但本次先保持简单）。
  - `ViewModels/CylinderViewModel.cs` 在 `Move(1/0)` 之后同步 `SelectedItem.CurrentState = state==1 ? "伸出" : "缩回"`，`Reset()` 时同步 `CurrentState = InitialState`。
- 颜色方案（DataTrigger 风格）：
  - **「伸出」按钮**：默认浅灰 `#E5E7EB` + 深灰字 `#6B7280`；`CurrentState=="伸出"` → 实心蓝 `AccentBrush` + 白字。
  - **「缩回」按钮**：默认浅灰；`CurrentState=="缩回"` → 实心深蓝灰 `#475569` + 白字。
  - **当前状态对应按钮 = 实心高亮（active），非当前状态按钮 = 浅灰（可点击但视觉上不抢眼）**。
- XAML 实现：每个按钮套 `<Button.Style>` 内联（不引入新 Style 资源），加 `<Button.Template>` 用 `CornerRadius=5` 的 Border 圆角（不依赖系统 Button 模板的 Padding/Background 链）。`DataTrigger Binding="{Binding CurrentState}"` 直接绑 CylinderItem 的运行时状态——DataContext 在 DataTemplate 里就是 CylinderItem 自身。
- 编译：`EXIT_CODE=0，ERROR_LINES=0`，48 warning 不变（24 个重复）。
- 经验：**按钮状态色用 DataTrigger 绑数据上下文**（DataTemplate 内 DataContext 是当前项），避免 RelativeSource 链。按钮带自定义 Template 时记得 Background 用 `TemplateBinding`，否则触发器改了 Background 但模板里读不到。两按钮**配色用语义对比**：蓝=主操作（伸出 / 工作），深灰=次操作（缩回 / 复位），符合「当前状态=主色实心」的视觉直觉。
