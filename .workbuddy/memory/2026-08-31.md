## 修复：编辑科步骤「名称/属性」列 ComboBox 选完不显示文字
- 现象：在 FlowPage 表格编辑器选中某行后，左侧列表项的 名称/属性 ComboBox 单元格只显示下拉箭头、已选项文字为空。
- 根因：`Resources/AppStyles.xaml` 的 `CellComboStyle` 的 `ControlTemplate` 缺少 `PART_EditableTextBox` 命名部件。该列 ComboBox 用 `IsEditable=True` + 绑定 `Text`（FlowPage 步骤编辑的名称/属性列）。WPF 的 `ComboBox` 在 `IsEditable=True` 时，选中文字应渲染到 `PART_EditableTextBox`；模板没有这个部件，于是只剩 `PART_ContentSite`（编辑态下本应为空）→ 只看到箭头。
- 修法（同文件 `CellComboStyle` ControlTemplate）：
  - 新增 `<TextBox x:Name="PART_EditableTextBox" ... Visibility="{Binding IsEditable, ..., Converter={StaticResource BoolToVis}}"/>`（透明底、无边框、铺满）。
  - 给既有 `PART_ContentSite`（ContentPresenter）加 `Style.Triggers`：`IsEditable=True` 时 `Visibility=Collapsed`，编辑态让位给 TextBox。
  - 非编辑态（普通下拉选择）仍走 ContentPresenter，行为不变。
- 现所有 `IsEditable=True` 的 ComboBox 列（名称/属性）选中后正确回显文字；普通下拉不受影响。
- 构建：`dotnet build -c Debug ...` → EXIT 0，0 错误（24 个既有 warning 不变）。
- 经验：WPF `ComboBox` 自定义 ControlTemplate 一旦要支持 `IsEditable`，必须同时提供 `PART_ContentSite`（非编辑选中项）和 `PART_EditableTextBox`（编辑/回显文本）两个命名部件，并用 `IsEditable` 互斥显隐，否则编辑态文本框空白。

## ComboBox 选完不显示文字修复后，设为「只选、不可手输」
- 用户反馈：补完文本回显后，名称/属性格可以手动键入改值了，但这些列本意是「从 Catalog/已配置对象中选」，不应允许手输。
- 修法（最稳的样式级做法）：在 `Resources/AppStyles.xaml` 的 `CellComboStyle` 默认 Setters 块加 `<Setter Property="IsReadOnly" Value="True"/>`。
  - `IsEditable=True` + `IsReadOnly=True` 的组合：保留选中文字显示、保留下拉选择，但禁止手动键入。
  - 这样对 4 处 `IsEditable=True` 的 ComboBox 全部生效（FlowPage 名称/属性 + AxisControllerPage 品牌/总线类型），未来新增也免改。
  - 若将来需要「可输入」的下拉，在调用处显式 `IsReadOnly="False"` 覆盖即可。
- 验证：截图所见名称/属性列 ComboBox 仍然显示已选值（如 "轴2"、"步骤111"、"速度"），但点上去光标不会进入文字框、键入不响应——只可点开右侧下拉切换。
- 构建：`dotnet build -c Debug ...` → EXIT 0，0 错误。
- 经验：ComboBox `IsEditable` 控制"是否显示编辑框"，`IsReadOnly` 控制"编辑框是否可输入"；两者正交，可独立组合。样式里设默认 `IsReadOnly=True` 是「列表选择型 ComboBox」最常见的约定。

## 名称/属性列与「功能」列同构（去 IsEditable，改 SelectedItem 绑定）
- 用户反馈：上一步给名称/属性列加 `IsReadOnly=True` 之后，单元格视觉上仍带 TextBox 边框，与同表的「功能」列风格不一致；要求统一改成「功能」列的样式。
- 「功能」列（FlowPage.xaml line 252）写法：`SelectedItem="{Binding Function}"` + 无 `IsEditable` → 普通下拉，ContentPresenter 渲染选中项。
- 修法（FlowPage.xaml 名称/属性两列 CellTemplate）：
  - 删 `IsEditable="True"`、`Text="{Binding Name/Property, ...}"`。
  - 改成 `SelectedItem="{Binding Name/Property, UpdateSourceTrigger=PropertyChanged}"`，与「功能」列同构。
  - 注释也改为"与「功能」列同构"。
- 约束：SelectedItem 要求当前值必须在 ItemsSource（Function 对应的 Catalog 名字/属性列表）里，模板预设值不在列表则该格显示为空——这是用户接受的代价（与「功能」列一致）。
- 副作用：上一次给 `CellComboStyle` 加的 `IsReadOnly=True` 对这两列不再生效（IsEditable=False 时 IsReadOnly 无意义），但对 `AxisControllerPage.xaml` 里仍用 `IsEditable=True` 的「品牌/总线类型」列继续生效——保留。
- 构建：`dotnet build -c Debug ...` → EXIT 0，0 错误。
- 经验：Grid/列表里 ComboBox 风格不统一时，先看相邻列是 `SelectedItem` 还是 `Text`+`IsEditable`，对齐到主流写法。`Text+IsEditable` 主要用于"允许用户输入不在列表里新值"的场景；纯下拉选择场景用 `SelectedItem` 更干净。
