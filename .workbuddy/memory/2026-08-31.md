## 列表项右侧显示流程运行状态
- `Models/FlowItem.cs` 新增 `FlowStatus` 枚举（Idle / Running / Paused / Breakpoint / Exception / Stopped）+ `Status` 属性（INPC）。
- `ViewModels/FlowRunnerService.cs` 在每个流程 RunOneFlow 生命周期内维护状态：
  - Table 流程：Run 入口 `SetStatus(Running)`；OperationCanceledException → Stopped；Exception → Exception；正常完成 → Idle。
  - Lua 流程：同上 + finally 收尾（被停 → Stopped，否则 Idle），并把现有 `PauseRequested/Resume` 翻为 `SetStatus(Paused)↔Running`。
  - FlowExecutor.AbortCheck 监听暂停边沿：用 `_pauseActive` 标志，`UiSet` 写 `Status`（跨类，FlowExecutor 内的 private static `UiSet` 可见，而 `FlowRunnerService` 内的 `SetStatus` 不可见——所以两个类各自实现线程封送）。
  - 新增 `SetStatus(flow, st)` 静态助手（inline Application.Current.Dispatcher.Invoke，因为 FlowExecutor.UiSet 是 private、跨类不可见）。
- `Views/EditorPage.xaml` `EditorListItemTemplate` 增加右列状态芯片：
  - 新样式 `FlowStatusChipStyle`（默认隐藏 + 灰），5 个 DataTrigger 按 Status 切色（运=绿 `#10B981` / 暂=橙 `#F59E0B` / 断=红 `#EF4444` / 异=深红 `#DC2626` / 停=灰 `#6B7280`）+ Visible。
  - 第 3 列 Border 套 TextBlock，Text 用新转换器 `FlowStatusLabel`（FlowStatus → "运行"/"暂停"/"断点"/"异常"/"停止"）。
- `Resources/AppStyles.xaml` 注册转换器：`views:FlowStatusLabelConverter x:Key="FlowStatusLabel"`。
- `Views/FlowStatusLabelConverter.cs` 新文件（IValueConverter，参考 OccupiedTextConverter.cs 模板）。
- 构建：`dotnet build` → EXIT 0，0 错误。
- 编辑器 Lua 流程的 Breakpoint 状态暂未主动设置（仅作为枚举占位 + UI 颜色分支）；需要 LuaDebugSession 暴露"停在断点"事件时再行接线。
- 注意：工程/相机/轴等非 FlowItem 类型没有 `Status` 属性，绑定为 null→DataTrigger 不命中→chips 默认 Collapsed，不爆错。
- 经验：`FlowRunnerService` 与 `FlowExecutor` 是不同的类；`SetStatus`（在 FlowRunnerService）无法访问 `UiSet`（在 FlowExecutor 的 private static）。把跨线程封送复制为最小 inline 是最直接的做法，避免提升 UiSet 可见性带来的扩散修改。

## Idle 状态芯片改为始终可见
- 用户反馈：截图显示只有 Lua 流程出现「停止」芯片，Table/Vision 流程完全没有芯片——因为 Table/Vision 是已运行结束或从未运行 → Status=Idle，但 `FlowStatusChipStyle` 默认 `Visibility=Collapsed` + 转换器 Idle→空串，于是空白。
- 修法：
  - `FlowStatusLabelConverter.cs`：Idle → "就绪"（不再返回空串）。
  - `FlowStatusChipStyle`：默认 `Visibility=Visible` + 浅灰 `#CBD5E1`（Idle 配色），运行/暂停/断/异/停的 DataTrigger 仅切色不切可见性。
- 现在每条流程右侧始终有 1 颗芯片（含 Table/Vision）：Idle=浅灰「就绪」/ Running=绿「运行」/ Paused=橙「暂停」/ Breakpoint=红「断点」/ Exception=深红「异常」/ Stopped=深灰「停止」。Idle 与 Stopped 用不同灰度区分"未跑"vs"被停"。
- 构建：`dotnet build` → EXIT 0，0 错误。
