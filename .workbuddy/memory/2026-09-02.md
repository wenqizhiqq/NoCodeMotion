## XAML 根 Grid 插入 RowDefinition 的坑（本次踩到）
- 用脚本给根 Grid 插 `RowDefinition` 时，必须插在 `</Grid.RowDefinitions>` **之前**（块内）。若把 1-based 行号当 0-based 索引用，会插到块外（位于 `</Grid.RowDefinitions>` 与 `<Grid.ColumnDefinitions>`/内容之间），触发 **MC3088：属性元素不能位于元素内容的中间，必须位于内容之前或之后**。
- LuaEditorView 因 `</Grid.RowDefinitions>` 后紧跟 `<Grid.ColumnDefinitions>` 最先报错；其余页虽同样错但 XAML 解析顺序未先报。统一用脚本把 stray 行移回块内后构建通过。
- **通用安全做法**：改动 XAML 根 Grid 布局（加行/列、插 footer）优先用 Python 读写并保留 BOM/CRLF；插入位置一律用 `</Grid.RowDefinitions>` 前一行，插完立即用 PowerShell `dotnet.exe build` 验证（只报 `error CS` 会漏掉 XAML 错，需 grep 全文 `error` 不含 `error CS`）。

## EngineerPage 底部提示栏错位修复（用户截图反馈「工程师页面不对」）
- 现象：提示栏跑到页面顶部、其余内容空白。根因：EngineerPage 根 `<Grid Margin="16">` **只定义了 ColumnDefinitions（无 RowDefinitions）**，脚本前向搜索 `</Grid.RowDefinitions>` 时误匹配了左列嵌套 Grid 的块，把 `Auto` 行插进了嵌套 Grid（根 Grid 始终没有 RowDefinitions），而 `PageHintBar` 按 `Grid.Row="2"` 插入根级 → 行索引非法 → 布局塌缩。
- 修复三步：① 删掉嵌套左列 Grid 里误插的 `<RowDefinition Height="Auto"/>`（恢复成两行 `*`）；② 在根 Grid 的 ColumnDefinitions 后补 `<Grid.RowDefinitions><RowDefinition Height="*"/><RowDefinition Height="Auto"/></Grid.RowDefinitions>`；③ 把 `PageHintBar` 的 `Grid.Row="2"` 改为 `Grid.Row="1"`（根 Grid 现 2 行：内容 0 / footer 1）。
- 教训：脚本插 RowDefinition 时不能用「前向找第一个 `</Grid.RowDefinitions>`」——若根 Grid 无 RowDefinitions，会命中嵌套 Grid。应优先针对「根 Grid 自身」判断：根 Grid 缺 RowDefinitions 时直接在其 ColumnDefinitions 后插入，且 footer 的 Grid.Row 取 `行数-1`（此处为 1）。
- 重建：`PowerShell dotnet.exe build -c Debug` 通过，0 错误 0 警告（DLL 已生成），无 XAML(MC)/C#(CS) 错误。
