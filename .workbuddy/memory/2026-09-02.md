## 错误详情弹窗过大 + IndexOutOfRange 根因
- **错误弹窗太大、空白多**：`Views/ExceptionDetailDialog.xaml` 的 `<Window>` 缺 `SizeToContent`，默认按窗口 natural size 显示（~960×680），即便内容只有一行也撑满。修复：Window 加 `SizeToContent="WidthAndHeight"`，自动收缩到 StackPanel 的 MinWidth/MaxWidth + TextBox MaxHeight+ 按钮区。`AllowsTransparency=True` + 透明背景让"未填充区域"看起来全是空白。
- **IndexOutOfRange 根因**：`Models/TrayItem.cs` 的 `Rows`/`Cols` setter 用 `SetField(ref, value)` → `SetField` 内部立即 `OnPropertyChanged(propertyName)` → `TrayPage.OnItemChanged` 立刻触发 `RenderTray()`，但此时 `_rows/_cols` 已更新、`Cells` 还是旧的 → RenderTray 用新 Rows/Cols 索引旧 Cells（Count=旧 Rows*Cols），如 5×5→10×5 时 `Cells[r*5+c]` 在 r=5 即越界。
- **修复**：Rows/Cols setter 改成「先赋值 → 调 RegenerateCells() 重建 Cells → 再 OnPropertyChanged()」，保证 RenderTray 看到的 Rows/Cols/Cells 三者始终一致。Cells 集合在 RegenerateCells 内部重建时会再触发一次 OnPropertyChanged(nameof(Cells))，RenderTray 重绘时 Cells.Count 已正确，多画一次帧但不出错。

## ⚠️ 构建坑：后台 `dotnet build` 残留进程导致 wpftmp 重复定义 (CS5001/CS0579/CS0102/CS0111 连环)
- **现象**：首次干净 `obj/bin` 编译通过；之后每次 `Remove-Item obj,bin` 再编都报 `wpftmp.csproj` 的 `error CS5001: 不包含 Main` 或大量 `CS0579 特性重复 / CS0102 类型已包含 / CS0111 已定义`——`obj\Debug\net10.0-windows\` 里堆积了 10+ 个 `NoCodeMotion_<rand>_wpftmp.AssemblyInfo.cs` 与各页 `.g.i.cs`。
- **根因**：某次 `run_in_background` 的 `dotnet build` 进程**未真正退出**（疑似 EDR 中途阻断写文件留下僵尸），持续重写 `obj` 的生成文件；`Remove-Item`/`[IO.Directory]::Delete` 删完 `obj` 后该进程**立即重建**它（Test-Path 又变 True）。新构建的 wpftmp 把「新建的 g.cs」与「僵尸进程写的旧 obj g.i.cs」一起编译 → 重复定义瀑布。
- **解决**：`Stop-Process -Name dotnet -Force; Stop-Process -Name VBCSCompiler -Force`（**不要带 `msbuild` 字样**，会被沙箱 LOLBin 拦截）；等待 2~3s 后 `obj` 才真正消失且不再重建；再干净编译即通过。
- **判定流程**：若 `wpftmp` 报 CS5001/大量 CS0579，先 `Stop-Process` 杀 dotnet/VBCSCompiler，确认 `obj` 删除后不再重现，再重建。单进程(`-m:1`)、`--disable-build-servers`、重定向 `BaseIntermediateOutputPath` 到 TEMP **都不能**解决——根因是僵尸进程而非并行/路径。
- **注意**：`Get-Process` / `cmd /c rmdir` / 含 `msbuild`/`csc` 的 PowerShell 命令会被沙箱以 LOLBin 拦截，改用 `Stop-Process -Name dotnet` 与 `[System.IO.Directory]::Delete` 即可。

## 操作员页 3D 仿真改由真实 .obj 模型装配（用户确认：嵌入 .obj + 自写 loader）
- **方案选定**：`AskUserQuestion` 用户选「嵌入 .obj + 自写 loader（推荐）」——不引第三方 3D 库（无 HelixToolkit），自写轻量 `ObjLoader`。
- **模型来源**：GitHub `luokizz/DIY-CNC-machine`（Ivan Miranda 免费 CNC，Autodesk ATF 生成 .obj）。经 `api.github.com/.../git/trees/main?recursive=1` 枚举出 39 个 obj 零件，下载 14 个拼成完整龙门 CNC：`side_plates/left|right/LEFT|RIGHT_PLATE`（侧板/龙门）、`router/CARRIAGE`（滑座）、`router/ROUTER_BRACKET`、`router/VERTICAL_SLIDER`、`router/Z_MOTOR_MOUNT`、`router/VACUUM_FUNNEL`、`router/VACUUM_HOSE_RING`、`router/CABLE_CHAIN_MOUNT`、`other/X|Y_AXIS_ENDSTOP_LIMIT_SWITCH_*`（限位）、`other/RAILS_SUPPORT`、`other/IDLER_BLOCK`、`electronic_box_small/front_panel_*`（控制柜）。落盘于 `Models/<子目录>/*.obj`，总 ~5.3MB。
- **新增 `Views/ObjLoader.cs`**：纯 C# 解析 WaveFront `.obj`——读 `v`/`f`（`f` 支持 `v`/`v/vt`/`v/vt/vn`/负相对索引，多边形扇形三角化），无 `vn` 时按面算法线（平面着色）。返回 `MeshGeometry3D`（**保留原始坐标、不做单模型归一化**，以便多零件在共享 CAD 坐标系下正确装配），`Freeze()` 冻结。
- **`Sim3DView.xaml.cs` 重写装配逻辑**：
  - `BuildMachine()` 依次 `ObjLoader.LoadFile` 加载各零件到 `ModelVisual3D`：静态结构件（侧板/控制柜/限位/导轨支撑/惰轮/拖链座）直接挂 `_machineGroup`；滑座组（CARRIAGE+ROUTER_BRACKET+Z_MOTOR_MOUNT）挂 `_carriageGroup`；主轴/刀具组（VERTICAL_SLIDER+VACUUM_*）挂 `_routerGroup`（嵌套于 `_carriageGroup`）。
  - 计算全部零件 `mesh.Bounds` 的合并 `Rect3D` → 单一全局变换 `Translate(-center) → Scale(150/maxDim) → [若 Z 跨度>Y 跨度*1.15 则 RotateX(-90°) 把 CAD Z-up 校正为 WPF Y-up]` 施加到 `_machineGroup`（即整体归一化、居中、方向修正，多零件因此自动正确装配）。
  - **三轴联动保真**：`UpdatePose()` 由归一化头坐标算世界位移 `(wx,wz,wy)`（X/Z 滑座、Y 刀具），再按 `_zUp` 反算成**原生 CAD 坐标**平移量（除以 `_globalScale`，Z-up 时 `native=(wx,-wz,wy)` 否则 `(wx,wy,wz)`）施加到 `_carriageGroup`/`_routerGroup`——因为全局变换含旋转/缩放，必须在原生坐标空间施加平移才能保持方向正确。红色当前位置头 `_headModel` 仍落于 `ToMachine(head)` 场景坐标。
