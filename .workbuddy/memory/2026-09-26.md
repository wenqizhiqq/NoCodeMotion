## Lua 语法高亮颜色一直不生效（已修，两个 bug 叠加）
- 症状：Lua 编辑器里注释/字符串/数字/关键字/注册函数全黑。
- **根因 1（磁盘加密）**：本工程所有源文件在磁盘上都带加密包装（前 3 字节 `88 7D 1C`，含 `.cs`/`.xaml`/`.csproj`/**`.xshd`**）。
  MSBuild 编译时会解密 `.cs`，但 `XmlReader.Create(文件/嵌入资源)` 拿到的是密文 → `HighlightingDefinitionInvalidException: Invalid character in the given encoding. Line 1, position 1.`
- **根因 2（XML 注释非法）**：xshd 里写了 `<!-- 单行注释 -- -->`，XML 规范禁止注释内含 `--` → 即便明文也解析失败：`An XML comment cannot contain '--'`。
- 修复：
  - `Views/LuaEditorView.xaml.cs`：把整份 xshd **内联为 C# 原始字符串常量 `LuaXshdXml`**（C# 11 `"""..."""`），用 `XmlReader.Create(new StringReader(LuaXshdXml))` 加载。`.cs` 编译时必解密 → 内联字符串必然是明文，彻底绕开根因 1。嵌入资源/文件降级为兜底。
  - `Assets/Lua.xshd` + 内联副本：`<!-- 单行注释 -- -->` → `<!-- 单行注释：从两个减号开始直到行尾 -->`。
  - `Editing/LuaSemanticColorizer.cs`：新增 `XshdCovered`（= `LuaApi.HardwareList` 名字 ∪ `LuaApi.ModuleNames`，即注册函数 + 标准库表名），语义着色器跳过这些名字；并**删掉**原来「控制流关键字刷橙色加粗」和「标准库刷青绿」两段——它们会覆盖 xshd 的紫色/棕色，导致颜色对不上。现在语义着色器只负责 xshd 认不出的用户自定义变量/函数。
- 验证方式（关键，可复用）：建独立控制台 harness `C:\tmp\xshdtest\`（net10.0-windows + `UseWPF` + 直接 `Reference` 输出目录的 `ICSharpCode.AvalonEdit.dll`，`EnableDefaultCompileItems=false`），
  用 `DocumentHighlighter.HighlightLine(ln)` 打印每段 `Color.Name/Foreground` 与文本，即可在无 UI 的情况下确认着色是否正确。
  实测内联 xshd：7 色全部命中 —— `WaitAxisDone`=Function/#795E26、`"轴11"`=String/#A31515、`-- 等待…`=Comment/#6A9955、`100`=Number/#098658、`local/if/then/end`=Keyword/#AF00DB、`Log`=StdLib/#1F7A8C、括号=Operator/#5A6C7D。
- 构建：全新 `IntermediateOutputPath`+`OutDir` + `--no-restore`，0 错误。
- 教训：本工程**不要**把 xshd/json/ini 等需要运行时用 XmlReader/JSON 直读的外部文件放在工程目录里当资源——它们会被加密，运行时读不了。这类数据一律内联进 `.cs`。
