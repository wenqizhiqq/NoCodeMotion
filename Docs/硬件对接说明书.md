# 硬件对接说明书（Lua 运动控制函数 → 真实设备）

本说明讲清楚：Lua 脚本里写的那一堆硬件控制函数（`AxisMove`、`SetIO`、`CylinderMove`…）
是怎么走到真实硬件的，以及你要做哪些事才能把设备接上。

---

## 1. 调用链总览

```
Lua 脚本（用户编写）
   │  AxisMove("轴1")
   ▼
HardwareApi（Lua 绑定层，Services/HardwareApi.cs）
   │  按名称从 ProjectStore.Data 解析出配置对象 AxisItem
   ▼
IHardwareBridge（对接接口，Services/IHardwareBridge.cs）★ 你只改这里
   │  把动作下发到真实设备
   ▼
真实硬件：运动控制卡 / IO 卡 / PLC / 串口 / 网口 / 视觉 …
```

- **Lua 绑定层 `HardwareApi`**：只负责"把名称解析成配置对象 + 注册成 Lua 全局函数"，不碰任何设备。已写好，无需改。
- **对接接口 `IHardwareBridge`**：唯一需要你实现的地方。每个方法接收一个**配置对象**（里面有卡号、模块、通道、端口等硬件地址）和运行时参数。
- **默认桩 `StubHardwareBridge`**：没接真实硬件时自动生效，只打日志、返回安全默认值，让脚本先完整跑通。

> 一句话：**框架已经把"接口预留"好了，你只要实现 `IHardwareBridge` 并挂上去，Lua 就能驱动真实硬件。**

## 2. 当前已预留的函数清单

这些函数已在 `HardwareApi.Register` 中注册成 Lua 全局函数，名称与"智能工具"面板插入的模板一一对应。
找不到对应名称的配置对象时，会抛运行时错误并在 Lua 输出面板给出中文提示（如 `找不到轴：轴1`）。

### 轴（Axis）
| Lua 函数 | 说明 | 对接方法（收到 AxisItem） |
|---|---|---|
| `AxisMove(name)` | 按轴配置的目标位置运动 | `MoveAxis(AxisItem)` |
| `SetAxisSpeed(name, speed)` | 设置运行速度 | `SetAxisSpeed(AxisItem, double)` |
| `AxisHome(name)` | 回零 | `HomeAxis(AxisItem)` |
| `StopAxis(name)` | 急停 | `StopAxis(AxisItem)` |
| `WaitAxisDone(name)` | 阻塞等待到位（误差 `InPosError`） | `WaitAxisDone(AxisItem)` |
| `EnableAxis(name)` | 使能 | `EnableAxis(AxisItem)` |
| `MoveAxisRel(name, distance)` | 相对移动 distance | `MoveAxisRel(AxisItem, double)` |
| `MoveAxisAbs(name, position)` | 绝对移动到 position | `MoveAxisAbs(AxisItem, double)` |

### 输入 / 输出 IO
| Lua 函数 | 说明 | 对接方法（收到 IoItem） |
|---|---|---|
| `ReadIO(name)` → 返回 0/1 | 读输入 | `ReadInput(IoItem) → double` |
| `WaitIO(name, value)` | 等待输入变为 value | `WaitInput(IoItem, int)` |
| `SetIO(name, value)` | 写输出 value | `WriteOutput(IoItem, int)` |
| `ToggleIO(name)` | 输出取反 | `ToggleOutput(IoItem)` |

> IO 方向约定：读取/等待用**输入 IO**（`ProjectStore.Data.Inputs`），设置/取反用**输出 IO**（`Outputs`）。

### 气缸（Cylinder）
| Lua 函数 | 说明 | 对接方法（收到 CylinderItem） |
|---|---|---|
| `CylinderMove(name, state)` | 动作：state=1 伸出 / 0 缩回 | `CylinderMove(CylinderItem, int)` |
| `WaitCylinder(name)` | 等待到位（按感应点轮询） | `WaitCylinder(CylinderItem)` |
| `CylinderReset(name)` | 复位到初始状态 | `CylinderReset(CylinderItem)` |

### 通讯（Comm）
| Lua 函数 | 说明 | 对接方法（收到 CommItem） |
|---|---|---|
| `CommSend(name, data)` | 发送数据 | `CommSend(CommItem, string)` |
| `CommRecv(name)` → 返回字符串 | 接收数据 | `CommRecv(CommItem) → string` |

### 料盘（Tray）
| Lua 函数 | 说明 | 对接方法（收到 TrayItem） |
|---|---|---|
| `TrayPick(name)` | 取料（按布局换算坐标） | `TrayPick(TrayItem)` |
| `TrayPlace(name)` | 放料 | `TrayPlace(TrayItem)` |

## 3. 配置对象里有哪些"硬件地址"（对接时直接用）

Lua 只传名称，但 `HardwareApi` 已经帮你把名称解析成了项目里配置好的对象。对接实现里
**直接读这些字段下发硬件指令**即可，不用自己再做名称查找。

- **AxisItem**：`AxisNo`（轴号）、`AxisType`、`Unit`、`Speed`、`PulsePerUnit`、`HomeMode`/`HomeSpeed`、`PosLimitPlus/Minus`、`InPosError`、`EnableLevel`/`DirLevel`/`AlarmLevel` 等。
- **IoItem**：`CardType`（卡类）、`CardNo`（卡号）、`ModuleNo`（模块）、`Sequence`（通道/序号）、`Level`（电平）、`SuitCode`（套码）。
- **CylinderItem**：`DeviceId`、`OutPoint`（输出点名）、`SensorExtend`/`SensorRetract`（伸/缩到位感应名）、`SensorType`、`TimeoutMs`、`DelayMs` 等。
- **CommItem**：`CommType`（串口/网口…）、`PortOrIp`、`BaudOrPort`、`DataBits`、`Parity`、`StopBits`、`TimeoutMs`。
- **TrayItem**：`StartX`/`StartY`、`PitchX`/`PitchY` 等布局参数，用于把"第几行几列"换算成坐标。

> 提示：`CylinderItem` 的 `OutPoint`/`SensorExtend`/`SensorRetract` 存的是 **IO 名称**，
> 真实对接时可在 `ProjectStore.Data.Inputs/Outputs` 里再反查一次拿到对应的卡号/通道。

## 4. 如何接入真实硬件（三步）

### 第 1 步：新建一个类，实现 `IHardwareBridge`

```csharp
using NoCodeMotion.Models;
using NoCodeMotion.Services;

public class MyMotionCardBridge : IHardwareBridge
{
    public void Log(string message) => Console.WriteLine("[硬件] " + message);

    public void MoveAxis(AxisItem axis)
    {
        // 用 axis.AxisNo 作为运动控制卡通道号，调用你自己的驱动
        MyCard.MoveTo(axis.AxisNo, /* 目标位置 */ 0);
    }

    public void WriteOutput(IoItem io, int value)
    {
        // 用卡号/模块/通道下发：io.CardNo, io.ModuleNo, io.Sequence
        MyIoCard.Set(io.CardNo, io.ModuleNo, io.Sequence, value);
    }

    // ……其余方法照此实现，参考 StubHardwareBridge 日志里给出的字段
}
```

### 第 2 步：在程序启动时挂载实现

```csharp
// App 启动处（或设备初始化处）
HardwareBridge.Current = new MyMotionCardBridge();
```

之后所有 Lua 脚本里的硬件函数都会走你的实现。**不挂也行**——默认 `StubHardwareBridge`
会打印将要执行的动作，方便先调试脚本逻辑。

### 第 3 步：处理阻塞等待与超时

`WaitAxisDone` / `WaitIO` / `WaitCylinder` 是**阻塞调用**（Lua 在后台线程执行，不会卡 UI）。
对接实现里应**轮询设备状态直到条件满足或超时报错**，例如：

```csharp
public void WaitAxisDone(AxisItem axis)
{
    var sw = System.Diagnostics.Stopwatch.StartNew();
    while (!MyCard.IsInPosition(axis.AxisNo))
    {
        if (sw.ElapsedMilliseconds > 超时毫秒)   // 参考 axis 配置或固定 5000
            throw new System.TimeoutException($"轴 {axis.Name} 等待到位超时");
        System.Threading.Thread.Sleep(10);
    }
}
```

## 5. 默认桩的行为（无硬件时）

`StubHardwareBridge` 把所有动作打到调试输出（Visual Studio 输出窗口 / `Debug.WriteLine`），
并打印解析到的硬件地址，例如：

```
[桩] 轴运动 → 名称=轴1 轴号=1 单位=mm 速度=100
[桩] 写输出 → 名称=输出1 卡类=… 卡号=0 模块=0 序号=1 值=1
[桩] 通讯发送 → 名称=相机 类型=TCP 地址=192.168.1.10 波特/端口=8000 数据=Trigger
```

`ReadIO` 返回 `IoItem.Value`（无硬件时为 0），`CommRecv` 返回空串。这样脚本可在无设备时完整跑通流程。

## 6. 常见问题

- **运行时报 `找不到轴：xxx`**：说明 Lua 里写的名称在项目"轴"列表里不存在。去项目配置里核对 `Name`，或改 Lua 里的字符串。
- **函数未定义 / `attempt to call a nil value`**：说明硬件函数没注册上。确认 `LuaDebugSession.Execute` 里调用了 `HardwareApi.Register`（默认已接）。
- **想让某类设备临时走桩、另一类走真机**：`IHardwareBridge` 里对每个方法自行决定是调真机还是打日志即可，无需拆接口。
- **新增一种硬件函数**：在 `HardwareApi` 加方法 + `Register` 里注册 + `LuaApi.HardwareList` 加提示 + `IHardwareBridge` 加接口方法（桩也补一个空实现）。
