# 轴 Jog 报 8194 / 速度不生效 —— 现场处置说明

> 适用：研控 MCN420 真机（`Mcn420ErrorCode.xml` 里 **8194 = 普通缓冲满出错**）。
> 本文档对应 2026-09-30 15:33 的 Debug 构建。
> 模拟卡**不会**报 8194（它的错误码表里没有这个码），所以看到 8194 就是**真机**。

---

## 一、8194 的真因：`Channel` 通道号写错了（已修）

**不是「缓冲被占」，而是「通道号非法」。**

研控每条运动指令都要带一个**通道号**（`Channel`），**合法值只有 `0` 或 `1`**
（原生结构体注释：`// 0 or 1`；`YK_vmove` 文档：「通道0 or 1，点位运动下通道默认写 0 即可」）。

之前程序里**写成了 `2`**。卡拿到一个它不认识的通道号，无法确定你要操作哪条缓冲，
于是回了一个语义相近的错误码 —— **8194「普通缓冲满」**。

> **这就是为什么点「停止」救不回来**：根本不存在「被占的缓冲」，
> 卡只是不认识通道 2 这个编号。

**已修**：程序里 4 处 `Channel = 2` 全部改成 `Channel = 0`，涉及
① Jog 参数预置 ② 点位参数预置 ③ **Jog 实际走的「速度曲线重建」那条路** ④ IO 计数。

### 现场怎么判断是这个问题

如果 Jog **一次都走不了**（松开按钮轴完全不动）+ 报 8194 → 就是这个。
装了新版本程序后应能正常 Jog。

## 二、已一并修好的辅助项

| 项目 | 说明 |
|---|---|
| **Jog 前自动先停一次轴** | 用「立刻停」清卡内缓冲，让 Jog 能反复点、不越点越死 |
| **缓冲占用读数** | 点 Jog 时状态栏会显示 `Jog 前缓冲读数：卡0 轴「轴0」指令缓冲占用 = 0（空）`。**= 0 说明缓冲是空的**，进一步印证 8194 与缓冲无关 |
| **8194 提示** | 改成按步骤排障：点停再 Jog → 查使能/报警/限位 → 断电重启 |

## 三、默认速度 / 默认寸动 = 10000

**运行速度、手动速度、点动距离（寸动）三者的默认值都改成 `10000`。**

- **新建的轴 / 自动生成的轴**：直接用 10000。
- **已有工程（老数据）**：打开工程时会**自动写回**成 10000。

### ★ 重要：只改「没设过」的值

迁移规则是 **「还等于旧默认值才改」**：

| 轴上的旧值 | 处理 |
|---|---|
| 运行速度 = `100`（旧默认） | → 改成 **10000** |
| 点动距离 = `1`（旧默认） | → 改成 **10000** |
| 手动速度 = `20`（旧默认） | → 改成 **10000** |
| 你**亲手填过**的值（如 `3000` / `250` / `8888`） | **原样保留，不覆盖** |

> 举例：截图里的 **点动距离 11111、手动速度 20000 是你自己填过的值**，
> 迁移**不会**动它们。只有从没改过、还是 100/1/20 的轴才会变成 10000。
> 如果你希望某根轴也用 10000，在轴页直接填 10000 即可。

## 四、轴移动**太慢**（速度填多大都没用）—— 已修

Jog 能走之后，现场又发现 **轴走得非常慢**（手动速度都填到 20000 了还是慢）。真因不在速度，
而在**加减速字段的语义**。

### 原因：加速时间被算成了 400 秒

轴的「加速度 / 减速度」字段过去被当成**加速度值**，程序内部再做一次换算
`加速时间 = 速度 ÷ 加速度`：

```
手动速度 = 20000，加速度 = 50   →   加速时间 = 20000 / 50 = 400 秒
```

也就是说：轴要以 20000 的速度走，得先**慢慢加速 400 秒**才能到速。
点一下 Jog 只走一瞬间，轴几乎一直在「斜坡最底部」爬 —— 所以**速度填多大都感觉一样慢**。

### 修法：加减速字段改为「加速时间（秒）」

- 「轴」页这两栏已改名为 **「加速时间 / 减速时间」**（原来叫「加速度 / 减速度」，容易被当成值）。
- 语义是 **从起始速度加速到额定速度所需的秒数**，直接下发，**不再除以速度**。
- **默认值 0.2 秒**（新的轴、自动生成的轴）。常用范围 `0.1 ~ 0.5 秒`。
- 老工程里还等于旧默认值 `50` 的加减速，打开工程时**自动改成 0.2 秒**；
  你**亲手填过**的加减速值**保留不动**。

> **为什么「填 20000 还是慢」和这个有关**：速度本来就没问题，是加速斜坡太长。
> 改完后，速度填 20000 就真按 20000 走。

### 自诊断提示（现场一眼看出）

- 点 Jog 时，**日志**会写明真正下发的内容，例如：
  `轴「轴0」Jog 正向 已启动：（20000 mm/s，脉冲当量 1000 pulse/unit 已下发到卡，卡内自动折算脉冲），加减速时间 0.2s`
- 若某轴的加减速时间仍偏大（≥ 5 秒），点 Jog 时**状态栏**会主动告警：
  「加减速时间偏大（加速 50s / 减速 50s）… 这两个字段现在是秒数，不是加速度值 … 请改成 0.1~0.5s」。

### 单位说明（mm 轴）

「脉冲当量」是 unit↔脉冲 的换算基准（研控卡内叫「指令位置比率」，`pulse/unit`）。
程序把它下发到卡后，**卡自己完成换算**；模拟卡没有这层，由程序侧乘当量换算成 `pulse/s`。
所以**你填的速度按轴的单位（如 mm/s）理解**，不必自己乘脉冲当量。

## 五、排障顺序（装新版程序后）

1. **装新版程序**（`bin/Debug/net10.0-windows/NoCodeMotion.dll`，见文末构建时间）。
2. 打开工程 → 看「运行速度 / 手动速度 / 点动距离」是否已是 10000（没设过的轴）；
   看「加速度 / 减速度」是否已是 **0.2**（没设过的轴）。
3. 点 **Jog**：
   - 能走 → 问题解决（根因是 Channel）。
   - 仍报 8194 → 看**状态栏**的「Jog 前缓冲读数」：
     - `= 0` → 缓冲是空的，与缓冲无关，查下面第 4 步。
     - `≠ 0` → 确实被占着，查下面第 4 步。
4. 查「上一条运动为什么结束不了」，轴上满足任意一条卡都会认为「轴还在运动中」：

   | 检查项 | 在哪看 | 正常应该是 |
   |---|---|---|
   | 伺服未使能 | 轴页「使能」列 | 显示**已使能**、伺服锁轴 |
   | 伺服报警 | 轴页「报警」列 | 无报警 |
   | 正/负限位压住 | 轴页「正极限 / 负极限」列 | 都没压住 |

5. 还不行 → **断电重启控制卡**（卡内缓冲只能由「运动到位」或「停止」释放）。
6. **轴太慢** → 确认「加速度 / 减速度」是 **0.1~0.5 秒** 量级（不是 50 这种像加速度值的数）。

## 六、还有一个容易忽略的原因：两根轴填了同一个轴号

同一控制器内**轴号不能重复**（轴号从 **0** 开始，名称里的数就是轴号：轴0、轴1…）。
两轴同号会**共用同一个底层轴通道**、卡内缓冲互相抢占 → **Jog 最容易报 8194**。
程序检测到会在状态栏给一次性告警：`[卡族·警告] …轴号重复…`。看到就先去「轴」页改轴号。
