# 雷赛控制卡 + 真实通讯 对接说明

本文档说明如何把 Lua 流程里的轴 / IO / 气缸动作接到**雷赛（Leadshine）DMC 系列运动控制卡**，
以及如何用**真实通讯库**（串口 / 网口 TCP / UDP / Modbus RTU / Modbus TCP）和 PLC、相机、扫码枪等设备通讯。

---

## 1. 整体结构

```
Lua 脚本            AxisMove / SetIO / CommSend …
   ↓
HardwareApi         按名称找到项目里配置好的轴 / IO / 气缸 / 通讯对象
   ↓
IHardwareBridge     对接接口（唯一对接点）
   ├── StubHardwareBridge        仿真：只打日志，不碰设备
   └── LeadshineHardwareBridge   真实：轴 IO 走雷赛卡，通讯走真实串口 / 网口 / Modbus
          ├── LtdmcCard      → LtdmcNative（P/Invoke LTDMC.dll）
          └── CommManager    → SerialCommChannel / TcpCommChannel / UdpCommChannel / ModbusCommChannel
```

相关文件：

| 文件 | 作用 |
| --- | --- |
| `Services/Hardware/Leadshine/LtdmcNative.cs` | LTDMC.dll 的函数声明（**只有这里有原生签名**） |
| `Services/Hardware/Leadshine/LtdmcCard.cs` | 安全调用层：库探测、初始化、错误码翻译成中文 |
| `Services/Hardware/Leadshine/LeadshineHardwareBridge.cs` | 真实对接实现（轴 / IO / 气缸 / 料盘 / 通讯） |
| `Services/Hardware/Comm/SerialCommChannel.cs` | 真实串口（System.IO.Ports） |
| `Services/Hardware/Comm/NetCommChannel.cs` | 真实网口 TCP / UDP |
| `Services/Hardware/Comm/ModbusCommChannel.cs` | 真实 Modbus RTU / TCP（NModbus 库） |
| `Services/Hardware/Comm/CommManager.cs` | 按通讯类型分派并缓存连接 |
| `Services/Hardware/HardwareSetup.cs` | 装配入口：仿真 / 雷赛 模式切换 |

引入的真实库（已写入 `NoCodeMotion.csproj`）：

- `NModbus` 3.0.83 —— Modbus RTU / TCP 主站
- `NModbus.Serial` 3.0.83 —— Modbus RTU 的串口适配
- `System.IO.Ports` 10.0.11 —— 真实串口

## 2. 接入雷赛控制卡（3 步）

### 第 1 步：放 DLL

把雷赛驱动包里的 `LTDMC.dll` 复制到程序运行目录（与 `NoCodeMotion.exe` 同级）。

> **位数必须一致**：程序默认 AnyCPU（64 位机器上按 64 位运行），就要放 **64 位** 的 LTDMC.dll。
> 如果你只有 32 位 DLL，请把项目改成 `<PlatformTarget>x86</PlatformTarget>`。
> 位数不符时程序不会崩，会在输出面板提示「LTDMC.dll 位数与程序不一致」。

### 第 2 步：配置轴与 IO

在软件里配置好即可，字段与雷赛参数的对应关系：

**轴（AxisItem）**

| 配置字段 | 对应雷赛调用 | 说明 |
| --- | --- | --- |
| `AxisNo` | `axis` 参数 | 卡上的轴号（0 起） |
| `PulsePerUnit` | `dmc_set_equiv` | 脉冲当量：走 1 个单位需要多少脉冲 |
| `Speed` / `Accel` / `Decel` | `dmc_set_profile_unit` | 加速时间 = 速度 ÷ 加速度，自动换算 |
| `Jerk` | `dmc_set_s_profile` | 大于 0 时启用 S 形平滑 |
| `HomeMode` | `dmc_home_move` 的 `home_mode` | 文字自动识别：含「限位」→0，含「原点」→1，含「EZ / Z相」→2；也可直接填数字 |
| `HomeSpeed` / `CreepSpeed` | `dmc_set_home_profile_unit` | 回零高速 / 爬行低速 |
| `HomeOffset` | `dmc_set_position_unit` | 回零完成后把坐标置成该值 |
| `PosLimitPlus` / `PosLimitMinus` | 软限位检查 | `MoveAxisAbs` 超范围会**直接拦住并中文报错**，防撞机 |
| `EnableLevel` | `dmc_write_sevon_pin` | 含「高」按高电平有效，否则按低电平有效（雷赛常见） |
| `InPosError` | 到位判定参考 | 到位用 `dmc_check_done` 判断 |

**IO（IoItem）**

| 配置字段 | 对应 | 说明 |
| --- | --- | --- |
| `CardNo` | `CardNo` 参数 | 卡号，单卡填 0 |
| `ModuleNo` + `Sequence` | 位号 | 位号 = `ModuleNo × 16 + Sequence`，每模块位数可在 `LeadshineHardwareBridge.Options.BitsPerModule` 改 |
| `Level` | 电平取反 | 含「低 / 常闭 / NC」时读写自动取反 |

### 第 3 步：启用

程序第一次运行脚本时会自动判断：

- 目录里有 `LTDMC.dll` → 自动进入**雷赛模式**
- 没有 → 进入**仿真模式**（轴 IO 只打日志）

也可以在代码里手动切换：

```csharp
NoCodeMotion.Services.Hardware.HardwareSetup.UseLeadshine();   // 真实卡 + 真实通讯
NoCodeMotion.Services.Hardware.HardwareSetup.UseSimulation();  // 全仿真
NoCodeMotion.Services.Hardware.HardwareSetup.Reconnect();      // 现场插好卡后重连
```

> **卡不在也不会崩**：控制卡没检测到时，轴 / IO 动作只在输出面板打印
> `[雷赛·未执行] …`，而**通讯功能照常真实可用**，方便先接 PLC 调流程。

## 3. 真实通讯怎么用

在软件的「通讯」配置里新建一条，`CommType` 决定走哪种真实通道：

| CommType | 实际通道 | PortOrIp | BaudOrPort |
| --- | --- | --- | --- |
| 串口 | SerialPort（RS232 / RS485） | COM3 | 波特率 9600… |
| 网口TCP / 相机网口 | TcpClient | 192.168.1.10 | 端口号 |
| 网口UDP | UdpClient | 192.168.1.10 | 端口号 |
| ModbusRTU | NModbus + 串口 | COM3 | 波特率 |
| ModbusTCP | NModbus + 网口 | 192.168.1.10 | 502 |

`DataBits` / `Parity` / `StopBits` / `TimeoutMs` 会真实下发到串口；`Parity` 支持中文（无 / 奇 / 偶）或英文（None / Odd / Even）。

### 3.1 串口、网口：发文本或十六进制

```lua
-- 发文本（支持 \r \n \t 转义）
CommSend("扫码枪", "TRIGGER\r\n")
local code = CommRecv("扫码枪")          -- 收到的文本，去掉尾部换行

-- 发十六进制字节
CommSend("相机", "HEX:02 41 42 03")
local ret = CommRecv("相机")             -- 不可见字节会返回 "HEX:.." 形式
```

### 3.2 Modbus：用命令字符串读写寄存器

格式：`功能,站号,地址,数量或值`（大小写不敏感）

| 命令 | 功能码 | 含义 | 示例 |
| --- | --- | --- | --- |
| `RH` | 03 | 读保持寄存器 | `RH,1,0,2` 读站号 1 地址 0 起 2 个 |
| `RI` | 04 | 读输入寄存器 | `RI,1,100,4` |
| `RC` | 01 | 读线圈 | `RC,1,0,8` |
| `RD` | 02 | 读离散输入 | `RD,1,0,4` |
| `WH` | 06 / 16 | 写保持寄存器 | `WH,1,10,1234` 或 `WH,1,10,11,22,33` |
| `WC` | 05 / 15 | 写线圈 | `WC,1,5,1` 或 `WC,1,5,1,0,1` |

读操作的结果用 `CommRecv` 取（逗号分隔）：

```lua
-- 读 PLC 两个寄存器
CommSend("PLC1", "RH,1,0,2")
local v = CommRecv("PLC1")        -- 例如 "100,200"

-- 写一个寄存器：让 PLC 启动
CommSend("PLC1", "WH,1,10,1")

-- 读一个输入点，等它变 1
CommSend("PLC1", "RD,1,0,1")
if CommRecv("PLC1") == "1" then
    print("PLC 就绪")
end
```

地址支持十六进制写法：`RH,1,0x10,2`。

> 从站返回异常时会给中文提示，例如
> `Modbus 从站返回异常码 2：寄存器 / 线圈地址超出从站范围（命令 RH,1,9999,2）`。

### 3.3 西门子 S7 / 三菱 MC

暂未内置专用协议，会给出中文提示。这两种可以先用 **ModbusTCP**（PLC 侧开 Modbus 服务）
或 **网口TCP** 自行拼报文；要内置的话在 `CommManager.Create` 里加一个通道类即可。

## 4. 气缸与料盘

- **气缸**走 IO：`OutPoint` 填输出点名称（也可直接填位号数字），
  `SensorExtend` / `SensorRetract` 填到位感应的输入点名称。
  - `PulseOutput` + `PulseWidthMs`：按脉冲方式驱动电磁阀
  - `DoubleCoil`：双线圈，另一路自动取反
  - `WaitCylinder`：有到位感应就轮询感应（超时 `TimeoutMs` 中文报错）；没有感应就按 `ExtendMs` / `RetractMs` 等时间
- **料盘**：`TrayPick` / `TrayPlace` 按 `Rows / Cols / StartX / StartY / PitchX / PitchY`
  算出当前格子坐标并自动推进格号，坐标打印在输出面板。
  料盘没有绑定 XY 轴的配置字段，实际移动请在脚本里配合 `MoveAxisAbs` 使用。

## 5. 注意：AxisMove 不带位置

`AxisItem` 里没有「目标位置」字段，所以单独调用 `AxisMove("轴1")` 无法确定终点。
真实模式下它**不会动作**，只提示改用：

```lua
MoveAxisAbs("X轴", 120.5)   -- 绝对定位
MoveAxisRel("X轴", -10)     -- 相对移动
WaitAxisDone("X轴")         -- 等到位
```

## 6. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `未找到 LTDMC.dll` | DLL 没放到 exe 目录，或没装雷赛驱动 |
| `LTDMC.dll 位数与程序不一致` | 换成与程序同位数的 DLL，或把项目改成 x86 |
| `库中没有该函数` | 你的库版本函数名不同，按手册改 `LtdmcNative.cs` 对应一行声明 |
| `dmc_board_init 返回 0` | 卡没插好 / 驱动没装 / 卡没上电 |
| 轴不动但有日志 `[雷赛·未执行]` | 控制卡未就绪，先解决上面几条 |
| 等待到位超时 | 伺服没使能、驱动器报警、目标超行程 |
| 串口 `已被其它程序占用` | 关掉串口调试助手或另一个上位机 |
| Modbus 通讯超时 | 站号 / 波特率 / 校验位与从站不一致，或 485 的 A/B 接反 |
| 目标位置被拦住 | 超出 `PosLimitPlus / PosLimitMinus` 软限位，这是防撞保护 |

所有硬件报错都以中文显示在 Lua 编辑器的输出面板，并带上处理建议。
