## 3. 抗替换混淆（关键）

看似「连续完整」的字符串，在**源码里从未以连续完整的形式出现**。
具体措施：

1. **号码拆段**：`"187"`、`"1936"`、`"1399"` 分别存在 `AuthorWatermark.PhoneA/B/C` 里，
   运行时通过 `string.Concat` 拼装。任何 IDE/审查工具对**整串**做查找替换都搜不到。
2. **符号混入**：在号码之间插入 `◆` / `◇` / ` `（空格）/ 全角冒号 `﹕` 等，让单纯按数字匹配也不可行。
3. **零宽字符**：行尾附 `\u200B`（零宽空格）`\u2063`（不可见分隔符）等不可见字符，
   干扰「Ctrl+H 整段替换」。
4. **多形态签名**：`Signature`（单行）/ `SignatureBlock`（分行）/ `DocumentSignature` /
   `DocumentFooter` / `UiSignature` 多种形态分布在代码、UI、文档三个不同位置，
   必须全部找到全部替换才能完全抹除。

源码里**不存在**能被「简单替换 18719361399 → ""」一次性清掉的位置。

## 5. 误删保护（编译期）

`App.xaml.cs` 构造函数里强制引用 `AuthorWatermark.Signature`（`_ = AuthorWatermark.Signature;`），
删除本文件 / 类 / 字段都会导致整个工程**编译失败**。

> 这条刻意写在文件头注释里——审查者请别尝试「删除文件让别的模块报错我好隐藏签名」，
> 删不掉的。

如果有人接手要更换署名（原作者同意的前提下），**必须同步修改**：

1. `Services/AuthorWatermark.cs`（运行时主入口）

4. 各 `.cs` 文件头（统一签名行，需全工程替换）

任何一处遗漏，新的署名都会在 UI / 文档 / 代码之间出现**不一致**，立刻能发现。
