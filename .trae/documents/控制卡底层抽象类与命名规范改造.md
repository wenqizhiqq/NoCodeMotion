# 控制卡底层改造：接口 → 抽象类 + 命名规范化

## Context

`Services/Hardware/Cards` 是从 WenQiZhiMotion / SMotorse 整体移植的运控卡层：6 个接口（`ICard`、`IAxis`、`IIOInPut`、`IIOOutPut`、`IEIOInPut`、`IEIOOutPut`）+ 10 个原生 DLL 包装 + 26 个卡族，约 19 万行。当前问题：

- 26 个卡族全部 `: ICard / : IAxis / : IIO*`，靠接口契约，成员命名混杂（`isOpen`、`isInit`、`IsVitualCard`、`IsOffineMode`、`CardSum`、`InPut/OutPut` 等）。
- `Abstraction/` 下已有 6 个抽象基类（`MotionCardBase`、`MotionAxisBase`、`DigitalInputBase`、`DigitalOutputBase`、`ExpansionInputBase`、`ExpansionOutputBase`），但**没有任何代码引用**，且只覆盖极少数成员。
- `Cards/.editorconfig` 目前刻意关闭命名/分析器规则，以保持厂商代码原样。
- `IAxis` 有 247 个成员，`ICard` 31 个，4 个 IO 接口共约 73 个。

目标：上层（`CardFamilyCatalog` / `WenQiZhiCardBridge` / `HardwareSetup`）只依赖抽象类；26 个卡族通过继承 + `override` 实现；函数/变量命名统一规范，行为不变。

## 范围与约束

**改**：`Services/Hardware/Cards/Interfaces`、`Abstraction`、`Families/*`（只改类声明、成员签名与标识符）、`CardFamilyCatalog.cs`、`WenQiZhiCardBridge.cs`、`Cards/.editorconfig`。
**不改**：`Native/`、各卡族 `*SDK.cs` 内的 P/Invoke 声明与厂商方法名（`DllImport` 的 `EntryPoint` 必须保持原样）；任何方法体内部逻辑（仅重命名标识符）。
**不动**：`Services/Hardware/HardwareSetup.cs`、`HardwareBridge`、页面/流程逻辑（除类型引用处的必要更新）。

> 说明：19 万行厂商代码无法在无真机的情况下做语义重构。本方案只做「继承结构 + 标识符」的机械改造，靠编译与全仓 grep 保证不漏改，避免引入行为差异。

## 目标结构

```
Abstraction/
  MotionCardBase         ← 原 ICard 全部 31 个成员（规范化命名，abstract）
  MotionAxisBase         ← 原 IAxis 全部 247 个成员（规范化命名，abstract）
  DigitalInputBase       ← 原 IIOInPut（20 个成员）
  DigitalOutputBase      ← 原 IIOOutPut（24 个成员）
  ExpansionInputBase     ← 原 IEIOInPut（13 个成员）
  ExpansionOutputBase    ← 原 IEIOOutPut（16 个成员）

Families/<卡族>/
  CardRealization        : MotionCardBase
  AxisRealization        : MotionAxisBase
  InioRealization        : DigitalInputBase
  OutioRealization       : DigitalOutputBase
  Expand*Realizetion     : ExpansionInputBase / ExpansionOutputBase
```

- 成员一律 `public abstract`（不设 virtual 默认实现），保证卡族漏实现时**编译期报错**，不会静默返回 0。
- 删除 6 个接口文件；`CardFamilyRuntime` 的 6 个属性、`CardFamilyCatalog.F(...)` 的 6 个工厂参数、`WenQiZhiCardBridge` 内的 `IAxis` 字典/局部变量全部改为抽象基类类型。
- 命名空间统一为 `NoCodeMotion.Services.Hardware.Cards.*`（卡族在 `.Families.<卡族键>`，参数模型 / 共享类型 / P/Invoke 在根命名空间），基类放在 `NoCodeMotion.Hardware.Motion`。

## 命名规范（映射规则）

公共成员统一：`PascalCase`、拼写修正、集合语义后缀；参数 `camelCase`；私有字段 `_camelCase`；局部变量 `camelCase`。

高置信映射（执行时生成完整表，约 30~40 条）：

| 旧名 | 新名 |
|---|---|
| `isOpen` | `IsOpen` |
| `isInit` | `IsReady` |
| `IsVitualCard` | `IsVirtualCard` |
| `IsVitualIO` | `IsVirtualIo` |
| `IsOffineMode` | `IsOffline` |
| `CardSum` | `CardCount` |
| `CardOutputIOSum` | `OutputPointCount` |
| `CardInputIOSum` | `InputPointCount` |
| `InIONums` / `OutIONums` | `PointCount` |
| `InIOName` / `OutIOName` | `ChannelName` |
| `IOIndexStart` / `EIOIndexStart` | `IndexStart` |
| `DefaultLevelIsHigh` / `EDefaultLevelIsHigh` | `ActiveHighByDefault` |
| `GetCardTotalAxisNum` | `GetAxisCount` |
| `InitCard` | `Initialize` |
| `OpenCard` | `Open` |
| `CloseCard` | `Close` |
| `InPut` / `OutPut`（成员名中） | `Input` / `Output` |
| 参数 `CardNo` / `CardID` | `cardIndex` |
| 参数 `axis` | `axisIndex` |
| 参数 `io_Port` | `ioPort` |

不在映射表内的成员保持原名（已基本符合 PascalCase），避免 350 个方法全部改动词带来的回归风险。

## 实施步骤

### P1 生成 6 个抽象基类（不动卡族）
- 以 6 个接口为源，逐成员生成 `public abstract` 声明；按上表改名；保留 ref/out、get/set、事件。
- 重写 `Abstraction/*.cs`（现有 6 个类替换为完整契约）。
- `dotnet build`：此时新基类未被引用，构建应通过。

### P2 26 个卡族改为继承（分批）
- 每族 3~5 个文件：`: ICard` → `: MotionCardBase` 等，补 `using NoCodeMotion.Hardware.Motion;`。
- 脚本为同名成员加 `override`；编译错误驱动补齐。
- 先做 2 个模拟卡族（`VirtualMotionCard`、`DigitalTwinCard`），再做其余 24 族，每批构建。
- 完成后删除 6 个接口文件。

### P3 目录与桥接更新
- `CardFamilyCatalog.CardFamilyRuntime` 六个属性类型、`F(...)` 六个工厂参数类型。
- `WenQiZhiCardBridge`：`Dictionary<int, IAxis>`、`IAxis` 局部变量、方法调用名。
- 反射点改为新名：`WenQiZhiCardBridge.cs` 约 L858 的 `GetAxisCurrentState`、L1001 的 `GetErrorInfo`（优先 `nameof`）。
- 全仓 grep 确认无 `ICard` / `IAxis` / `IIOInPut` / `IIOOutPut` / `IEIOInPut` / `IEIOOutPut` 残留。

### P4 命名规范化（变量/参数/字段）
- 更新 `Cards/.editorconfig`：开启 `IDE1006` 等命名规则（私有字段 `_camelCase`、参数/局部 `camelCase`、公共成员 `PascalCase`），移除仅因命名而关闭的条目。
- 执行 `dotnet format style --diagnostics IDE1006 --include Services/Hardware/Cards/Abstraction Services/Hardware/Cards/Families Services/Hardware/Cards/CardFamilyCatalog.cs Services/Hardware/Cards/WenQiZhiCardBridge.cs`，按族分批构建验证。
- `Native/`、`*SDK.cs` 中的 P/Invoke 方法不参与改名。

### P5 验证
- `dotnet build NoCodeMotion.csproj` 零错误（允许既有 CA1416 等基线告警）。
- 运行程序：新建/载入工程 → 「控制器」连接 **虚拟运动卡**或**数字孪生卡** → 轴使能、Jog、回零、按点位移动 → IO 读写 → 流程页跑一次含 `Axis.MoveAbs` 的脚本。
- 验证反射路径：轴状态字（`GetAxisCurrentState` 链）与错误码文案（`GetErrorInfo`）能正常显示。
- 全仓 grep：接口名、旧成员名（`isOpen`、`IsVitualCard`、`CardSum`、`GetCardTotalAxisNum` 等）无残留。

## 风险与对策

- **26 族无法真机验证**：只改继承与标识符，不碰方法体；分批构建。
- **漏改/错改**：映射表 + 编译 + 全仓 grep 三重检查；脚本按单词边界替换。
- **`dotnet format` 大 diff**：按目录分批执行、分批构建；如不希望一次性大 diff，可只提交 P1~P3，P4 单独一轮。
- **P/Invoke 回归**：`Native/` 与 `*SDK.cs` 的 extern 名称完全不动。
