## 修复：点位表选中行不驱动「移动条件」列表（关键 bug）
- 现象需求：「每一个点位名称对应一个条件列表」。原实现下**点击点位表的单元格不会更新 SelectedPoint**，条件列表永远停在上一个点位（或变空）。
- 证据（WPF 源码，gitee 镜像 dotnet/wpf）：
  - `DataGrid.HandleSelectionForCellInput`：`SelectionUnit == FullRow` 才走 `MakeFullRowSelection`；`Cell` / `CellOrRowHeader` 走 `MakeCellSelection`。
  - `MakeCellSelection` 只操作 `_selectedCells`，**从不把行加进 SelectedItems**（只在取消选中时移除）；非 Ctrl/Shift 点击还会 `UnselectAll()`。
  - 因此 `SelectionUnit="CellOrRowHeader"` 下点击单元格 → SelectedItem 不变或变 null → TwoWay 绑定不回传 SelectedPoint。
  - `DataGridCell` 的鼠标类处理器用 `handledEventsToo: true` 注册，所以点在单元格内的 TextBox 上也会触发选中逻辑。
- 改法：左侧点位表 `SelectionUnit="CellOrRowHeader"` → `"FullRow"`（Views/PointPage.xaml:319）。右侧条件表保持 CellOrRowHeader 不动。
- 副作用：点击整行高亮（原为单格高亮）。点位表本就 IsReadOnly + HeadersVisibility="Column"（无行头），所以原来其实**没有任何鼠标方式能选中行**。

### 环境教训（补充）
- **Edit 工具会把 UTF-8+BOM 文件的行尾改成 LF**：本次 `Views/PointPage.xaml.cs` 被改后出现 32 处裸 LF，
  需用 Python 重新归一化回 CRLF。**同一批改动的 `PointMoveCondition.cs` / `PointViewModel.cs` 却仍是 CRLF**，
  所以不能凭「刚才那个文件没事」推断，**每个被 Edit 过的文件都要单独验一遍**（检查 `\n` 计数 − `\r\n` 计数 是否为 0）。
- 带零宽字符的作者水印必须逐字节保留：改写整文件时用「原文件前 3 行 + 新正文 + 原文件水印起至结尾」拼接，
  不要手抄水印（肉眼看不见的 U+200B/U+2063 抄不准）。

### 关键坑：运行态读数会经 Conditions 冒泡触发自动保存（差点写成高频写盘）
- 链路：`PointMoveCondition` 任意属性变更 → `PointItem.OnConditionChanged` → `OnPropertyChanged(nameof(Conditions))`
  → `ListEditorViewModel.OnItemPropertyChanged` → **`ProjectStore.ScheduleSave()`**（同时还会走 `HardwarePush` 钩子）。
- 后果：新加的「实际值」每 250ms 刷新一次、每次刷 2 个属性，6 行 → 每秒最多约 48 次 `ScheduleSave()`，把自动保存打成写盘风暴。
- 修法：`Models/PointItem.cs` 的 `OnConditionChanged` 里用 `switch (e.PropertyName)` 挡掉
  `ActualValue` / `ActualOk` / `IsActualOk` / `IsActualFail` 四个**运行态只读**属性，其余照旧冒泡。
- **通用原则：凡是「运行态/只读展示」属性，绝不能挂在会触发落盘的 PropertyChanged 冒泡链上。**
  以后再加类似的实时展示字段（如实时速度、报警位），必须同步往这个 switch 里加 case。

### 环境教训（本轮新增）
- **隐式 using 不含 `System.Windows`**：`<ImplicitUsings>enable</ImplicitUsings>` + `<UseWPF>true</UseWPF>` 时，
  生成的 `GlobalUsings.g.cs` 只有 `System / System.Collections.Generic / System.Linq / System.Threading / System.Threading.Tasks`。
  用 `Application.Current` 必须自己写 `using System.Windows;`，否则 CS0103。
  （验证方式：直接看 `obj/**/NoCodeMotion.GlobalUsings.g.cs`。）
- **`core.autocrlf=true`**：仓库内存 LF、工作区是 CRLF，所以 `git show HEAD:file` 看到的是 LF 而工作区是 CRLF，
  别被误导。用 Python 往 CRLF 文件里插内容时，插入串若用 `\n` 会留下**混合行尾**，
  写入前务必 `replace('\r\n','\n').replace('\n','\r\n')` 归一化。git 提交时会归一化，但工作区要保持一致。
- **bash 双引号里写含 `$"` 的 C# 代码会被转义搞坏**（`\$` / `\"` 处理不一致导致断言失败）：
  改用 Write 工具把 Python 脚本写成文件再执行，不要硬塞进 `-c "..."`。

- **踩坑：不能 `Append`**。`PointItem.EnsureConditionRows()` 会把行数规整为固定 6 行并裁掉尾部空行，

- 示例条件刻意只用枚举型（气缸/输出）：`SimRuntime` 默认就是 0，**开箱即可正常移动、不会自己把自己拦住**；
  数值型（变量/轴位置）随运行漂移，做成示范会时灵时不灵。
