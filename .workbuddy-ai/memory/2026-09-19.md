## 点位页「移动条件」表格去掉水平滚动条
- 文件：`Views/PointPage.xaml`（移动条件 DataGrid，约 426-495 行）
- 原因：右侧卡片 `Grid.Column=1` 固定 340px，减去左右外边距 18px、Border 边框 2px、DataGrid 外边距 8px 后可用约 312px；三列固定宽 70+150+86=306px，叠加竖向滚动条约 17px 后超出 → 出现水平滚动条。
- 改法（两点）：
  1. 三列由固定宽改为按比例自适应：`IO` = `0.75*` MinWidth 56，`IO名称` = `1.5*` MinWidth 100，`IO状态` = `0.9*` MinWidth 72。
  2. DataGrid 增加 `ScrollViewer.HorizontalScrollBarVisibility="Disabled"` 兜底。
- 该写法在本项目已有先例：`Views/OperatorManualPage.xaml:42`、`Views/NewProjectDialog.xaml:179` 同样用 Disabled。

## 环境备忘：本机 dotnet build 在受限 shell 下无法运行
- 现象：`dotnet build` 报 `NuGet.Configuration.ConfigurationDefaults` 类型初始化失败 → `Value cannot be null. (Parameter 'path1')`（NuGet.targets 780 行 GetRestoreSettingsTask）。
- 根因：该 shell 进程无法解析用户配置目录（ApplicationData），属环境问题，与代码改动无关；`--no-restore` 也会在同一处失败。
- 已用「无关的空项目」复现同样报错 → 证实是环境问题，不是本仓库代码问题。
- 换 PowerShell 工具也不行：其中外部 exe 调用被沙箱静默拦掉（`$LASTEXITCODE` 为空、无输出）；且该工具的输出捕获不生效，需重定向到文件再用 Bash 读。
- 结论：改完 XAML 无法在此环境自测编译，只能做 XML 良构性校验，需由用户在正常终端里重新生成。

## 修复：点位表选中行不驱动「移动条件」列表（关键 bug）
- 现象需求：「每一个点位名称对应一个条件列表」。原实现下**点击点位表的单元格不会更新 SelectedPoint**，条件列表永远停在上一个点位（或变空）。
- 证据（WPF 源码，gitee 镜像 dotnet/wpf）：
  - `DataGrid.HandleSelectionForCellInput`：`SelectionUnit == FullRow` 才走 `MakeFullRowSelection`；`Cell` / `CellOrRowHeader` 走 `MakeCellSelection`。
  - `MakeCellSelection` 只操作 `_selectedCells`，**从不把行加进 SelectedItems**（只在取消选中时移除）；非 Ctrl/Shift 点击还会 `UnselectAll()`。
  - 因此 `SelectionUnit="CellOrRowHeader"` 下点击单元格 → SelectedItem 不变或变 null → TwoWay 绑定不回传 SelectedPoint。
  - `DataGridCell` 的鼠标类处理器用 `handledEventsToo: true` 注册，所以点在单元格内的 TextBox 上也会触发选中逻辑。
- 改法：左侧点位表 `SelectionUnit="CellOrRowHeader"` → `"FullRow"`（Views/PointPage.xaml:319）。右侧条件表保持 CellOrRowHeader 不动。
- 副作用：点击整行高亮（原为单格高亮）。点位表本就 IsReadOnly + HeadersVisibility="Column"（无行头），所以原来其实**没有任何鼠标方式能选中行**。
