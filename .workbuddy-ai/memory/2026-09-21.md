## 需求（当日两轮，同一主题）：流程页「复制JSON / 粘贴生成」AI 往返

原始需求：「所有的流程页面都需要有 2 个按钮：复制JSON粘贴到AI对话软件，AI根据需求生成内容，
粘贴到软件就可以生成对应的流程」→ 第二轮追加：「还需要说明怎样操作啊，粘贴按钮需要弹窗确定」。

### 1) 两个按钮放在哪：流程页 Row-0 的 Detail 头部

四种流程（运控 Table / 脚本 Lua / 视觉 Vision / 节点图 NodeGraph）都在同一个 `FlowPage` 里切换，
所以按钮放在 `FlowPage.xaml` Row-0 的 `DockPanel` 里、紧跟类型 chip 之后 —— **一处实现，四种流程全都有**。
内嵌的 `VisualFlowPage` / `NodeGraphPage` 通过 `FlowContentReplaced` 事件跟着 `Reload()`。

**坑（必记）：`EditorPage.Detail` 的内容区里不能给元素加 `x:Name`。**
会报 `MC3093: 无法对元素"X"设置 Name 特性值…在另一范围内定义它时，已注册了名称`
（Border / Detail 内容会被注册进两个 NameScope）。所以那行操作说明的 `TextBlock` 只能匿名，
提示信息走 `ToolTip`。

### 2) 后端：`Services/AiProjectExchange.cs`

- 导出：`ExportFlowJson` / `ExportSteps`（**7 个字段**：逻辑/功能/对象/属性/运算/值/超时）。
  带上「属性 + 运算」是为了往返无损；只给「动作」也能进，由 `MapAction` 映射成内置模板实际在用的
  (属性, 运算, 值) 三元组，再用 `ClampTo` / `ClampProperty` / `ClampOperation` 夹回合法值，
  保证 DataGrid 单元格不会渲染成空白。
- 导入判定：**恰好 1 个流程 + 当前有选中流程 → 覆盖（保留原名称）**；否则追加为新流程、名称去重
  （`UniqueFlowName`）。覆盖时 `keepName: true`——名称是流程在左侧列表里的身份，被 AI 悄悄改名
  用户就找不到自己刚改的流程了。
- 解析统一走 `ReadFlowItems(json, body)`（去 ```json 围栏 / `AllowTrailingCommas` / 注释跳过 /
  数组或裸对象或 `{"流程":[…]}` 解包）。`ApplyFlowGenerated`、`CountFlowsInJson`、`PreviewFlowJson`
  全部委托它，**判定口径不会漂**。

### 3) 【重要坑】JSON 中文被写成 `\uXXXX`

默认 `JsonSerializer` 编码器会把「运控」序列化成 `\u8FD0\u63A7`，而这段 JSON 是要粘进 AI 对话给人看的。
修复：`JsonSerializerOptions { Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping }`
（与 `Services/ProjectJsonAnnotator.cs`、`Services/UserStore.cs` 的既有约定一致）。
`ExportGraph` 也从 `GetRawText()` 改成重新 `Serialize(..., JOpts)`，否则节点图里仍是 `\uXXXX`。

### 4) 弹窗 `Views/PasteFlowDialog.xaml(.cs)`

Apple 风 `WindowStyle="None" AllowsTransparency="True"` 圆角白卡弹窗，内含：
- 「操作说明」四步（① 在流程页点【复制JSON】… ④ 点【确定生成】）；
- 可编辑的 JSON 输入框（自动填入剪贴板，可 Ctrl+V / 手改）；
- 【重新读取剪贴板】按钮；
- **实时预览**（`PreviewFlowJson`）：识别到几个流程 / 类型 / 步骤数，并预告
  「将【覆盖】当前流程「X」（名称保留）」还是「将【新增】到工程」；
- 内容解析不出流程时【确定生成】**禁用**。

剪贴板为空也照常弹窗（弹窗里有说明和「重新读取剪贴板」，用户不用猜下一步干什么）。

## 第二轮修复：验证时发现的两个真实缺陷

### 5) 【关键】`TableToolbar` 的「共 N 项/步」标签根本不受 `Count` 控制

`Views/TableToolbar.xaml` 里显示的文本绑的是 **`MatchInfo`**（`TextBlock x:Name="MatchInfoText"`），
而 `MatchInfo` 只在 **`OnLoaded` 和 `SearchText` 变化**时重算 —— 所以行数一变（粘贴生成整批换掉步骤集合、
或点「添加」加一行）标签就**一直停在打开页面时的数字**。
`Count` / `CountLabel` 两个 DP 只是参与 `MatchInfo` 的文案拼接，**从来没被直接显示过**。
（IoPage×2 / VariablePage / FlowPage 都写着 `Count="{Binding Items.Count}"`，全都一直是死的。）

修复（`Views/TableToolbar.xaml.cs`）：
- `TargetGridProperty` 加 `PropertyMetadata(null, OnTargetGridChanged)`，在其中对
  `DataGrid.ItemContainerGenerator.ItemsChanged` **订阅/退订**（换 grid 时先退旧的）；
- `OnGridItemsChanged` → 无关键字走 `UpdateMatchInfo()`，有关键字走完整 `ApplySearch()`；
- `Count` / `CountLabel` 也加 `OnCountChanged` 回调；
- `UpdateMatchInfo` 以 `TargetGrid.ItemsSource` 为准（用户看到的就是它），没挂上 grid 时才退回 `Count`。
- 需要 `using System.Windows.Controls.Primitives;`（`ItemsChangedEventArgs`）。

**验证方式**：连续粘两次不同步数（7 → 3），断言标签跟着 7 → 3。
只断言一次 7 是不够的 —— 工程里本来就可能已经是 7 步，看不出标签是死的还是活的。

### 6) 名称列空白：`ComboBox` 只列 Catalog 里的名字，值不在库里就渲染空白

`Views/FlowPage.xaml` 的「名称」列是 `ComboBox ItemsSource="{Binding Function, Converter={StaticResource FunctionToNamesConverter}}"`，
而该 converter 返回 `Catalog.AxisNames` / `IoNames` / `CylinderNames` / …。
`Catalog.AxisNames` 来自 `ProjectStore.Data.Axes.Select(a => a.Name)` —— 工程 24 里轴名是 **X / Y**，
而 AI 生成的是 **X轴 / Y轴 / 来料检测 / 夹爪缸**，全都不在库里 → 单元格显示空白。

**已核实：值本身是正确落盘的**（`bin/Debug/net10.0-windows/Projects/工程24.xlsx` 的「流程」sheet 里
`名称` 列写着 X轴/Y轴/来料检测/夹爪缸）。所以这是**显示问题，不是数据丢失**。
代码注释里作者本来就写明了「模板预设值不在列表则该格为空」——是既定设计。

**决定不改渲染层**：试过用 `IMultiValueConverter` 把当前值并进 `ItemsSource`，但
`ComboBox.SelectedItem` 默认 TwoWay，**ItemsSource 一换实例 WPF 就把 SelectedItem 置空并回写 null**，
会把用户刚选的名称清掉 —— 数据丢失风险，不值得。改为「如实提示」：
- 提示词：`BuildNameContextText` 里空类别原来直接 `return` 省略，AI 看不到「气缸一个都没配」就去编名字。
  现在改成显式写 `- 气缸：（工程里未配置，请不要引用这一类）`。
- 导入提醒：新增 `UnknownObjects(f)` / `UnknownObjectsHint(f)`，按
  `ProjectStore.Data`（**不是 Catalog**）逐条比对「功能 → 合法对象名」，对不上的拼成
  `注意：轴[X轴]、气缸[夹爪缸] 在工程里不存在，「名称」列会显示空白，请先配置该对象或在表格里改选`，
  同时挂在**弹窗预览（带 ⚠，点确定前就能看到）**和**状态栏**上。
  「注释」行的对象是自由文本，跳过校验；系统/相机等不需要引用具体对象的功能也跳过。

## 环境 / 工具教训（本轮最重要，跨项目可复用）

### 7) 【大坑】这台机器的桌面**没有交互式输入**，合成鼠标点击会打空

症状：UIA 找得到按钮、`IsEnabled=True`、坐标也正常，但 `b.Click(simulateMove=True)` /
`mouse_event` 点了**毫无反应**（复制JSON 点了剪贴板不变、粘贴生成点了不弹窗）。
排查结论：

    GetForegroundWindow() == NULL        # 没有任何窗口在前台
    GetCursorPos()        == (0, 0)      # 光标根本不在桌面上
    OpenInputDesktop()    != NULL        # 会话本身在，只是没有输入桌面

**解法：用 UIA 的 `Invoke` 模式直接调 WPF 命令，完全绕开鼠标和前台窗口。**

    ctrl.GetInvokePattern().Invoke()      # 返回 bool

- `uiautomation` 包 **没有** `GetSupportedPatterns()`（那是裸 UIA COM API），别照抄 C#/C++ 示例。
  2.0.29 有 `GetInvokePattern / GetSelectionItemPattern / GetValuePattern / GetTogglePattern / …`。
- **导航项本身是 `TextBlock`，Invoke 不了**：要沿 `GetParentControl()` 往上找到外层
  `ButtonControl` 再 Invoke（实测 L1 就是 Button）。
- 同理 **`PrintWindow` 的客户区在这种状态下会全白**（标题栏正常），截图不再能作为视觉证据 ——
  改以 UIA 读到的控件文本/状态为准（比截图更硬）。

### 8) 补丁脚本：CRLF 文件里用 `\n` 匹配会 0 命中

`ui_e2e5.py` 是 **CRLF**。用 `bash -c "... python -c '...'"` 内联脚本、`old` 里写 `\n`，
`text.count(old)` 恒为 0（真机是 `\r\n`）。而且内联脚本里带中文引号容易被 shell 吃掉。
**规矩：一律把补丁写成 `.py` 文件再跑**，并在文件里做

    if crlf:
        old = old.replace('\r\n','\n').replace('\n','\r\n')

（与 `edit-bom-crlf-source-files` skill 的 `patch()` 同一套做法。）

### 9) 别用 `git show HEAD` 来隔离「本次改动」

本轮 HEAD 比工作区**落后约 1000 行**（上一轮的改动还没提交），
所以 `git diff HEAD` 里 996 行"新增"其实大部分是上一轮的。
据此算的花括号差值（HEAD `+1` → 工作区 `+2`）也**毫无意义**：
`Services/AiProjectExchange.cs` 里有大量 JSON 模板字符串，`{` `}` 本来就不配平。
**结论：这类文件的括号/差值只能横向比 HEAD 判断"有没有新增失衡"，本轮连这个都不成立 ——
直接信 `dotnet build`。**

### 10) 【勘误】「`.bt/` 会被编进产品」是错的

`MEMORY.md` / `2026-09-19.md` / `edit-bom-crlf-source-files` skill 里都写着
「主工程默认 `**/*.cs` glob 不排除 `.bt/` 之类目录，写进去会被编进产品」。**实测证伪**：
往 `.bt/` 放一个内容为 `this is definitely not valid C# at all !!!` 的 `.cs`，
`dotnet build -t:Rebuild` 仍是 **0 错误 / 590 警告** → **点开头的目录默认不参与编译**。

真正危险的是**不带点**的临时目录：csproj 里只显式 `<Compile Remove="artifacts\**" />`，
所以 `scratch/` / `tmp/` / `test/` 会被 `**/*.cs` 收进去编进产品。
结论不变（冒烟测试仍放 `%TEMP%`），但**理由要改**——已同步修正 `MEMORY.md` 与 skill。

顺带发现仓库里还留着上一轮的 scratch 目录 `.bt/`（`add_buttons*.py` / `splice_flow.py` /
