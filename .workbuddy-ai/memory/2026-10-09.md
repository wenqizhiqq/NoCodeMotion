## 09:xx 图像采集「来源」：默认相机 + 真接海康相机 + 路径无效明确报错

客户反馈：**「为什么图像采集没有读取文件而是默认的，也需要读取相机的」**。查下来是三个叠加的真问题：

1. **默认来源是「文件」**：`VisualFlowStep._sourceType` 默认 `"文件"`，模板建出的采集步**没写 `SourceType`** → 就停在「文件」。
2. **模板给的「文件路径」根本不是文件**：一个模板 `SavePath = "Images/inspection/"`（是**文件夹**），另一个连路径都没有 → `File.Exists` 失败 → `RunAcquire` 走 `SyntheticFallback` **悄悄生成合成测试图并报 `Ok=true`**。看着「跑通了」，其实一张图都没取到 —— 这就是「没有读取文件而是默认的」。
3. **来源=相机 永远打不开工业相机**：`RunAcquire` 的相机分支只有 `new Cv.VideoCapture(索引)`；而工程里能用的真实取像链路（`MvsCameraService.TryGrabBgra`）**只存在于 `VisionEngine.CaptureFrame`**（Lua 相机步骤 / 3D 抓拍在用），视觉流程采集步压根没调它。加上模板存的是**相机名**「下视相机」而引擎只 `int.TryParse` → 直接判「相机编号无效」。

客户拍板的口径（AskUserQuestion）：默认来源改成**相机**（读不到再回退），并四件事一起做：真接海康相机 / 相机名+下拉 / 模板改相机源 / 路径无效明确报错。

改动：
- `Services/Vision/VisionEngine.cs`（LF+BOM+水印，字节级补丁）：`RunAcquire` 整体重写 → 相机分支先 `ResolveCameraIndex(s.CameraId)` 再 `TryGrabRealCamera`；**抽出 `TryGrabRealCamera(idx,out w,out h,out err)`**（① MVS `MvsCameraService.TryGrabBgra` ② OpenCV `VideoCapture`）供 `RunAcquire` 与 `CaptureFrame` **共用**（`CaptureFrame` 也改成调它）；新增 `public static int ResolveCameraIndex(string?)`（工程相机名 → 下标 / 纯数字 0 基 / 名字带数字 1 基）；**文件·文件夹 路径无效一律 `AddFail` + `return null`**，不再静默回退；补 `using System.Globalization/Linq`。主循环 `display = cur?.Clone()` 容错 + `测量` 补 `cur == null` 判空。
