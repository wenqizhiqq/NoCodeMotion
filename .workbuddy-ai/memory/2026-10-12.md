## 08:40–09:05 请求 G：气缸单动 / 双动 + 「连接控制器后气缸页选不了 IO 名称」

### 现象与根因
- 现象：连上控制器后，气缸页「IO 配置」4 个下拉选不了任何 IO 名称。
- 根因：`AxisControllerViewModel.GenerateIoPoints()`（连接控制器后自动生成 IO 点）**只刷新了合并库**
  `Catalog.SetIo(...)`，漏了按方向拆分的 `Catalog.SetIoIn(...)` / `Catalog.SetIoOut(...)`。
  气缸页 4 个下拉绑的正是 `InIoNames` / `OutIoNames`（节点图属性、流程页「输入IO / 输出IO」也读这两个）
  → 连卡后这两个库还是旧值；新工程直接是空 → 下拉空白 / 选不了。
  `SetIoIn`/`SetIoOut` 此前只在 `Catalog.SyncAllFromData` 与 `IoViewModel.SyncIoCatalog` 里被调过。
- 用户口径：**不需要重命名轴 / IO，只需要「更新数量」** —— 即让刷新后的名称与数量真正进到下拉。

### 语义
- **单动气缸 = 1 路输出 + 2 路输入**（伸出输出 / 伸出感应 / 缩回感应）；缩回靠弹簧，不写第 2 路输出。
- **双动气缸 = 2 路输出 + 2 路输入**（多一个「缩回输出」）。
- 为什么在 **Type 的 setter** 里归一：xlsx 载入 / AI 导入 / 模板 / 界面写入四条路径都走属性 setter，一处归一即全覆盖；
  不归一的话旧工程的「单作用 / 双作用」在**受限值域**的类型药丸里匹配不上候选 → 渲染空白并写回 null。
