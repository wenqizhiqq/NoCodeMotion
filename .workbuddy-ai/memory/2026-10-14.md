**关键技术教训（纠正之前的误判）**：
- 之前诊断"仓库 .cs 头 88 7d 1c 是加密包装导致 dotnet 读坏"是**错**的。真正根因：注入脚本把 14 个新增章节的 body 写成了**跨行裸字符串**（缺 `"…\n" +` 续行、字符串未闭合）→ CS1010 "Newline in constant" + 中文标点 CS1056。git cat-file 看是明文（git overlay），xxd 看磁盘是"包装"（另一层 FS 视图），dotnet 读坏字节（因为内容本身有语法错）。
- **唯一能让 dotnet 读到明文的通道是 WorkBuddy 原生 Write/Edit**（exempt）。Bash/Python/cp/`git checkout` 写仓库会被"包装"；`/tmp` 副本明文但沙箱按调用清理（不可持久）。
- Write 写整文件后 Edit 就能读明文了（豁免生效）。**先 Write 整文件去包装 + 修语法，再 Edit 增量改。**
- 增改说明书：可见引号一律「」全角；body 必须 `"行\n" +` 续行；**绝对不要跨行裸字符串**（CS1010 头号原因）。
- 源码守卫 G28.2 只查 `@@HDR@@`/`@@FTR@@` 占位符残留，不强制 BOM/水印字节——Write 丢了零宽水印/BOM 也不会让守卫掉 Pass。守卫全文 grep 无"必须带 BOM/必须带水印字节"失败断言。
