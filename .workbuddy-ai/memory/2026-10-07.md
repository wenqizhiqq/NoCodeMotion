## 13:40 真机崩溃修复：`AppleCheckBox` 不在 App 的资源可达链里

**现象**（用户截图）：`PointPage.xaml.cs:17 InitializeComponent()` 抛
`XamlParseException`，内部异常「**无法找到名为"AppleCheckBox"的资源。资源名称区分大小写。**」，
定位 `PointPage.xaml` 第 868 行第 89 列。

**真因**：`App.xaml` 的 `MergedDictionaries` **只合并了 `Resources\AppStyles.xaml`**；
`Themes\AppleControls.xaml` 从未被任何地方合并，而 `AppleCheckBox` **只在那里定义**
（全仓库唯一一处，且除我新写的这行外**没有任何人用过** → 它其实是死样式）。
`{StaticResource}` 解析顺序：元素自身 Resources → 祖先 → `Application.Current.Resources`（即可达链）→ 系统。
**grep 到 `x:Key` 完全不等于运行时找得到**；而且 **`dotnet build` 抓不到**——StaticResource 是
运行期 XAML 解析，构建照样 0 错误，窗口一打开就崩。

**修法**：换成全局可用的 `AppleToggle` + 独立 `TextBlock` 标签。
注意 `AppleToggle` 是 **46×26 无文字开关**（`ControlTemplate` 根本不渲染 `Content`），
写 `Content="折线模式"` 会**什么都不显示** —— 打开它的 `ControlTemplate` 看一眼才发现。

**新增守卫 G17（148 PASS / 0 FAIL）**：沿 `App.xaml` 的 `MergedDictionaries` 递归求可达键集
（跳过 `pack://` 外部程序集），断言各页面用到的 `{StaticResource K}` 都在链内或本文件定义。
实测 53 个 XAML / 167 个可达键，**恰好揪出 1 处**（就是 AppleCheckBox）。
`Themes\`/`Resources\` 不扫（字典本身），`RunStatsView.xaml` 的 `KpiTitle`/`KpiValue`
进 allowlist（借用宿主 `OperatorPage.xaml` 的资源，非缺陷）。
**并做了反向验证**：把 `AppleCheckBox` 注回去 → G17 报 `Views\PointPage.xaml :: AppleCheckBox`、
147 PASS / 1 FAIL；恢复后 md5 与注入前一致。**能失败的守卫才是守卫。**

**冒烟新增 F 段（24 → 27 项全 PASS）**：`new NoCodeMotion.App()` + `app.InitializeComponent()`
建立应用级资源链，再 `new PointPage()` / `new EngineerPage()` —— 真的走一遍 XAML 解析。
**没有 `App` 实例时所有应用级键都会假失败**，所以必须先建 App 再建页面。

**复核**：构建 `--no-incremental` **0 错误 / 614 警告**，DLL 13:38 / 3,633,664 B；
被改文件仍无新增警告。清理掉 `tools\_rescheck.py` / `_patch_fix_checkbox.py`。

## 15:00 相机页 + 流程视觉接真实相机（海康 MVS SDK）

**需求**（用户）：`C:\Program Files (x86)\MVS\Development\Samples\C#` 相机页面需要真实获取相机，
**流程里面的视觉也要取到**。

**关键侦察结论（决定了整个设计）**：
- 海康 **MVS 运行库（Runtime）本机没装** —— 全盘只找到**托管封装**
  `MVS\Development\DotNet\AnyCpu\MvCameraControl.Net.dll`（59,904 B，纯 IL，AnyCPU，
  可在 .NET 10 加载），**原生 `MvCameraControl.dll` 一个都没有**（只有 import 用的 `.lib`）。
  → 调用 `MV_CC_EnumDevices_NET` 抛 `DllNotFoundException`（0x8007007E）。
  **所以本机无法做端到端真机验证**，设计必须是「有相机就用、没有就优雅降级 + 给出可读原因」。
- 该托管封装是**纯 IL**（PE 0x014C / COR flags 0x9 ILONLY），`MyCamera` 有无参公有构造，
  `MV_CC_EnumDevices_NET` 是**静态**方法、其余为实例方法。API/结构体布局全部**用反射实测**过
  （没去逐行读 4k 行的 `BasicDemo.cs`）。
- `MV_CC_DEVICE_INFO_LIST` 在封装里是 `uint nDeviceNum; IntPtr[] pDeviceInfo;`（封送有坑）
  → 改用**手写镜像原生布局**（256 个内联 `IntPtr`，共 2056 B）。
- `MVCC_INTVALUE.nCurValue` 是 **`UInt32`** → 转 int 前必须做范围检查。
- 取图**没有**返回 `MV_FRAME_OUT` 的 API；用 `MV_CC_GetImageForBGR_NET`，
  再按 `nFrameLen` 反推像素布局（3 B/px=BGR、4=BGRA、1=Mono），避开像素类型常量。

**实现**：
- 新增 `Services/Camera/MvsCameraService.cs`（BOM+LF，594 行）：`MvsCameraDevice` /
  `MvsCameraSettings` / `static MvsCameraService` / `sealed MvsCameraSession : IDisposable`。
  **会话按设备 Key 复用**（`SN:` → `IP:` → `IDX:`）：一台 GigE 设备只有一个独占句柄，
  相机页与流程视觉共用同一个已打开会话。
  `IsRuntimeAvailable`（缓存 `bool?`）+ `LastError` 做优雅降级；`Enumerate()` **永不抛**。
- `Native/MvCameraControl.Net.dll` 入库；csproj 加 `<Reference>` + `HintPath` + `Private`。
- `ViewModels/CameraViewModel.cs`：新增 `Preview`/`HasPreview`/`SearchDevicesCommand`，
  `Connect()` 换成真开设备+抓首帧预览（**失败不谎报已连接**），`Capture()` 真取像、
  失败回退仿真（页面与流程行为一致）。
- `Views/CameraPage.xaml`：占位十字 → 真 `<Image Source="{Binding Preview}">` +
  `HasPreview` 驱动的占位浮层；加「搜索设备」按钮。
- `Services/Vision/VisionEngine.cs`：`CaptureFrame` **先走 MVS**，取不到再回退 OpenCV / 合成图。

**顺带修掉一个真隐患**：`CaptureFrame` 末尾 `return SyntheticCapture(...)` **在 try 之外**，
而 `SyntheticCapture` 自己依赖 OpenCvSharp → OpenCV 原生库加载失败时异常直接冲出，
**把流程「相机」步骤整条打断**。改成包 try/catch 再退到**纯托管**占位帧 `ManagedPlaceholder`
（不碰任何原生库）→ `CaptureFrame` 永不抛。

**验证（全部实测）**：
- 构建 **0 错误 / 620 警告**（与改动前基线一致，相机文件无新增警告）。
- 守卫 **`tools\guard_sources.py` → 160 PASS / 0 FAIL**（新增 **G18** 共 12 项锁死相机层）。
- XAML 良构：`CameraPage/PointPage/EngineerPage` 均 `XML OK`，无 `CRCRLF`。
- 冒烟 **A–H 全 PASS / exit 0**：A–E 图形生成回归、F 三个页面真实例化（`PointPage`/`EngineerPage`/
  **新增 `CameraPage`**）、G 相机层降级（`IsRuntimeAvailable=False` + 可读 `LastError`、
  `Enumerate` 空列表不抛、`Connect` 不谎报、`Capture` 回退仿真出 320×240 预览、`LastResult` 已写）、
  H `CaptureFrame` 回退帧 320×240 / 307,200 B。

**冒烟环境两个坑（都不是产品问题）**：
1. 主工程用 `<Reference>+HintPath` 引的 MVS 封装**不会进引用方的 `deps.json`**，
   而 `dotnet exec` **严格按 deps.json 解析** → 冒烟工程必须**照抄一份同样的 `<Reference>`**
   （产品自身 `NoCodeMotion.deps.json` 有 4 处记录、DLL 也在输出目录，**产品不受影响**）。
2. 本机 `%TEMP%` 里的 exe **无法直接执行**（bash 报 exit 127）、**也无法 kill**
   （`taskkill` 拒绝访问）→ 改用 `dotnet exec <dll>` 运行；构建加 `-p:UseAppHost=false`
   可绕开被残留进程锁住的 `*.exe`。

**未做 / 待办**：真机（装好 MVS Runtime + 接相机）端到端取像验证；检测算法未接入，
